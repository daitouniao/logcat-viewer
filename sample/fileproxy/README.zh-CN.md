# 文件代理示例（fileproxy）

本目录提供 logcat「文件代理」功能的两个可直接运行的代理示例，以及应用侧的完整配置说明。

文件打不开时（路径形态不受支持、NTFS 权限被收、被写入进程独占、EDR/组策略拦截，或读到的内容不是文本），可由一个外部「文件代理」进程代为读取：代理用任意手段拿到文件字节流，经 Windows 命名管道按协议交给应用；应用先把字节流整体暂存（spool）为本机临时文件，再走正常索引链路，界面全程显示原始路径。

## 目录内容

| 文件 | 说明 |
| ---- | ---- |
| `fileproxy.py` | Python 3.8+ 示例，零第三方依赖（仅标准库） |
| `fileproxy.js` | Node.js 示例，零第三方依赖 |

两个脚本实现完全相同的协议 v1，可任选其一，也可作为自写代理的骨架。

## 方式一：手动启动代理

1. 先启动脚本（管道名默认 `logcat-fileproxy`，与应用设置一致即可）：

   ```text
   python <脚本路径>\fileproxy.py
   node  <脚本路径>\fileproxy.js
   ```

2. 在应用中打开目标文件。模式为「启用」或「自动」且需要代理时，应用直接连上已在运行的代理。

## 方式二：配置启动命令（自动拉起）

菜单「设置 → 文件代理…」打开设置对话框：

| 配置项 | 说明 |
| ------ | ---- |
| 模式 | 三选一，默认「停用」。**停用**：完全不走代理，行为与没有此功能时一致；**启用**：打开文件一律经代理读取；**自动**：直接打开失败，或打开成功但嗅探判定内容不是文本时才走代理，其余照常直接读 |
| 管道名 | 默认 `logcat-fileproxy`。应用启动代理时会自动追加 `--pipe <此值>`，无需在参数里手写；保存时校验（非空、不含反斜杠、不超长） |
| 可执行文件 | 解释器或程序的**完整路径**（不依赖文件关联），例如 Python 的 `python.exe` 或 Node 的 `node.exe` 所在路径 |
| 参数 | 传给可执行文件的其余参数（如 `--root D:\data`）。`--pipe <管道名>` 由应用在启动命令末尾自动追加，无需手写；脚本路径含空格时用引号包住。旧配置里手写的 `--pipe {pipe}` 仍兼容（按占位符替换处理），打开设置对话框时会自动剥除展示 |

参数填写示例（`<脚本路径>` 换成你存放本目录的实际位置；`--pipe <管道名>` 由应用自动追加，不用写）：

```text
# Python
"<脚本路径>\fileproxy.py"

# Node.js
"<脚本路径>\fileproxy.js"
```

| 配置项 | 说明 |
| ------ | ---- |
| 启动等待超时（毫秒） | 自动拉起后等待管道就绪的时间，默认 5000 毫秒 |
| 测试连接 | 按当前填写值连接并握手（无需先保存）；代理未运行时自动按启动命令拉起并等待就绪，拉起成功的进程照常驻留复用 |

说明：

- 仅当**连不上手动代理**且**配置了启动命令**时才会自动拉起；拉起的进程驻留复用，应用退出时随之结束。
- 保存立即生效，无需重启应用。
- 自动拉起配置等同以应用权限执行任意代码，**勿配置不受信任的脚本**（见下文「安全须知」）。

## 脚本命令行参数

两个脚本的公共参数：

| 参数 | 说明 |
| ---- | ---- |
| `--pipe <名称>` | 管道名，默认 `logcat-fileproxy`，须与应用「文件代理设置」中的管道名一致 |
| `--root <目录>` | 只允许读取该目录下的文件，拒绝其余路径（演示最小安全边界；不给则不限制） |

脚本专属参数：

| 脚本 | 参数 | 说明 |
| ---- | ---- | ---- |
| `fileproxy.py` | `--once` | 处理完一个客户端连接即退出（便于测试 / 一次性使用） |
| `fileproxy.js` | `--idle <秒>` | 多少秒无客户端自动退出；`0` = 永不（默认） |

## 协议 v1 摘要

自写代理只需实现四个操作。传输为 Windows 命名管道字节流（`\\.\pipe\<管道名>`）：

- 控制消息 = 单行 JSON + `\n`（UTF-8，单行上限 64KB）
- `hello` → `{"ok":true,"proxy":"<自描述>","proto":1}`；`proto` 缺失或 ≠1 应用即判连接失败
- `open` + 文件路径 → `{"ok":true,"h":<句柄>,"size":<字节数>}`
- `read` + `{h, off, len}` → `{"ok":true,"n":<字节数>}` 头行 + 紧跟 n 字节裸块（无分隔符）；`n=0` 表示 EOF；`len` 上限 16MB
- `close` + `{h}` → `{"ok":true}`
- 未知操作 / 坏 JSON / 坏句柄回 `{"ok":false,"err":"…"}` 且**不断线**（长连接复用）

## 应用侧行为与限制

- 经代理的文件先整体暂存到应用所在目录的 `temp` 子目录再建索引；界面、最近文件、导出默认名全程显示原始路径；关闭文档即删除暂存。
- 目标文件大于 1GB 时会先弹确认框（整体复制可能写满磁盘）。
- 「重新加载」对代理文件为全量重拉。
- 应用为单实例运行，不支持同时开多个窗口。

## 安全须知

- 启动命令配置 = 以应用权限执行任意代码，等同应用自身权限，**勿配置不受信任的脚本**。
- 管道为本机会话级 ACL，协议内无认证消息；示例的 `--root` 参数演示了最小读取范围限制，生产环境自写代理请自行收紧读取范围。
- 应用不会对代理返回的内容做来源校验，代理自描述（`hello` 响应的 `proxy` 字段）仅用于错误消息展示。
