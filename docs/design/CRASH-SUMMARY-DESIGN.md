# 崩溃一键定位与摘要展示（产品设计说明）

> 日期：2026-10-11　状态：**最终版（2026-10-11 评审通过定稿）**
> 本文只讲「为什么做」和「做出来长什么样」。

---

## 1. 这是什么

手机 App 出问题（崩溃、卡死）时，系统会记下一份很长的「日志文件」。用本工具打开后，**崩溃内容往往埋在几十万行普通日志中间**，而且崩溃本身动辄几千个字符，在列表里显示成一坨被拦腰截断的长串，很难一眼看懂。

本设计要解决三件事：

1. **一眼认出崩溃** —— 把那坨长串换成一文明了然的摘要；
2. **自动读出关键信息** —— 崩溃叫什么名字（异常类型）、发生在哪个 App（包名）；
3. **汇总到独立窗口** —— 打开「崩溃汇总」弹出窗口，整个文件里崩了几次、都是什么类型，点一下就能跳到主窗口对应位置。

---

## 2. 为什么要做（设计目的）

| 现在的痛点 | 设计目标 |
|---|---|
| 崩溃在列表里是一大段被截断的乱码式长串，看不出是什么错 | 显示成一行摘要：崩溃类型 + App + 时间 + 被折叠了多少行 |
| 想知道「这个文件里崩了几次、哪些错最多」，只能手动一条条翻 | 「崩溃汇总」弹出窗口自动汇总全部崩溃，按出现次数排序 |
| 崩溃种类五花八门（Java 错误、底层信号错误、应用无响应），肉眼难以区分 | 自动识别分类，不同类别用不同标识 |
| 切换中英文界面后，列表里残留旧语言的文字 | 顺手修复这个已有显示问题（作为前置小修先行上线） |

---

## 3. 展示效果

### 3.1 崩溃摘要行（列表内）

**改造前** —— Message 列是一坨被截断的 `↵` 长串，完全读不了：

```
E/AndroidRuntime(  869): FATAL EXCEPTION: main↵E/AndroidRuntime(  869): Process: com.example.app,… …(+3412 字符)
```

**改造后** —— 同一行显示成一目了然的摘要：

```
☠ IllegalStateException · com.example.app · 10:23:45 · +37 行
```

摘要的含义从左到右：

| 片段 | 含义 |
|---|---|
| ☠ | 崩溃标记符号（一眼扫过去就能定位） |
| IllegalStateException | 崩溃类型（出了什么错） |
| com.example.app | 发生崩溃的 App（包名） |
| 10:23:45 | 崩溃发生时间 |
| +37 行 | 完整堆栈还有 37 行被折叠在背后 |

> 说明：摘要只是「显示得更聪明」，日志原文一个字都不动。点击该行或查看详情时，仍然能看到、复制到完整的堆栈内容。

### 3.2 崩溃汇总窗口（弹出窗口）

新增一个**非模态弹出窗口**（与过滤窗口同形态），从主窗口工具栏 / 菜单打开，自动统计整个日志文件：

| 类别 | 异常类型 | 包名 | 次数 | 首次 | 末次 |
|---|---|---|---|---|---|
| Java | IllegalStateException | com.example.app | 23 | 09:01 | 18:44 |
| Java | NullPointerException | com.example.pay | 8 | 10:23 | 11:05 |
| Native | SIGSEGV | com.example.game | 2 | 14:02 | 14:03 |

- 按出现**次数从多到少**排列，最常发生的崩溃排最上面；聚合结果**全部列出**，不限条数；
- **点击任意一行，主窗口直接定位到对应崩溃的位置**；窗口保持打开，可连续逐条核对；
- 弹出窗口空间充裕，可以承载更丰富的表达（类别列、后续的按列排序 / 按类别过滤）；
- 无崩溃时显示「无崩溃」空态提示。

### 3.3 自动识别的崩溃类别

| 类别 | 典型样子 | 说明 |
|---|---|---|
| Java 崩溃 | `FATAL EXCEPTION` + `IllegalStateException` 等 | App 代码出错，最常见 |
| Native 崩溃 | `SIGSEGV`、`SIGABRT` 等信号 | 底层（C/C++）出错 |
| ANR 应用无响应 | `ANR in com.x` + 原因说明 | App 卡死无响应 |

类别标识同时用符号 + 文字区分，**不单靠颜色**（照顾色觉障碍用户）；相关配色需在浅色 / 深色两套界面下都保持可读。

普通业务日志里偶尔出现「FATAL EXCEPTION」「signal」等字样但并非真崩溃的，会通过判据设计避免误判（开发阶段每类至少配 1 正例 + 2 反例做验证）。

## 4. 边界与说明

1. **跟随「续行合并」开关**：摘要行在默认的「续行合并」模式下显示；用户手动关闭合并后，日志按原始行逐行展示，摘要行自然消失（此时本来就是一行一条，无需摘要）。崩溃识别和汇总窗口统计**两种模式下都正常工作**。
2. **超长文件不设明细上限**：崩溃事件按「每次崩溃一条」稀疏存储（几十字节/条），汇总窗口用虚拟列表按需渲染——明细全量保留，「点击跳转」对全部崩溃都可用，无需截断保底。
3. **复制不受影响**：对崩溃行执行复制时，得到的仍是完整堆栈原文，而不是摘要文字。
4. **为后续分析预留数据**：崩溃识别产出一份「崩溃事件清单」（含发生位置与行号区间），摘要行与汇总窗口统计都来自它；后续「错误聚类分析」上线时将直接复用这份清单，无需重新解析整个文件。

---

## 5. 明确不做的（及原因）

| 不做 | 原因 |
|---|---|
| 崩溃「行号区间」展示 | 默认模式下整段崩溃就是一行，区间没有意义；该需求取消 |
| 崩溃指纹去重 | 已并入「错误聚类分析」功能（另行设计）；本功能的「崩溃事件清单」将作为其直接输入，不重复建设 |

---

## 6. 上线顺序

| 阶段 | 内容 | 用户可感知的变化 |
|---|---|---|
| ⓪ | 语言切换残留文字修复 | 现有 bug：切语言后列表旧文字刷新 |
| ① | 崩溃自动识别（数据准备） | 无界面变化 |
| ② | 崩溃摘要行 | 列表里长串变摘要 |
| ③ | 崩溃汇总窗口（弹出） | 主窗口新增「崩溃汇总」入口与弹出窗口 |
| ④ | 后续增强：按崩溃类型过滤；汇总窗口升级为按错误指纹分组（衔接「错误聚类分析」）；与时间轴热力图联动 | 汇总窗口 / 过滤 / 时间轴联动 |
