# 待重启卡：日志行标记（归 core，与过滤同批）

- 状态：**待排期**（已定归属与批次，未设计、未编码）
- 日期：2026-11-27
- 关联提交：无（未编码）
- 验收结论：不适用（未实施）

## 背景

用户希望在日志查看时对感兴趣的行做标记，并在标记与过滤同时使用时保持可辨识。经讨论确认：标记功能放在 **core 侧**实现，与**过滤功能同批**推进，不在最近文件、列宽等 UI 切片里零散加入。

本卡只登记结论与重启条件，不展开设计。

## 范围与边界（已确认）

- 归属：标记的数据与语义由 core（Rust）承载，不由新壳或旧查看器各自实现；UI 只做展示与交互。
- 批次：与过滤同批设计、同批实现，避免出现「标记已落但不是过滤参与者」的中间态。
- 交互面（待设计时细化）：给行打 / 取消标记；标记在滚动与过滤变化后仍能定位到原记录；标记与过滤同时生效时的展示规则。
- 持久化（待设计时细化）：标记是否随会话保留、是否写入索引缓存或独立文件、源文件变化后如何失效。

## 需要澄清（重启时逐项拍板）

1. **标记的标识**：按记录序号、按源文件字节偏移，还是按内容哈希？——决定源文件变化后的稳定性与缓存可行性。
   - 方案：序号（简单、文件变化即失效）；字节偏移（稳定、需随索引维护）；内容哈希（最稳、开销高）。
   - 当前偏向：字节偏移，与既有索引块同为「源文件位置」口径。
2. **标记的存储位置**：写入既有 sidecar 缓存目录，还是独立标记文件？
   - 方案：并入 sidecar（复用身份校验与失效重建）；独立文件（与缓存解耦，需另做原子写）。
   - 当前偏向：并入 sidecar，减少第二套落盘路径。
3. **与过滤的合成**：过滤结果集是否包含标记状态？「只看标记」是过滤器的一种还是独立开关？
   - 当前偏向：标记作为结果集的附加状态随行返回；「只看标记」作为过滤条件的一种形态，避免两套结果集。
4. **标记的粒度**：单行标记，还是支持区间 / 按 Tag / 按级别批量标记？
   - 当前偏向：先做单行标记，批量留待使用反馈。

## 重启条件

- 过滤能力在 core 的契约先落地（或与标记同批设计）；
- 上述 1–4 项拍板后，按 §二 标准流程建 OpenSpec change，规范落 `logcore/` 模块下的对应 capability。
