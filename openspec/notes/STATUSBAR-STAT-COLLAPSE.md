# 状态栏统计塌缩（索引/过滤时间偶发不显示）

状态：已定位待实机验收
日期：2026-10-26
关联提交：fix 一笔（UpdateStat 强制重排）+ 本笔记
验收结论：待维护者实机复现验证（96 DPI 会话无法复现坍塌）

## 现象

- 第二个文件开始，右下角统计（总/命中/标记/索引 ms/过滤 ms）有时不显示，稳定态只剩渠道标签「直接读文件」。
- 与过滤输入内容相关性的初判为假：`rou` 显示 → `rout` 不显示 → `route` 显示，非单调；本质偶发，rout 只是踩中的那一次。
- 125% 与 100% 屏均复现，全屏窗口也复现，与 DPI、窗口宽度无关。
- 判别实验：统计消失时拖动列表滚动条（触发 `OnScrolled` 改 `_lblPos` 文本）→ 统计立刻恢复，且之后一直正常，换文件也正常。

## 排查链（排除记录）

1. 更新逻辑：`_lblStat` 全部写入点仅两处——`StartIndex` 开头清空（frmMain.cs）、`UpdateStat()` 写入。每条正常结束的 `ApplyFilter` 必调 `UpdateStat()`；被新调用抢占的旧调用静默退出，但抢占者最终也会补写；`_doc == null` 的静默早退只发生在建索引期间且建索引完成后必再调一次。纯逻辑不存在「稳定态标签为空」的确定性路径。`StopWorker` 触发源（打开文件/Esc/关窗/停采集）与过滤输入场景无交集。
2. 布局溢出：`_lblFile` 带 `Spring=true` 未关 AutoSize 曾是头号嫌疑，但全屏窗口空间充足、且命中数/文字宽度随输入单调变化，解释不了非单调现象，否决。
3. 内容分支：`FilterEngine`（预筛 + MsgFilter）无按输入内容或命中规模的分支路径；`LogListView.SetRows` 无异常路径、无消息泵。
4. `AdbUpdateStat` 只在采集中写 `_lblMsg`，无关。

## 根因

统计文本一直在，是 StatusStrip 的**项布局塌缩**：`_lblStat`（AutoSize 的 ToolStripStatusLabel）在某次布局被算成零宽后，仅改自身文本不触发整条重排，项保持不可见；任何其他标签的文本变化（如拖滚动条改 `_lblPos`）捎带触发整条重排才恢复。

坍塌入口（推测，WinForms 内部时机无法在 96 DPI 会话复现取证）：打开文件时统计被清成空串（项正常塌到零宽），建索引/过滤期间 `_lblMsg` 与进度条反复增删，完成时 `UpdateStat` 写回文本的重排请求偶发被吞。

## 修复（§2.1 短流程）

`UpdateStat()` 尾部追加 `_statusStrip.PerformLayout()`（一行、幂等），文本写回必定伴随整条重排。不触碰行为契约：spec 仅对渠道状态区有布局契约（fileproxy spec「空文本占位、不得隐藏」），统计栏无 spec 条目。

## 验证

- dotnet test 全量 673/673 通过、零跳过，与基线一致，无新增失败。WinForms 布局无法单测覆盖，未为此新增用例。
- 实机验收（待办）：在曾复现的机器上打开大文件后连续过滤、换文件，观察统计是否再出现不显示；若再现，拖滚动条看是否仍能恢复（能恢复说明塌缩入口未被堵住，需回炉）。

## 同源发现：采集态过滤进度条卡住（2026-10-26 追加）

实机截图（ADB 采集中，命中 199 行的过滤已完成、统计栏已更新）显示绿色进度条停在半路不消失。卡住路径可由代码完整走通：

- `_pbar` 显隐规则：非 quiet `ApplyFilter` 开始时点亮，finally 仅当 `_workerGen == gen` 才隐藏；quiet 过滤全程不碰 `_pbar`。
- 采集态 quiet 过滤高频发生：增量同步状态不一致回退全量（`ApplyIncremental`）、文档重建静默刷新（`AdbAutoReload`），两者都会 `++_workerGen` 抢占代际。
- 序列：非 quiet 过滤 A 点亮进度条 → quiet 同步 B 抢占（gen 已变）→ A 的 finally 按 gen 判定跳过隐藏（防误关继任者的进度条）→ B 是 quiet 不碰进度条 ⇒ 永久卡在可见。「有时候」= 仅当两者恰好打架。

修复（三处统一，`_pbarGen` 所有权标记）：谁点亮 `_pbar` 谁登记 gen，`ApplyFilter` / `StartIndex` / `Reload` 的 finally 改为「自己仍是 owner（`_pbarGen == gen`）才隐藏」——被 quiet 抢占时死者仍是 owner 正常隐藏；被非 quiet 新过滤抢占时 owner 已易主，死者不误关新进度条。`StartIndex` / `Reload` 属潜伏同款（quiet 只在采集态发生，而采集态开文件会先停采集，无已知复现路径），按维护者拍板一并统一。

验证：dotnet test 全量 673/673 通过、零跳过，与基线一致。实机验收（待办）：采集态反复「按 Enter 过滤 + 让自动同步跑」，观察进度条是否再卡住。
