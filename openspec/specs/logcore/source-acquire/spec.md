# logcore/source-acquire Specification

## Purpose
定义源获取契约：宿主以两段式（plan → commit）请求打开文件或开启采集；文件源的路由、格式与编码判定归 core，采集源按请求声明的设备流处理，返回三轴拆开的源描述，并经轮询事件通道上报进度、增量与错误。本 capability 由 Rust core 宿主执行，是获取链从窗体迁入 core 的行为面。

## Requirements

### Requirement: 两段式获取流程

源获取 SHALL 分为 plan 与 commit 两段：文件源的 plan 阶段完成存在性检查、格式判定、文本嗅探与代理路由决策，返回获取计划；采集会话的 plan 跳过上述判定，直接返回设备流计划。commit 阶段才执行暂存、解码与索引装载。plan 阶段 MUST 不写盘、不建索引、不改变任何持久状态，文件源的副作用止于读取首尾样本与文件元数据（大小、修改时间）、必要时拉起代理；本地直读源的四要素身份由此算全并随计划结果返回，代理暂存与采集源的身份为空。plan 成功 SHALL 返回计划与可继续 commit 的句柄；commit MUST 复用该句柄，plan 与 commit 两阶段的取消均作用于该句柄。

#### Scenario: plan 只判定不装载

- **GIVEN** 一个可读的本地日志文件与合法配置快照
- **WHEN** 宿主发起 plan
- **THEN** 返回的路由与大小信息可判定来源走向，且该文件内容与所在目录均无任何写入痕迹

#### Scenario: 计划句柄贯穿两阶段

- **GIVEN** 文件源 plan 成功且已拉起代理
- **WHEN** 宿主以同一句柄发起 commit
- **THEN** commit 复用 plan 阶段的判定结果与代理连接，不重复拉起

#### Scenario: plan 之后取消

- **GIVEN** plan 已成功返回、commit 尚未发起
- **WHEN** 宿主以该句柄取消本次获取
- **THEN** 不产生任何装载产物，已拉起的代理连接被释放

#### Scenario: 采集会话跳过探测与代理

- **GIVEN** 宿主以采集会话发起获取，配置模式为自动
- **WHEN** plan 与 commit 执行
- **THEN** 不执行存在性、格式、文本嗅探与代理决策，路由为设备流，采集文件由 core 在暂存目录创建

### Requirement: 提交受理与装载完成

commit SHALL 在受理后立即返回，不等待暂存、解码与索引完成；返回值只表达受理结果，宿主 MUST NOT 将其当作装载完成。受理前的校验（句柄状态、请求参数、计划结果仍可用）SHALL 同步返回错误；受理后的运行期失败 MUST 经错误事件上报并把句柄置为失败态，MUST NOT 回填到已返回的调用。commit 受理本身不发布事件；文件源的完成以完成事件表示，采集源受理即进入采集运行状态，其终态仍是停止或错误。源描述 SHALL 经描述读取入口获取：受理后即可读取，渠道等静态字段即为终值（渠道在 plan 阶段确定、装载期间不变），本地直读源的身份与装载模式取 plan 阶段确定值：装载开始复核发现文件已变时身份更新为复核值、装载模式按未命中改为分块渐进，命中条目解码失败时装载模式改为分块渐进——两者均仅更新一次，代理暂存与采集源的身份为空，行数为当前已装载行数（初始为零）；装载完成后行数与文档大小取终值。宿主判定装载完成 MUST 以终态事件为准，进度只用于呈现。

#### Scenario: 提交在装载完成前返回

- **GIVEN** plan 已成功、目标是一份需要完整解析的大文件
- **WHEN** 宿主发起 commit
- **THEN** 调用在暂存与索引完成前返回受理结果，此时描述可读、行数为零，进度处于装载阶段

#### Scenario: 完成经事件告知

- **GIVEN** commit 已受理、装载仍在进行
- **WHEN** core 完成解析与索引
- **THEN** 发布完成事件，宿主据此判定装载完成；此后描述的行数与文档大小为终值

#### Scenario: 运行期失败只经事件

- **GIVEN** commit 已受理、随后直读打开失败
- **WHEN** 装载执行
- **THEN** commit 调用不携带该错误，错误事件携带错误码，句柄进入失败态并保留至显式释放

#### Scenario: 受理前错误同步返回

- **GIVEN** 句柄上的 commit 已受理
- **WHEN** 宿主再次发起 commit
- **THEN** 调用同步返回非法状态，不启动第二次装载

#### Scenario: 采集受理即运行

- **GIVEN** 采集请求的 commit 被受理
- **WHEN** 宿主读取描述与进度
- **THEN** 句柄进入采集运行状态、描述可读，不需要等待完成事件

### Requirement: 受理前发现计划结果不可用

commit 受理前的校验发现计划结果已不可用（如计划阶段建立的代理连接已断开）时，SHALL 同步返回运行中断线错误且不发布事件；core SHALL 释放计划阶段已占用的代理连接并作废计划结果，句柄 SHALL 保持计划就绪、不产出描述骨架。此后再次 commit MUST 返回非法状态，宿主 SHALL 关闭句柄后重新计划。

#### Scenario: 计划连接失效后提交

- **GIVEN** plan 已成功、core 拉起的代理连接已建立，随后进程级收尾或外部原因使该连接断开
- **WHEN** 宿主发起 commit
- **THEN** 同步返回断线错误码、不发布事件；句柄仍为计划就绪、读描述返回非法状态，已占用的代理连接被释放

#### Scenario: 重新计划恢复

- **GIVEN** 上例的 commit 已同步失败
- **WHEN** 宿主关闭该句柄并重新 plan
- **THEN** 新获取可重新拉起代理并成功受理

### Requirement: 入口判定归 core

宿主 SHALL 只传用户意图（文件路径或采集会话）与配置快照，路由、格式与编码判定 SHALL 全部由 core 完成。宿主 MUST NOT 自行探测文本性或决定是否走代理。宿主传入的文件路径 MUST 为绝对路径（盘符绝对或 UNC）；相对路径（含盘符相对与根相对）MUST 返回参数错误且不产生任何副作用，core MUST NOT 按自身工作目录解析路径。宿主传入的路径 SHALL 原样作为显示路径：core MUST NOT 规范化路径、解析符号链接，MUST NOT 改变分隔符或大小写；当原始路径为绝对路径且超出操作系统常规长度上限时，core MAY 在打开时补长路径前缀，该前缀 MUST NOT 出现在显示路径中，实际打开路径与显示路径分离。

#### Scenario: 宿主不做探测

- **GIVEN** 一个二进制特征明显的文件
- **WHEN** 宿主按配置快照发起 plan
- **THEN** 由 core 的判定结果决定路由，宿主全程未执行本地嗅探逻辑

#### Scenario: 网络共享路径原样显示

- **GIVEN** 用户选择一个网络共享路径（含 UNC 形式）
- **WHEN** 获取成功并返回源描述
- **THEN** 显示路径与用户所选完全一致，未被改写为设备路径或规范化形式

#### Scenario: 相对路径被拒

- **GIVEN** 文件请求携带相对路径（如 `logs\a.log`、`C:logs\a.log` 或 `\logs\a.log`）
- **WHEN** plan 执行
- **THEN** 返回参数错误、字段路径指出 `path`，不打开任何文件、不按工作目录解析

#### Scenario: 超长路径可打开且显示不变

- **GIVEN** 一个长度超出常规上限的绝对路径
- **WHEN** core 执行获取
- **THEN** 打开成功，实际打开路径可带长路径前缀，而显示路径仍为用户原路径

### Requirement: 代理路由三态判定

代理使用判定 SHALL 由配置模式与现场证据共同决定：显式开启恒走代理；显式关闭恒直读，但非文本输入拒绝（见「不支持的格式拒绝」）；自动模式下，直接打开成功且嗅探判为文本时直读，判为非文本时拒绝。非法模式值 MUST 回退为显式关闭。判定与「直接打开失败转代理」的回退 SHALL 在 plan 阶段完成，路由在计划返回时确定；commit 阶段 MUST NOT 改变渠道，直接打开失败按运行期失败处理。

#### Scenario: 自动模式直接打开成功且为文本

- **GIVEN** 模式为自动、文件可直接打开、嗅探判定为文本
- **WHEN** plan 执行
- **THEN** 路由为本地直读，不拉起代理

#### Scenario: 自动模式嗅探判非文本

- **GIVEN** 模式为自动、嗅探判定非文本
- **WHEN** plan 执行
- **THEN** 同步返回 UNSUPPORTED_FORMAT，不转代理、不拉起代理、不建立句柄

#### Scenario: 非法模式值回退

- **GIVEN** 配置快照携带无法识别的模式值
- **WHEN** plan 执行
- **THEN** 按显式关闭处理

### Requirement: 代理实例复用与结束

同一管道名下由 core 拉起的代理进程至多一个：core SHALL 复用已拉起的实例，同一时刻多个源因该管道名需要代理时 MUST NOT 重复拉起；同一实例 SHALL 支持多个源并发暂存，各源的判定、暂存与错误互不干扰。core 自己拉起实例时 MUST 使用从配置管道名派生的进程内唯一管道名并连接该名，使不同宿主进程互不共用、互不结束对方拉起的实例；配置的基础管道名 SHALL 只用于连接外部代理，外部代理可被多个宿主进程共用，core MUST NOT 登记或结束。代理进程 SHALL 在派生名的最后一个使用者关闭后结束。宿主 SHALL 在进程退出前调用一次进程级收尾入口，结束 core 拉起并登记的全部代理并清空登记；被其中止的连接 SHALL 按运行中断线处理，之后的新获取 MAY 重新拉起。该入口 MUST NOT 关闭源或释放句柄，且 SHALL 幂等。

#### Scenario: 多个源共用同一代理实例

- **GIVEN** 两个文件都需要走代理、配置快照中的管道名相同
- **WHEN** 两个源先后执行 plan 与 commit
- **THEN** 两者都暂存成功、互不干扰，且只存在一个由 core 拉起的代理进程

#### Scenario: 拉起去重

- **GIVEN** 已有一个由 core 拉起的代理在运行
- **WHEN** 新的源需要同一管道名的代理
- **THEN** 复用该实例，不再拉起第二个进程

#### Scenario: 关闭一个源不结束代理

- **GIVEN** 两个源共用同一代理实例
- **WHEN** 关闭其中一个源
- **THEN** 代理进程仍在运行，另一个源继续可用

#### Scenario: 最后使用者关闭后结束

- **GIVEN** 共用同一代理实例的源只剩一个
- **WHEN** 关闭该源
- **THEN** 由 core 拉起的代理进程结束

#### Scenario: 不同进程各自拉起互不干扰

- **GIVEN** 两个宿主进程同时需要代理，环境中没有手动启动的代理
- **WHEN** 两者各自拉起代理并暂存
- **THEN** 各自连接自己派生出的管道名，一方关闭源或退出收尾不中断另一方的暂存

#### Scenario: 外部代理可跨进程共用

- **GIVEN** 用户手动启动的代理监听配置的基础管道名
- **WHEN** 两个宿主进程都获取需要代理的文件
- **THEN** 两者都连接该外部代理，且任一方关闭源或退出收尾都不结束它

#### Scenario: 收尾中止活动连接可重试

- **GIVEN** 一个源正在经 core 拉起的代理暂存
- **WHEN** 宿主调用进程级收尾入口
- **THEN** 该源收到断线错误事件并进入失败态，收尾入口返回后登记为空，之后的新获取可重新拉起代理

#### Scenario: 退出收尾只结束自己拉起的代理

- **GIVEN** 宿主退出前仍有源未关闭，且环境中另有一个手动启动的代理
- **WHEN** 宿主调用进程级收尾入口
- **THEN** core 拉起的代理全部结束，手动启动的代理不受影响；重复调用不产生额外动作

### Requirement: 失败分类

获取失败 SHALL 经同步返回或错误事件之一上报，携带错误码与参数，同一失败 MUST NOT 两路重复上报。plan 阶段可判定的失败 SHALL 只经同步返回交付，不发布事件——事件通道自 plan 成功建立句柄后生效；commit 受理后的运行期失败 MUST 只经错误事件上报。直接打开失败转代理时 SHALL 保留直接打开失败的附注；代理无法启动、拉起超时与运行中断线 SHALL 使用互不相同的错误码，启动失败 SHALL 携带代理路径与系统错误号；失败后 MUST 不残留源资源与租约，句柄保留至宿主显式释放——失败后对其推入返回失败，关闭与释放照常可用。

#### Scenario: 代理拉起超时

- **GIVEN** 模式要求走代理、代理无法在超时内就绪
- **WHEN** plan 执行
- **THEN** 同步返回超时错误码，不发布事件，未启用直读，无残留连接

#### Scenario: 代理无法启动

- **GIVEN** 模式要求走代理、代理可执行文件不可用（不存在或无法启动）
- **WHEN** plan 执行
- **THEN** 同步返回启动失败错误码（与超时错误码不同），参数携带代理路径与系统错误号，不发布事件，无残留连接

#### Scenario: plan 失败不经事件

- **GIVEN** plan 阶段即判定失败（如目标不存在）
- **WHEN** 宿主取回结果
- **THEN** 错误只经同步返回交付，不建立句柄、不产生事件通道

#### Scenario: 直接打开失败转代理

- **GIVEN** 自动模式、直接打开失败而代理可用
- **WHEN** plan 执行
- **THEN** 计划路由为代理暂存，不发布错误事件；该次直接打开失败的证据仅在代理随后也失败时以附注出现

#### Scenario: 受理后直开失败不再回退

- **GIVEN** plan 判定为本地直读、commit 已受理，随后打开源文件失败
- **WHEN** 装载执行
- **THEN** 发布直接打开失败的错误事件、句柄进入失败态，不尝试代理、不改变渠道

#### Scenario: 运行中断线

- **GIVEN** commit 已受理、代理暂存进行中、连接中途断开
- **WHEN** 获取继续执行
- **THEN** 发布断线错误码的错误事件，与拉起超时错误码不同，句柄进入失败态，源资源与租约不残留，句柄保留至显式释放

#### Scenario: 格式拒绝按阶段分通道

- **GIVEN** 同一非文本输入分别在 plan 期（直读可判）与受理后（暂存副本）被识别
- **WHEN** 拒绝发生
- **THEN** plan 期只经同步返回交付，不发布事件；受理后只经错误事件上报，句柄进入失败态

### Requirement: 文本嗅探规则

文件源的文本嗅探 SHALL 以固定大小窗口读取头部，统计除制表、换行、回车、换页之外的控制字符与删除符占比，占比严格大于阈值判为非文本；空文件判为文本；字节序特征判为宽字符编码即非文本。窗口大小与阈值 SHALL 可由宿主经配置快照注入，且 MUST NOT 暴露为用户设置项。直读文件与暂存副本使用同一判据。

#### Scenario: 空文件判文本

- **GIVEN** 文件源为空文件
- **WHEN** 嗅探执行
- **THEN** 判定为文本，按日志文本继续

#### Scenario: 控制字符占比超过阈值

- **GIVEN** 窗口内控制字符占比严格大于阈值
- **WHEN** 嗅探执行
- **THEN** 判定为非文本，由获取阶段按「不支持的格式拒绝」处理

#### Scenario: 控制字符占比恰在阈值上

- **GIVEN** 窗口内控制字符占比恰等于阈值
- **WHEN** 嗅探执行
- **THEN** 判定为文本，按日志文本继续

### Requirement: 三轴源描述

commit 受理后 core SHALL 经描述读取入口提供源描述，其渠道、格式、编码三轴 MUST 互相正交，任一单轴变化不得牵动其余两轴。描述 SHALL 包含：显示路径与源路径分离、列声明（宿主只按列声明渲染，不自持列集）、四要素身份（大小、修改时间、首尾各 64 KB 指纹；本地直读源在 plan 阶段读样本算全、受理骨架即给出，装载开始时复核发现文件已变则更新为复核值；代理暂存源与采集源身份为空且属合法组合）、装载模式（一次到位或分块渐进；本地直读源命中缓存为一次到位，未命中为分块渐进，命中条目在装载开始解码失败时由一次到位更新为分块渐进且仅更新一次，暂存与采集源恒为分块渐进）、行数与文档大小、追加模式、租约性质与租约标识、时间语义。采集源没有用户路径，其显示路径 SHALL 为空值；宿主 MUST NOT 以显示路径作为采集源的标题或最近使用键，标题与最近使用口径归宿主。描述 SHALL 在 commit 受理时即产出骨架并随装载推进更新，失败态 SHALL 返回最后快照而非报错；宿主 MUST NOT 以描述可读推断源路径所指产物存在或装载成功。

#### Scenario: 三轴正交

- **GIVEN** 一个本地直读的 UTF-8 日志文件
- **WHEN** commit 受理后读取描述
- **THEN** 渠道、格式、编码三轴各自独立取值，改变其中一轴的输入不会连带改变其余两轴的取值逻辑

#### Scenario: 文件源身份受理即可读

- **GIVEN** 一个本地直读文件的 plan 已成功
- **WHEN** commit 受理后读取描述
- **THEN** 身份四要素已完整可读，取 plan 阶段算全的值，不因装载未完成而空缺

#### Scenario: 计划后文件被改写

- **GIVEN** plan 已成功、commit 受理前文件被外部改写
- **WHEN** 装载开始时复核身份
- **THEN** 身份更新为复核值，装载模式改为分块渐进，按未命中完整解析，描述与装载结果均对应文件当前内容

#### Scenario: 命中条目解码失败装载模式更新

- **GIVEN** plan 头部命中缓存、装载开始复核身份一致，但条目列数据损坏
- **WHEN** 装载开始解码条目失败并降级为完整解析
- **THEN** 描述中的装载模式更新为分块渐进且仅更新一次，身份保持复核值，不发布错误事件

#### Scenario: 显示路径不外泄暂存路径

- **GIVEN** 经代理暂存打开的文件
- **WHEN** 宿主消费源描述
- **THEN** 标题、最近使用与导出命名只使用用户原路径，暂存路径仅经源路径字段供内部使用

#### Scenario: 采集源身份为空属合法

- **GIVEN** 采集会话的 commit 已受理
- **WHEN** 宿主读取描述
- **THEN** 身份为空属合法组合，不构成失败

#### Scenario: 代理暂存源身份为空

- **GIVEN** 一次经代理暂存打开的文件源
- **WHEN** 宿主读取描述
- **THEN** 身份为空属合法组合，不构成失败；暂存文件身份不被补算

#### Scenario: 采集源无显示路径

- **GIVEN** 采集会话的 commit 已受理
- **WHEN** 宿主读取描述并构建标题
- **THEN** 显示路径为空值，宿主按渠道自行生成标题且不把它写入最近使用，不构成失败

#### Scenario: 失败态描述仍可读

- **GIVEN** 采集 commit 已受理，随即因临时目录不可写进入失败态，此前无任何一行可装载
- **WHEN** 宿主读取描述
- **THEN** 返回最后快照：列集、渠道与租约等静态字段齐全，行数为已落盘行数，源路径所指文件即使不存在也不构成错误

### Requirement: 列声明下发

列集 SHALL 由 core 随源描述下发，宿主 MUST 按列声明的稳定标识渲染表头、执行导出与标记，不得按列位置索引。列标识 MUST 跨版本稳定。

#### Scenario: 按声明渲染表头

- **GIVEN** commit 返回的描述携带列声明
- **WHEN** 宿主重建表头
- **THEN** 列数与顺序与声明一致，且后续按列标识取值不因列集变化而错位

### Requirement: 配置只经快照传入

core MUST NOT 读取任何配置文件，不感知设置存储路径、存储格式与默认值规则；判定与装载所需的全部配置（模式、代理参数、嗅探窗口与阈值、暂存目录、缓存目录与容量上限）SHALL 由宿主在请求中一次性传入。请求 SHALL 为单一对象并按契约字段集校验：缺必填项或取值非法 MUST 返回参数错误并以字段路径指明位置；未声明字段 MUST 被忽略；缺省项 SHALL 按 core 声明的默认值生效；采集请求 MUST NOT 要求路径、代理配置与缓存目录。

#### Scenario: core 不读配置文件

- **GIVEN** 宿主环境中存在任意内容的设置文件
- **WHEN** plan 与 commit 执行
- **THEN** 判定结果只取决于请求中传入的快照，与该文件内容无关

#### Scenario: 缺必填字段报字段名

- **GIVEN** 一个文件请求缺少代理配置
- **WHEN** plan 执行
- **THEN** 返回参数错误，参数中的字段路径指出缺失的是代理配置，且不产生任何装载副作用

#### Scenario: 缺省值生效

- **GIVEN** 文件请求省略嗅探窗口与阈值
- **WHEN** plan 执行
- **THEN** 按 core 声明的默认值判定，行为与显式传入默认值一致

#### Scenario: 未知字段被忽略

- **GIVEN** 请求携带契约未声明的字段
- **WHEN** plan 执行
- **THEN** 请求正常执行，不因未知字段报错

#### Scenario: 采集请求不要求文件字段

- **GIVEN** 采集会话请求只带暂存目录与设备标注
- **WHEN** plan 与 commit 执行
- **THEN** 不因缺少路径、代理配置与缓存目录报错

### Requirement: sidecar 缓存复用

core SHALL 以四要素身份为键，在宿主传入的缓存目录中查找索引缓存：命中判定 SHALL 在 plan 阶段完成，仅以条目的定长头部为判据（魔数、格式版本、行数、段长形状、总长与四要素身份），MUST NOT 依赖条目中字典与列数据的解码结果，MUST NOT 为此读取列数据；为此 plan 阶段须读取文件首尾样本算全身份（只读，不建目录、不写条目），并按头部校验结果登记在用条目。命中条目的列数据解码 SHALL 在装载开始时、身份复核通过后进行；命中且复核身份一致时，SHALL 复用索引、跳过文本解析（缓存不含文本，命中仍须打开源文件取文本）；未命中、身份不一致、头部校验失败、条目解码失败或版本不符时，SHALL 静默降级为完整解析，任何缓存异常 MUST NOT 使获取失败、MUST NOT 发布错误事件。缓存 SHALL 只服务本地直读源，暂存与采集产物 MUST NOT 入缓存。缓存字节格式 SHALL 与既有实现保持一致：旧缓存 MUST 可直接复用，新写条目 MUST 为同一格式。写入 SHALL 原子替换、不得留下半成品；写入失败 MUST NOT 影响装载结果。缓存容量 SHALL 受条目与目录两级上限约束，超限按最近使用回收，本进程的在用条目 MUST NOT 被回收。取消与关闭 MUST NOT 删除缓存条目。缓存目录与容量上限 SHALL 由宿主经配置快照传入，core MUST NOT 自行发明默认目录。

#### Scenario: 二次打开命中缓存

- **GIVEN** 同一本地文件此前已装载并写入缓存，且文件身份未变
- **WHEN** 宿主再次发起获取
- **THEN** 描述中的装载模式为一次到位；装载开始时解码条目并跳过解析，行数与文档大小与文件内容一致

#### Scenario: 身份变化降级解析

- **GIVEN** 缓存存在，但文件大小或修改时间已变
- **WHEN** 装载执行
- **THEN** 视为未命中并完整解析，装载结果与文件当前内容一致，缓存被更新

#### Scenario: 损坏条目静默降级

- **GIVEN** 缓存条目头部校验通过，但列数据被外部破坏
- **WHEN** 装载开始解码条目
- **THEN** 获取成功且结果为完整解析，不发布错误事件，损坏条目被替换，装载模式更新为分块渐进

#### Scenario: 版本不符视为未命中

- **GIVEN** 缓存条目携带的格式版本与当前实现不一致
- **WHEN** 装载执行
- **THEN** 按未命中处理并完整解析；低于当前版本的条目在原位置重写，高于当前版本的条目不被覆盖

#### Scenario: 只缓存本地直读源

- **GIVEN** 一次经代理暂存或采集的获取
- **WHEN** 装载完成
- **THEN** 不产生缓存条目，暂存与采集产物不入缓存

#### Scenario: 容量回收保留在用条目

- **GIVEN** 缓存目录超出容量上限，且其中条目正被本进程的活动源使用
- **WHEN** 回收执行
- **THEN** 按最近使用淘汰其他条目，在用条目与新写条目被保留

#### Scenario: 关闭不删缓存

- **GIVEN** 装载已命中或写入缓存条目
- **WHEN** 宿主关闭并释放该源
- **THEN** 缓存条目仍在，可被后续获取复用

### Requirement: 在用条目口径

在用条目 SHALL 指本进程内未关闭的本地直读源所对应的缓存键：命中或写入缓存时登记，源关闭、取消或失败收尾时注销。容量回收 MUST 跳过在用条目并保留新写条目。启动维护 SHALL 以空的在用集合运行；回收其他进程的在用条目 SHALL 被允许，后果仅为该文件下次获取重新解析，MUST NOT 视为失败、MUST NOT 发布错误事件。维护结果 SHALL 如实统计回收后保留的条目数。

#### Scenario: 跨进程回收只致重新解析

- **GIVEN** 另一进程的活动源正使用某缓存条目
- **WHEN** 本进程启动维护并按容量回收
- **THEN** 该条目可被删除，另一进程的源不受影响，其下次获取该文件时完整解析且不报错

#### Scenario: 在用登记随源关闭注销

- **GIVEN** 源因命中缓存而登记了在用条目
- **WHEN** 该源关闭
- **THEN** 该条目不再受在用保护，可被后续容量回收删除

### Requirement: 临时产物与锁标记

core 创建的临时产物（代理暂存目录、采集文件）SHALL 落在请求快照指定的临时目录内，并以固定命名约定标识其归属与类型；创建产物之前 core MUST 先取得同名锁标记，并在产物存续期间独占持有该标记，标记 MUST NOT 承载任何业务数据。产物正常收尾删除时 SHALL 一并删除标记；进程异常退出时标记 MUST 随之失效，使该产物可被下一次维护判定为无主。标记被占用 SHALL 表示该产物归属某个活动进程，任何维护方 MUST NOT 删除标记被占用的产物。

#### Scenario: 产物与标记同时存在

- **GIVEN** 采集会话已建立
- **WHEN** 宿主检查临时目录
- **THEN** 采集文件与其锁标记同时存在，且标记在会话存续期间处于被占用状态

#### Scenario: 正常收尾不留标记

- **GIVEN** 采集会话已关闭
- **WHEN** 宿主检查临时目录
- **THEN** 采集文件与其锁标记都不存在

#### Scenario: 停止保留的产物仍被占用

- **GIVEN** 采集已停止但句柄尚未释放
- **WHEN** 宿主检查临时目录
- **THEN** 采集文件与其锁标记均保留，标记仍处于被占用状态

#### Scenario: 异常退出后产物可判无主

- **GIVEN** 进程异常退出，临时目录中留下暂存目录或采集文件
- **WHEN** 下一次维护执行
- **THEN** 这些产物与其锁标记被删除，不被误判为活动源

### Requirement: 启动维护流程

宿主 SHALL 在进程启动时调用一次维护入口，该入口 MUST NOT 依赖句柄或活动源，且 SHALL 同时处理缓存目录与临时目录。缓存侧 SHALL 校验条目结构、删除损坏条目与写入残留的临时文件、按容量上限回收。临时目录侧 SHALL 按命名约定识别暂存目录、采集文件及其锁标记：标记可被独占取得者视为无主，SHALL 连同产物一并删除；标记被占用者 MUST 跳过且 MUST NOT 删除；产物存在而标记缺失者视为无主；仅有标记而无对应产物者 SHALL 一并删除。维护 SHALL 返回统计结果并幂等，重复调用不产生额外删除；目录不存在 SHALL 视为空目录，返回零统计且不创建目录；任一目录维护失败（如不可写）MUST NOT 抛错、MUST NOT 阻断后续获取，且 MUST NOT 删除结构可读的有效缓存条目或仍被占用的产物。

#### Scenario: 启动维护清理损坏与残留

- **GIVEN** 缓存目录中存在损坏条目与写入残留的临时文件
- **WHEN** 维护入口被调用
- **THEN** 损坏条目与残留文件被删除，有效条目保留，返回统计如实反映删除数量

#### Scenario: 清理无主临时产物

- **GIVEN** 临时目录中存在进程异常退出遗留的暂存目录与采集文件
- **WHEN** 维护入口被调用
- **THEN** 这些产物与其锁标记被删除，统计如实反映删除数量

#### Scenario: 跳过仍被占用的产物

- **GIVEN** 临时目录中存在仍被另一活动进程持有的采集文件
- **WHEN** 维护入口被调用
- **THEN** 该产物与其标记被保留，统计记入跳过数量，不构成失败

#### Scenario: 启动维护幂等

- **GIVEN** 维护刚刚完成
- **WHEN** 再次调用维护入口
- **THEN** 不产生新的删除，返回统计为零

#### Scenario: 目录不存在视为空

- **GIVEN** 宿主传入的缓存目录与临时目录均尚不存在
- **WHEN** 维护入口被调用
- **THEN** 返回零统计，不创建目录、不报错

#### Scenario: 维护失败不阻断获取

- **GIVEN** 缓存目录或临时目录不可写
- **WHEN** 维护入口被调用且随后发起获取
- **THEN** 维护返回部分失败统计，获取仍按未命中路径成功完成，仍被占用的产物与有效条目均未删除

### Requirement: 采集推入语义

采集会话 SHALL 由宿主取流并按批次推入完整行：推入调用异步入队即返，不阻塞宿主；行数据 SHALL 由 core 在调用返回前复制为自有内存，宿主内存在返回后即可释放或复用，MUST NOT 要求宿主保活；core SHALL 以无上限队列承接、不丢行，由消化线程按入队顺序完成解析、索引追加、落盘与事件发布。每批消化完成后 SHALL 发增量事件，其增量与提交行数一一对应，仅在行数增长时发布；空批次不发布事件。采集文件 SHALL 由 core 创建并追加写入，固定为 UTF-8 无 BOM、行尾 CRLF（宿主推入的行已按 UTF-8 解码），路径经源描述交还宿主。单批超过推入上限时 SHALL 整批被拒绝、返回参数错误且字段路径指向行数组，MUST NOT 部分入队，MUST NOT 发布事件；上限 SHALL 随绑定层以编译期常量与接口一同发布，core 不提供查询入口。

#### Scenario: 推入批次按序可读

- **GIVEN** 采集会话已建立，宿主依次推入多批已知行
- **WHEN** 各批消化完成
- **THEN** 采集文件中的行数与顺序和推入一致，每条增量事件的增量值与对应批次行数一致、累计值等于已装载行数

#### Scenario: 推入后宿主可立即复用缓冲

- **GIVEN** 宿主调用 feed 推入一批已知行
- **WHEN** 调用返回后宿主立刻释放或覆盖原缓冲区
- **THEN** 该批行仍完整消化并落盘，内容与顺序和推入一致，不出现乱码或丢失

#### Scenario: 入队即返不阻塞

- **GIVEN** core 消化速度慢于宿主推入速度
- **WHEN** 宿主推入新批次
- **THEN** 调用立即返回，行进入队列不丢失，拥堵体现为队列积压

#### Scenario: 空批次无事件

- **GIVEN** 宿主推入空批次
- **WHEN** core 处理该批
- **THEN** 不发布增量事件

#### Scenario: 超限批次整批被拒

- **GIVEN** 采集会话正在运行，宿主推入的单批行数超过随绑定层常量发布的上限
- **WHEN** core 处理该次推入
- **THEN** 调用返回参数错误且字段路径指向行数组，该批一行都不入队，也不发布增量事件

#### Scenario: 采集文件由 core 落盘

- **GIVEN** 采集会话推入若干批已知行并消化完成
- **WHEN** 宿主读取源描述中的源路径
- **THEN** 该文件存在、内容与推入行一致、编码与换行符合声明，可被宿主复制

### Requirement: 采集收尾语义

停止 SHALL 排空队列、刷盘并发停止事件，之后句柄与采集文件保留，后续推入 MUST 返回已停止且不入队；停止的排空进度 MUST 经进度轮询入口可查。排空开始后句柄进入排空中：排空期间推入 MUST 立即返回已停止且不入队，重复停止 SHALL 幂等等待同一结果；排空期间的关闭 SHALL 中止排空并完成关闭，此后 MUST NOT 发布停止事件，被阻塞的停止调用 SHALL 返回已关闭。关闭 SHALL 停止消化、作废未消化队列、释放源资源（含尽力删除采集文件）并以同步返回表示完成，关闭完成后推入 MUST 返回已关闭且不入队；关闭与推入的竞争由 core 串行化。停止 SHALL 由宿主在停止取流并推完残余批次之后发起；core MUST NOT 停止宿主取流；关闭不要求该前置顺序，无外部占用时关闭后不再保留任何采集产物。宿主 MUST 在关闭返回前不退出进程。落盘失败时 SHALL 清空队列、发布错误事件、后续推入返回失败且不入队，已落盘行必须保留，不得静默丢数据。

#### Scenario: 停止后排空并保留文件

- **GIVEN** 采集会话有未消化批次
- **WHEN** 宿主发起停止
- **THEN** 剩余批次全部消化落盘后发布停止事件，文档仍完整可读，采集文件保留

#### Scenario: 停止后推入被拒

- **GIVEN** 停止已完成
- **WHEN** 宿主推入新批次
- **THEN** 调用返回已停止，行不入队、不产生事件

#### Scenario: 排空期间推入被拒

- **GIVEN** 停止已发起、队列仍在排空
- **WHEN** 宿主推入新批次
- **THEN** 调用立即返回已停止，行不入队，排空不受影响

#### Scenario: 排空期间关闭中止排空

- **GIVEN** 停止已发起、排空仍在进行
- **WHEN** 另一线程发起关闭
- **THEN** 关闭完成、采集文件删除，此后不发布停止事件，被阻塞的停止调用返回已关闭

#### Scenario: 宿主先停取流再收尾

- **GIVEN** 采集会话仍有数据在宿主侧取流管道中
- **WHEN** 宿主准备停止采集
- **THEN** 宿主先停止取流并推完残余批次，再调用停止；core 不代宿主停止取流

#### Scenario: 关闭直接丢弃未消化队列

- **GIVEN** 采集会话仍有未消化批次
- **WHEN** 宿主发起关闭
- **THEN** 关闭返回时队列中剩余行未被消化、采集文件已删除、源资源已释放，句柄仍可安全访问；该丢弃是关闭语义的一部分，不视为数据丢失

#### Scenario: 停止排空进度可查

- **GIVEN** 采集会话仍有积压批次
- **WHEN** 宿主发起停止并轮询进度
- **THEN** 可观察到排空进度直至停止事件发布，排空期间无行丢失

#### Scenario: 关闭后推入被拒

- **GIVEN** 采集会话的关闭已完成
- **WHEN** 宿主推入新批次
- **THEN** 调用返回已关闭，行不入队、不产生事件

#### Scenario: 关闭后采集文件删除

- **GIVEN** 采集会话已完成关闭
- **WHEN** 宿主检查源描述中的源路径
- **THEN** 采集文件已不存在，租约性质为关闭即删

#### Scenario: 落盘失败不静默丢数据

- **GIVEN** 采集文件所在位置写入失败
- **WHEN** 消化线程落盘失败
- **THEN** 发布错误事件、队列清空、后续推入返回失败，此前已落盘的行保留且可读

#### Scenario: 排空期间落盘失败

- **GIVEN** 停止已发起、排空仍在进行，此时写入失败
- **WHEN** 消化线程落盘失败
- **THEN** 发布错误事件且不发布停止事件，句柄进入失败态，被阻塞的停止调用返回失败；此前已落盘的行与采集文件保留

### Requirement: 关闭时产物删除尽力而为

关闭 SHALL 释放源资源并解除锁标记；删除采集文件与暂存产物 SHALL 尽力而为：被外部进程占用导致删除失败时，MUST NOT 改变关闭的返回结果、MUST NOT 发布错误事件、MUST NOT 使句柄停留在非关闭状态；残留产物 SHALL 在下次启动维护时按无主产物回收。删除失败不构成关闭失败，宿主 MUST NOT 以关闭后的产物是否存在判定关闭结果。

#### Scenario: 产物被外部占用时关闭仍完成

- **GIVEN** 外部进程持有采集文件或暂存产物的打开句柄
- **WHEN** 宿主发起关闭
- **THEN** 关闭正常返回、句柄状态为已关闭、锁标记已解除；产物残留，下次启动维护将其按无主删除

#### Scenario: 无外部占用时关闭不留产物

- **GIVEN** 没有外部进程占用采集文件
- **WHEN** 关闭完成
- **THEN** 采集文件与锁标记均不存在

### Requirement: 排空进度口径

排空进度 SHALL 只描述本次排空：进入排空时已处理量归零，总量为发起停止时队列中的剩余行数，排空完成时已处理量与总量相等。宿主 MUST NOT 从排空进度推断文档的累计行数，累计行数 SHALL 取自增量事件的累计值或源描述中的行数。

#### Scenario: 排空进度从零起算

- **GIVEN** 采集会话已消化若干行、队列中仍有剩余行
- **WHEN** 宿主发起停止并轮询进度
- **THEN** 已处理量从零起算，总量为发起停止时队列剩余行数，排空完成后两者相等

#### Scenario: 累计行数不走排空进度

- **GIVEN** 排空仍在进行
- **WHEN** 宿主需要文档的累计行数
- **THEN** 取自增量事件的累计值或源描述中的行数，排空进度只反映本次排空

### Requirement: 事件通道为轮询制

进度与状态 SHALL 经宿主轮询获取，MUST NOT 采用回调：进度用可轮询的原子计数（阶段、已处理量与总量；装载期以字节计，采集中与排空以行计，总量客观不存在时如实为空）；取消用宿主可控的原子标志。事件流 SHALL 满足：阶段按获取路径固定顺序推进且不倒退，同一阶段内已处理量单调不减；渠道在 plan 阶段确定，受理后 MUST NOT 发布渠道变化事件；终态按源类型分派——文件源以完成或错误为终态，采集源以停止或错误为终态，同一源至多出现一个终态事件，终态之后不再出现该源的装载事件；关闭不发布终态事件。单次轮询 SHALL 返回自上次轮询以来产生的全部事件，空结果为合法返回值；增量事件 SHALL 只由采集源产生并同时携带本批增量与累计行数；文件源装载 MUST NOT 发布增量事件，其行数经源描述读取。宿主 MUST 按固定周期轮询事件以控制内存占用；源未关闭期间事件 MUST NOT 因轮询延迟而丢失或被合并；关闭即作废尚未取走的事件与进度（关闭语义为丢弃当前文档），关闭后的轮询 MUST 返回已关闭。

#### Scenario: 轮询延迟不丢事件

- **GIVEN** 宿主一段时间未轮询事件
- **WHEN** 宿主恢复轮询
- **THEN** 期间产生的事件全部可读取，未被丢弃或合并

#### Scenario: 关闭作废未取走事件

- **GIVEN** 关闭前产生了尚未被轮询取走的事件
- **WHEN** 关闭返回后宿主轮询
- **THEN** 返回已关闭，不返回这些事件，且不构成错误

#### Scenario: 无新事件返回空结果

- **GIVEN** 上一次轮询已取走全部待处理事件
- **WHEN** 宿主再次轮询且其间未产生新事件
- **THEN** 返回空结果，不构成错误、不产生额外事件

#### Scenario: 进度单调

- **GIVEN** 一次正在进行的装载
- **WHEN** 宿主连续轮询进度
- **THEN** 阶段按路径顺序推进不倒退，同一阶段内已处理量单调不减

#### Scenario: 文件源装载不发增量事件

- **GIVEN** 文件源的 commit 已受理、装载仍在进行
- **WHEN** 宿主轮询事件
- **THEN** 事件流只出现阶段切换与终端事件，不出现增量事件；装载中的行数经源描述读取

#### Scenario: 渠道在计划返回时确定

- **GIVEN** 自动模式、直接打开失败但代理可用
- **WHEN** plan 执行
- **THEN** 计划返回的路由即为代理暂存，commit 受理后描述与该路由一致，装载期间渠道不再变化、不发布渠道变化事件

#### Scenario: 无总量时如实表达

- **GIVEN** 采集会话正在运行、日志总量客观不存在
- **WHEN** 宿主读取进度
- **THEN** 已处理量为已解析行数、总量为空，core 不编造比例

#### Scenario: 终态唯一

- **GIVEN** 一次装载到达完成、停止或错误
- **WHEN** 宿主继续轮询
- **THEN** 该源至多出现一个终态事件，且事件流在其后不再出现该源的装载事件

#### Scenario: 关闭不发终态事件

- **GIVEN** 采集会话正在关闭
- **WHEN** 关闭完成、源资源释放
- **THEN** 事件通道不产生停止或完成事件，关闭结果以关闭调用的同步返回为准

### Requirement: 采集只属图形界面

采集推入通道 SHALL 仅由图形界面宿主实现与调用；第二宿主 SHALL 复用其余契约面（文件获取与事件通道）但 MUST NOT 接入采集。

#### Scenario: 第二宿主不接采集

- **GIVEN** 非图形宿主消费本契约
- **WHEN** 其使用文件获取与事件轮询
- **THEN** 功能完整可用，且契约不要求其实现采集推入

### Requirement: 取消与不变量

plan 与 commit 两阶段 SHALL 各有取消口径：取消后已占用资源（代理连接、临时产物、租约）按阶段规则释放，不残留；句柄本身保留至宿主显式释放。关闭在计划就绪与装载中 SHALL 等价取消：中止该次获取、释放已占用资源（含计划阶段已拉起的代理连接），不发布终态事件。判定顺序 SHALL 固定；格式与编码 SHALL 在装载开始后运行期不变；关闭顺序固定为停消化、作废未消化队列、删除采集文件（尽力而为）/释放源资源、释放租约或删目录，句柄本身保留至宿主显式释放。

停止 SHALL 只对采集源有效，对文件源调用 MUST 返回非法状态。停止与关闭 SHALL 幂等：重复调用返回与首次相同的结果，不重复发布事件、不产生额外副作用；采集源处于失败状态时调用停止 MUST 返回失败。关闭后对句柄的推入、轮询与进度读取 MUST 安全返回已关闭，宿主可在任意线程并发轮询直至显式释放句柄。

#### Scenario: 提交阶段取消释放资源

- **GIVEN** commit 已受理、暂存或建索引仍在进行
- **WHEN** 宿主取消
- **THEN** 装载中止，临时产物与租约被释放，句柄保留至显式释放

#### Scenario: 计划阶段直接关闭

- **GIVEN** plan 已成功并已拉起代理，commit 尚未发起
- **WHEN** 宿主直接关闭该句柄（未先取消）
- **THEN** 效果与取消相同：代理连接被释放、不产生装载产物、不发布终态事件，句柄进入已关闭

#### Scenario: 格式编码运行期不变

- **GIVEN** 装载已开始
- **WHEN** 同一会话内继续读取或接收增量
- **THEN** 格式与编码轴保持装载开始时的取值

#### Scenario: 文件源上停止被拒

- **GIVEN** 活动源是文件源
- **WHEN** 宿主对其调用停止
- **THEN** 返回非法状态，装载不受影响

#### Scenario: 停止与关闭幂等

- **GIVEN** 采集会话已停止或已关闭
- **WHEN** 宿主重复调用停止或关闭
- **THEN** 返回与首次相同的结果，不重复发布事件、不产生额外副作用

#### Scenario: 失败态上停止返回失败

- **GIVEN** 采集会话因落盘失败进入失败状态
- **WHEN** 宿主调用停止
- **THEN** 返回失败，已落盘行不受影响

#### Scenario: 关闭后句柄仍可安全访问

- **GIVEN** 采集会话已关闭、句柄尚未被宿主显式释放
- **WHEN** 宿主推入、轮询事件或读取进度
- **THEN** 调用安全返回已关闭，不崩溃、不产生事件

#### Scenario: 关闭期间并发轮询安全

- **GIVEN** 一个线程正在关闭采集源
- **WHEN** 另一线程持续轮询事件或读取进度直至关闭返回
- **THEN** 两线程互不破坏，关闭返回后轮询仍可安全返回已关闭

### Requirement: 句柄状态与操作合法性

每句柄 SHALL 处于确定状态（计划就绪、装载中、已装载、采集中、排空中、已停止、失败、已关闭），各导出仅在契约定义的「状态 × 操作」组合上执行，其余组合 MUST 返回非法状态。排空期间推入 MUST 返回已停止，停止 SHALL 幂等，取消与释放 MUST 返回非法状态；关闭 SHALL 中止排空且此后不再发布停止事件。plan 成功之后、commit 发起之前，事件轮询 SHALL 返回空结果，进度 SHALL 返回初始阶段快照，两者均不构成错误。commit 受理之后 MUST NOT 再次 commit；装载完成之前的取消 SHALL 有效并中止装载（句柄进入已关闭），装载完成之后 MUST NOT 取消（采集的收尾走停止与关闭）。源描述读取在计划就绪时 MUST 返回非法状态，在已关闭时 MUST 返回已关闭，其余状态可读。释放句柄 MUST 以已关闭为前提，未关闭即释放 MUST 返回非法状态且不释放资源。

#### Scenario: commit 重复调用被拒

- **GIVEN** 句柄上的 commit 已受理
- **WHEN** 宿主再次发起 commit
- **THEN** 返回非法状态，已受理的装载不受影响

#### Scenario: 装载完成前取消中止装载

- **GIVEN** commit 已受理、文件源装载仍在进行
- **WHEN** 宿主对该句柄发起取消
- **THEN** 装载中止、已占用资源释放，句柄进入已关闭，未取走事件作废

#### Scenario: 装载完成后取消被拒

- **GIVEN** 文件源装载已完成或采集源已进入采集运行状态
- **WHEN** 宿主对该句柄发起取消
- **THEN** 返回非法状态，源继续运行，收尾只能经停止或关闭

#### Scenario: 计划就绪时读描述被拒

- **GIVEN** plan 已成功、commit 尚未发起
- **WHEN** 宿主读取源描述
- **THEN** 返回非法状态，不产生副作用

#### Scenario: plan 阶段轮询与读进度

- **GIVEN** plan 已成功、commit 尚未发起
- **WHEN** 宿主轮询事件并读取进度
- **THEN** 轮询返回空结果、进度返回初始阶段快照，均不构成错误

#### Scenario: 未关闭即释放被拒

- **GIVEN** 句柄仍处于活动状态
- **WHEN** 宿主释放该句柄
- **THEN** 返回非法状态、句柄与源资源均未释放，随后关闭与释放均可成功

### Requirement: 多活动源并存

同一 core 实例内 SHALL 允许同时存在多个活动源（含文件源与采集源），各句柄的判定、装载、事件与进度互相独立；core MUST NOT 设置活动源数量上限，也 MUST NOT 因闲置自行关闭或回收任何源。源的生命周期 SHALL 由宿主外部管理：宿主负责关闭不再使用的源，回收时 MUST 保留最近使用的活动源，不得把仍在使用的源判为闲置。

#### Scenario: 多源并存

- **GIVEN** 一个采集会话正在运行
- **WHEN** 宿主再打开一个文件源
- **THEN** 两个源都成功建立，各自的判定、事件与进度互不干扰

#### Scenario: 关闭一个源不影响其他

- **GIVEN** 同时存在多个活动源
- **WHEN** 宿主关闭其中一个
- **THEN** 其余源的句柄、装载内容与事件流不受影响

#### Scenario: core 不自行回收闲置源

- **GIVEN** 一个已建立的源长时间无推入、无轮询
- **WHEN** 时间流逝
- **THEN** core 不关闭、不回收该源，其句柄仍可正常使用

#### Scenario: 宿主回收保留最后源

- **GIVEN** 多个源中只有最后一个仍在使用
- **WHEN** 宿主按超时回收闲置源
- **THEN** 最近使用的活动源被保留，关闭其余源后保留源仍完整可用

### Requirement: 不支持的格式拒绝

文件源在解析之前 SHALL 判定格式：首部命中 DLT 魔数 `44 4C 54 01` 判为 DLT；文本嗅探判为非文本的判为二进制；其余按日志文本继续。格式判定 MUST 先于身份摘要与缓存查找。plan 阶段可判定的拒绝 SHALL 同步返回 UNSUPPORTED_FORMAT（14），`format` 参数取 `Dlt` 或 `Binary`，不建立句柄；commit 受理后才可判定的拒绝（暂存副本）SHALL 发同码错误事件，句柄进入失败态，不发布任何行。拒绝 MUST NOT 产生缓存条目、MUST NOT 改变源描述的渠道与格式轴、MUST NOT 产出成功态的源描述。

#### Scenario: 直读文件非文本被拒

- **GIVEN** 模式为自动或显式关闭、文件可直接打开、首部未命中 DLT 魔数且嗅探判为非文本
- **WHEN** plan 执行
- **THEN** 同步返回 UNSUPPORTED_FORMAT，`format` 参数为 `Binary`，不建立句柄、不发布事件，也不产生缓存条目

#### Scenario: DLT 魔数给出格式标签

- **GIVEN** 文件首部 4 字节为 `44 4C 54 01`，其余字节即使会被嗅探判为非文本
- **WHEN** plan 执行
- **THEN** 同步返回 UNSUPPORTED_FORMAT，`format` 参数为 `Dlt`（魔数判定先于嗅探）

#### Scenario: 暂存副本非文本被拒

- **GIVEN** 模式为显式开启，或自动模式下直接打开失败已转代理；暂存完成且副本嗅探判为非文本（首部未命中魔数）
- **WHEN** 装载开始
- **THEN** 发布 UNSUPPORTED_FORMAT 错误事件且 `format` 参数为 `Binary`，句柄进入失败态，不发布任何行，不产生缓存条目

#### Scenario: 拒绝先于缓存查找

- **GIVEN** 目标文件为非文本，且缓存目录中存在其身份键对应的条目
- **WHEN** plan 执行
- **THEN** 同步返回拒绝，不读取、不命中、也不复用该条目
