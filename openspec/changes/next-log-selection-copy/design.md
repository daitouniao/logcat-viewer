# Design

## Context

见 `proposal.md`。当前实现的关键现状：

- 日志行由自绘画布按视口绘制，画布本身不参与命中测试，鼠标事件落在其上的透明滚动容器；颜色只允许来自 `DesignTokens`（主题键两套必须对齐，已有测试守护）。
- 行数据按「起始行 + 条数」分页取回后解码为托管行模型，页缓存在页面供给层；任意时刻只有视口附近的页在内存里。
- 键盘事件已在主窗处理（目前只有 `Ctrl+End`），状态栏文案经本地化键生成。
- 当前没有过滤，行序 = 文档行序；未来过滤接入后行序将变为结果集序，选择与复制必须按同一序。

## Goals / Non-Goals

**Goals:**

- 选择集合与命中行都按「行序」表达，不依赖具体页是否已在缓存。
- Shift 区间选择在千万行文件上不产生与行数同阶的内存分配。
- 复制在后台取数，不阻塞滚动；复制内容与旧查看器「复制原始文本」一致。
- 选择状态不进入数据层，不改任何互操作导出。

**Non-Goals:**

- 不做框选、拖动选择、右键菜单、全选快捷键与「复制为表格行」。
- 不做跨文件/跨结果集的选择保持。
- 不为超大选择设置硬上限；复制规模的风险在「风险」节如实记录。

## Decisions

### D1 选择集合用区间集（有序不重叠区间），不用逐行集合

- 选择语义是「若干行区间」：Shift 选择天然是区间，Ctrl 单击是增删单行。
- 用逐行 `HashSet<long>` 时，Shift 选中 270 万行会产生同量级条目（数十 MB）；区间集只存边界，成员判定用二分查找，内存与区间数同阶（正常使用几十个）。
- 与「虚拟列表只渲染视口」同源：绘制时对每个可见行做成员判定，成本 O(log 区间数)。
- 备选：`HashSet<long>`（实现最简，但大区间不成立）；位图压缩（省内存但实现重、对增量切换不友好）——不取。

### D2 命中测试放在滚动容器，画布保持不可命中

- 画布当前不参与命中测试，滚动容器接收指针事件；点击位置换算为「行序 = (滚动偏移 + 局部 Y) / 行高」。
- 指针落点是滚动条/滑块时跳过，避免把拖动滚动条误判为选行。
- 选择变化只触发画布重绘（重绘是既有的视口级绘制），不引入新的布局或控件树。

### D3 选择状态由主窗持有，页供给层不感知选择

- 主窗持有区间集与锚点行，画布通过依赖属性接收「选中判定」能力（或选中集快照），变化时重绘。
- 页供给层保持现状，只负责取页；选择与复制在界面层组合。
- 文件切换 / 重新装载时主窗清空选择；主题、语言、尺寸变化只重绘，不动选择（与既有「外观变化不改变查看位置」一致）。

### D4 复制按区间逐页取数，复用页缓存，后台拼装

- 复制需要范围内的原文；这些行可能不在当前页缓存里。
- 在页供给层增加「按行区间取行」的异步入口：命中缓存直接返回，缺页时按页大小顺序补齐（与视口取页同一条路径、同一份缓存），取完在后台拼装。
- 拼装内容 = 每个选中行的原始文本（已解码为托管字符串的原文），按行序用 `\n` 连接、末尾不加换行；这是旧查看器「复制原始文本」的口径。
- 复制期间不改选择；完成后以状态栏「已复制 N 行」反馈，失败给失败提示，不弹模态框。
- 备选：让数据层返回「按行号取原文」的导出接口——需要改 C ABI，超出本切片，且现有分页接口已足够。

### D5 选中行的视觉用新的语义色 token

- 选中行绘制底色，文字颜色不变；新增 token（如 `Surface.Selection`）并在明暗两套主题各给一值，沿用既有 token 完整性测试。
- 不在控件内写颜色字面量；主题切换后画布按既有机制重绘，选中底色随主题变化。

### D6 快捷键与本地化

- `Ctrl+C` 在主窗键盘处理中识别；无选择时不消费按键、不改状态栏。
- 复制成功/失败用既有稳定键本地化目录新增两条文案，中英各一份；缺键由既有测试报红。
- 复制过程不新增快捷键；`Ctrl+End` 等既有行为不变。

## Risks / Trade-offs

- [超大区间复制占用内存与时间] → 复制在后台取数与拼装，不阻塞滚动；第一版不设硬上限，已知一次性大选择可能产生很大字符串，后续需要时可加「复制中」进度或上限（不影响本规范）。
- [页缓存被选择/复制路径挤占] → 只读复用现有页缓存与失败集，不新增第二份缓存；失败页与视口一致地不重试。
- [未来过滤接入后行序含义变化] → 设计与规范统一用「行序」而非「文档行号」；过滤接入时只需把行序绑定到结果集序，选择逻辑不改。
- [滚动条拖动被误判为选行] → 指针事件源头判断，落在滚动条/滑块时不进入选择逻辑。
- [键盘焦点在输入控件时 Ctrl+C 被抢] → 当前窗口无输入框；后续加过滤框时只在非文本输入焦点下处理复制（设计已记录边界）。
