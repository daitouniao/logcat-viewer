# Spec Delta

## ADDED Requirements

### Requirement: 正则模式参与正文过滤

正文条件 SHALL 支持两种匹配方式：子串（缺省）与正则。正则模式 MUST 只作用于记录正文，其作用域、全部/任一组合、排除语义与结果集形态 MUST 与子串模式共用同一契约。正则档 SHALL 只回答「该行正文是否被 pattern 集合按组合方式命中」，MUST NOT 给出命中位置或抽取子串。

#### Scenario: 通配跨度只命中目标行

- **GIVEN** 一行正文含 `ANR in com.example.process`，另一行正文含 `ANR in` 后不带包名
- **WHEN** 以正则 `ANR in com\..*` 过滤
- **THEN** 只有第一行命中

#### Scenario: 正则档头部信息不参与匹配

- **GIVEN** 一行 tag 为 `ActivityManager`，其正文不含该词
- **WHEN** 以正则 `[Aa]ctivity\w*` 作为正文条件过滤
- **THEN** 该行不命中

#### Scenario: 只判存在性不回传命中位置

- **GIVEN** 一行正文同时命中两条 pattern
- **WHEN** 以正则档过滤
- **THEN** 结果集只含该行的文档行号，不携带命中位置或命中词

#### Scenario: 正则档排除剔除命中行

- **GIVEN** 文档三行正文，其中一行命中给定正则
- **WHEN** 以该正则、开启排除过滤
- **THEN** 命中的行被剔除，其余两行保留

#### Scenario: 正则档全部命中

- **GIVEN** 一行正文同时含 `GC` 与 `pause`，另一行只含 `GC`
- **WHEN** 以两条正则、全部命中过滤
- **THEN** 只有同时含两者的行命中

### Requirement: 正则档的正文归一化

正则档 SHALL 与子串档同源取正文，并 MUST 在求值前把无法按 UTF-8 解码的字节归一为替换字符；含非法字节的行 MUST 与合法行同等参与求值，MUST NOT 影响同一文档其余记录的判定。同一行的归一化结论 MUST 被该行全部 pattern 复用，判定结果 MUST NOT 随 pattern 条数或提交顺序而变。

#### Scenario: 非法字节按替换字符命中

- **GIVEN** 一行正文含无法按 UTF-8 解码的字节，界面上显示为替换字符
- **WHEN** 以匹配替换字符的正则过滤
- **THEN** 该行命中

#### Scenario: 非法字节两侧可被通配跨连

- **GIVEN** 同一行正文中非法字节前后各有一个可见字符
- **WHEN** 以把这两个字符直接相邻书写的正则（中间无元字符）过滤
- **THEN** 该行命中（非法字节占一个可匹配位置）

#### Scenario: 条数与顺序不改变判定

- **GIVEN** 同一份文档，正文条件为若干条正则
- **WHEN** 分别以该条件与其逆序提交过滤
- **THEN** 两次结果集完全相同

### Requirement: 正则档的空正文与空 pattern

正则模式下空正文行 SHALL 按长度为 0 的文本参与求值：能匹配空串的 pattern 在其上命中，不能匹配空串的 pattern 不命中。空 pattern SHALL 视为可在任意位置匹配，其全部命中/任一命中与排除的结论 MUST 与子串档的空词语义一致。正文条件为空集合时仍视为该类别未启用，空字符串取值 MUST NOT 被归一为未启用。

#### Scenario: 锚点正则命中空正文

- **GIVEN** 文档含一行正文为空、若干行正文非空
- **WHEN** 以只能匹配空串的首尾锚点正则过滤
- **THEN** 只有正文为空的行命中

#### Scenario: 通配正则命中空正文

- **GIVEN** 一行正文为空
- **WHEN** 以匹配任意长度（含零长）的正则过滤
- **THEN** 该行命中

#### Scenario: 单词边界正则不命中空正文

- **GIVEN** 一行正文为空
- **WHEN** 以只含单词边界的正则过滤
- **THEN** 该行不命中

#### Scenario: 空 pattern 与排除

- **GIVEN** 文档含任意若干记录
- **WHEN** 以只含空字符串取值的正则条件、开启排除过滤
- **THEN** 结果为空（空 pattern 恒命中，排除后全部剔除）

#### Scenario: 空集合取值仍为未启用

- **GIVEN** 文件源装载完成
- **WHEN** 提交正文条件为空集合、其他条件为空的过滤
- **THEN** 结果集为恒等视图

### Requirement: 正则档大小写等价

正则模式下 `case` 缺省（忽略大小写）时 SHALL 按 Unicode 大小写折叠求值：ASCII 字母大小写 MUST 等价，`ß` 与 `ẞ` MUST 等价，带重音与不带重音 MUST NOT 等价。`case` 为区分大小写时 MUST 按码点精确求值，但 pattern 内自行声明的大小写开关 SHALL 仍按正则方言生效。

#### Scenario: 缺省忽略大小写

- **GIVEN** 一行正文含 `TIMEOUT`
- **WHEN** 以正则 `timeout` 过滤且未区分大小写
- **THEN** 该行命中

#### Scenario: 区分大小写后不命中

- **GIVEN** 一行正文含 `TIMEOUT`
- **WHEN** 以正则 `timeout` 过滤且开启区分大小写
- **THEN** 该行不命中

#### Scenario: pattern 内大小写开关仍生效

- **GIVEN** 一行正文含 `Timeout`
- **WHEN** 以在 pattern 内自行声明忽略大小写的 `timeout` 过滤且开启区分大小写
- **THEN** 该行命中（pattern 内开关不被外层区分大小写抹掉）

#### Scenario: 折叠后的德语大写 eszett 等价

- **GIVEN** 一行正文含 `straße`，另一行含 `STRAẞE`
- **WHEN** 以正则 `strasse` 过滤且未区分大小写
- **THEN** 两行均不命中；改以 `ß` 书写时两行均命中

### Requirement: 正则方言边界

正文正则 SHALL 采用线性时间求值的方言，MUST NOT 支持环视（前视与后视）、反向引用、原子组与独占量词；提交这些写法 MUST 按语法不合法拒绝，MUST NOT 静默忽略或降级。`\w` `\d` `\s` `\b` MUST 按 Unicode 语义求值，字符类集合运算与 Unicode 属性类 SHALL 可用。pattern 的合法与否 MUST 只由 core 判定，宿主 MUST NOT 以其他引擎的语法结论替代。

#### Scenario: 前视被拒

- **GIVEN** 文件源装载完成
- **WHEN** 提交含前瞻环视的正文正则
- **THEN** 开启查询时按正则无效拒绝并标明原因是语法，不产出结果集

#### Scenario: 反向引用被拒

- **GIVEN** 文件源装载完成
- **WHEN** 提交含序号反向引用的正文正则
- **THEN** 按正则无效拒绝并标明原因是语法

#### Scenario: Unicode 词类命中中文正文

- **GIVEN** 一行正文为中文词语
- **WHEN** 以「一个或多个词字符」的正则过滤
- **THEN** 该行命中（词字符不限于 ASCII）

#### Scenario: 属性类可用

- **GIVEN** 一行正文含大写字母
- **WHEN** 以按 Unicode 字母类别书写的正则过滤
- **THEN** 该行命中

### Requirement: 字面量型正则与子串档同结论

区分大小写时，把所有元字符均已转义（等价于纯文本）的 pattern 以正则模式提交，其命中行集 MUST 与把同一文本以子串模式提交的结果集完全相同。忽略大小写时二者 MAY 不同，差异 MUST NOT 出现在纯 ASCII 正文上。

#### Scenario: 转义点号与子串同集

- **GIVEN** 一份文档，部分行含字面 `tim.eout`，部分行含 `timxeout`
- **WHEN** 分别以区分大小写的子串条件 `tim.eout` 与正则条件 `tim\.eout` 过滤
- **THEN** 两次结果集相同，均只含字面 `tim.eout` 的行

#### Scenario: 未转义点号不是字面量

- **GIVEN** 同一份文档
- **WHEN** 以区分大小写的正则 `tim.eout` 过滤
- **THEN** `timxeout` 的行也命中，与子串档结论不同（该 pattern 含元字符，不受上一条约束）

### Requirement: 正则条件的规模上限

单条正文正则的字符数 MUST 有上限（2000 字符），同一正文条件的正则条数 MUST 有上限（16 条），且实现 MUST 另设编译规模上限以拒绝长度合规但展开规模失控的 pattern。三者取值 SHALL 在实现口径中固定，不因源文件内容与调用方而变。

#### Scenario: 单条超长被拒

- **GIVEN** 文件源装载完成
- **WHEN** 提交字符数超过上限的正文正则
- **THEN** 按正则无效拒绝并标明原因是长度超限

#### Scenario: 条数超限被拒

- **GIVEN** 文件源装载完成
- **WHEN** 同一正文条件提交超过条数上限的正则
- **THEN** 按正则无效拒绝并标明原因是条数超限

#### Scenario: 规模失控被拒

- **GIVEN** 文件源装载完成
- **WHEN** 提交长度合规、但展开后编译规模超过实现上限的正则
- **THEN** 按正则无效拒绝并标明原因是规模超限

#### Scenario: 常见写法不受上限影响

- **GIVEN** 文件源装载完成
- **WHEN** 分别提交含 20 个分支的合并正则、2000 字符纯字面量与逐字符量词串联的正文正则
- **THEN** 三者均被接受，不触发规模类拒绝

### Requirement: 非法正则条件被拒绝

正文正则不合法规则（语法不合法、长度超限、条数超限、编译规模超限）时 MUST 在开启查询时同步拒绝，MUST NOT 静默降级为子串匹配、MUST NOT 产出部分结果集、MUST NOT 改变源句柄状态。拒绝 SHALL 使用专用错误码「正则无效（17）」而非参数错误，参数 MUST 只携带语义键：必带原因（语法 / 长度超限 / 条数超限 / 规模超限），能归因到具体某条时附带其序号，MUST NOT 携带文案。

#### Scenario: 语法错误同步返回

- **GIVEN** 文件源装载完成
- **WHEN** 以含未闭合分组的正文正则开启查询
- **THEN** 同步返回正则无效、原因为语法，不产出结果集，句柄仍可正常用于后续查询

#### Scenario: 原因区分语法与规模

- **GIVEN** 文件源装载完成
- **WHEN** 分别以未闭合分组与合规但规模失控的 pattern 开启查询
- **THEN** 两次返回同一错误码，参数中的原因互不相同

#### Scenario: 不降级为子串

- **GIVEN** 一行正文含字面 `(abc`
- **WHEN** 以语法不合法的正则 `(abc` 开启查询
- **THEN** 返回正则无效，不返回按子串匹配该文本的结果集

### Requirement: 参数类无效条件被拒绝

未知的匹配方式或组合方式、级别不在 1–7、分钟不在 0–59、为负的进程号或线程号、tag 条件中的空字符串取值 MUST 被拒绝为参数错误，并在参数中标明无效项。类型不符或 JSON 形状非法的条件 MUST 被拒绝为参数错误，并标明整个过滤表达式无效；其他无法归因到具体类别的错误同样标明整个过滤表达式无效。被拒绝的过滤 MUST NOT 产出结果集。正文匹配的取值方式仅接受子串与正则两种，其他取值 MUST 被拒绝为参数错误并标明无效项；正则模式自身的不合法内容不属于本条，按正则档的专用拒绝处理。本代未支持的类别或字段（如时间区间、标记）MUST 被拒绝为参数错误，并标明整个过滤表达式无效，MUST NOT 静默忽略。

#### Scenario: 未知组合方式被拒

- **GIVEN** 文件源装载完成
- **WHEN** 以「介于全部命中与任一命中之间」的未知组合方式提交过滤
- **THEN** 返回参数错误并指明无效的是组合方式，不产出结果集

#### Scenario: 分钟超出范围被拒

- **GIVEN** 文件源装载完成
- **WHEN** 以 60 作为分钟取值提交过滤
- **THEN** 返回参数错误并指明无效的是分钟条件，不产出结果集

#### Scenario: 未知正文匹配方式被拒

- **GIVEN** 文件源装载完成
- **WHEN** 以既非子串也非正则的正文匹配方式提交过滤
- **THEN** 返回参数错误并指明无效的是正文匹配方式，不产出结果集

#### Scenario: 级别取值越界被拒

- **GIVEN** 文件源装载完成
- **WHEN** 以 0 或 8 作为级别取值提交过滤
- **THEN** 返回参数错误并指明无效的是级别条件，不产出结果集

#### Scenario: 负进程号被拒

- **GIVEN** 文件源装载完成
- **WHEN** 以 -1 作为进程号提交过滤
- **THEN** 返回参数错误并指明无效的是进程号条件，不产出结果集

#### Scenario: 空 tag 值被拒

- **GIVEN** 文件源装载完成
- **WHEN** 以空串作为 tag 值提交过滤
- **THEN** 返回参数错误并指明无效的是 tag 条件，不产出结果集

#### Scenario: 未支持类别被拒

- **GIVEN** 文件源装载完成
- **WHEN** 提交含标记条件的过滤
- **THEN** 返回参数错误并标明整个过滤表达式无效，不产出结果集

#### Scenario: 类型不符被拒

- **GIVEN** 文件源装载完成
- **WHEN** 以字符串作为级别取值提交过滤
- **THEN** 返回参数错误并标明整个过滤表达式无效，不产出结果集

## MODIFIED Requirements

### Requirement: 正文大小写等价

本子串模式下忽略大小写（默认）时，比较双方 SHALL 按 Unicode 小写化后逐字节相等即命中：ASCII 字母大小写 MUST 等价，`ß` 与 `ẞ` MUST 等价，带重音与不带重音 MUST NOT 等价，土耳其无点 `ı` 与 ASCII `i` MUST NOT 等价。区分大小写时 MUST 按原始字节精确比较。无法按 UTF-8 解码的正文 MUST 按替换字符参与小写化，MUST NOT 影响同一文档其余记录的判定。正则模式的大小写等价另按正则档判定，MUST NOT 套用本条的折叠口径。

#### Scenario: ASCII 大小写双向等价

- **GIVEN** 一行正文含 `Plain ASCII`
- **WHEN** 分别以 `plain`、`PLAIN`、`PlAiN` 过滤
- **THEN** 三次结果一致，该行均命中

#### Scenario: 区分大小写严格比较

- **GIVEN** 一行正文含 `PLAIN`
- **WHEN** 以 `plain` 过滤且开启区分大小写
- **THEN** 该行不命中

#### Scenario: 德语 eszett 等价

- **GIVEN** 一行正文含 `Straße`，另一行含 `ẞ`
- **WHEN** 以 `ß` 过滤且忽略大小写
- **THEN** 两行均命中

#### Scenario: 开尔文符号折叠为 ASCII k

- **GIVEN** 一行正文含 ASCII `k`
- **WHEN** 以开尔文符号（U+212A）过滤且忽略大小写
- **THEN** 该行命中

#### Scenario: 土耳其无点 i 不等价

- **GIVEN** 一行正文只含 `ı`，不含 ASCII 的 i 或 I
- **WHEN** 以 `i` 过滤且忽略大小写
- **THEN** 该行不命中

#### Scenario: 重音字符不等价

- **GIVEN** 一行正文含 `CAFÉ`，另一行含 `cafe`
- **WHEN** 以 `café` 过滤且忽略大小写
- **THEN** 只有含 `CAFÉ` 的行命中

#### Scenario: 非法 UTF-8 按替换字符参与比较

- **GIVEN** 一行正文含无法按 UTF-8 解码的字节，其余行正文正常
- **WHEN** 以含替换字符的正文条件、忽略大小写过滤
- **THEN** 含非法字节的行按替换字符命中，其余行的判定不受影响

### Requirement: 正文多值与排除

正文条件 SHALL 支持「全部命中」与「任一命中」，可由调用方选择，缺省为全部命中。空词在「任一命中」下 MUST 立即成立，在「全部命中」下 MUST 跳过、不构成否决。排除模式下 MUST 保留未命中的记录。子串模式下条件值为非空词时，空正文视为未命中并在排除模式下保留；条件值为空词时，空正文按空词语义命中，排除模式下按命中剔除。正则模式下空正文按空文本参与求值，不受本子串模式空正文条款约束。

#### Scenario: 任一命中

- **GIVEN** 文档一行正文含 `start`，一行含 `timeout`
- **WHEN** 以 `start` 与 `timeout`、任一命中过滤
- **THEN** 两行均命中

#### Scenario: 全部命中

- **GIVEN** 一行正文同时含 `start` 与 `failed`
- **WHEN** 以 `start` 与 `failed`、全部命中过滤
- **THEN** 该行命中

#### Scenario: 空词在任一命中下立即成立

- **GIVEN** 条件含空词与一个不存在的词，组合方式为任一命中
- **WHEN** 执行过滤
- **THEN** 全部记录命中

#### Scenario: 空词在全部命中下不否决

- **GIVEN** 条件含空词与一个存在的词，组合方式为全部命中
- **WHEN** 执行过滤
- **THEN** 结果与只用该存在的词过滤相同

#### Scenario: 全部为空词的全部命中模式

- **GIVEN** 正文条件只含空词，组合方式为全部命中
- **WHEN** 执行过滤
- **THEN** 全部记录命中

#### Scenario: 空词在任一命中下与排除

- **GIVEN** 文档含正文非空的行，条件含空词与一个不存在的词，组合方式为任一命中，开启排除
- **WHEN** 执行过滤
- **THEN** 结果为空

#### Scenario: 全部为空词的全部命中与排除

- **GIVEN** 文档含任意记录，正文条件只含空词，组合方式为全部命中，开启排除
- **WHEN** 执行过滤
- **THEN** 结果为空

#### Scenario: 排除模式保留未命中记录

- **GIVEN** 文档一行正文含 `start`，一行不含，一行正文为空
- **WHEN** 以 `start`、开启排除过滤
- **THEN** 含 `start` 的行被剔除，其余两行保留

## REMOVED Requirements

### Requirement: 无效条件被拒绝

**Reason**: 该条把「本代正文仅支持子串匹配，以正则模式提交 MUST 被拒绝」与「正则模式被拒」场景钉为契约，正则档落地后二者同时作废；其余参数类拒绝口径与全部场景不变。openspec 的 MODIFIED 会整块替换需求且禁止丢场景（防误删门禁），无法只删其中一条场景，故整条作废并按原内容重建。

**Migration**: 由 ADDED 的「参数类无效条件被拒绝」承接（同名场景逐条保留，仅把「正则模式被拒」替换为「未知正文匹配方式被拒」）；正则自身的不合法内容改由「规模上限」与「非法正则条件被拒绝」两条拒绝。
