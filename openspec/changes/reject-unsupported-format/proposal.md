# Proposal

## Why

调用方（MCP / 自动化脚本）可能把任意二进制文件当日志路径传入；今天这类输入会被解析成一屏垃圾行——自动模式下还会先被转成代理暂存，白付一次全量拷贝。需要在装载之前识别出「这不是日志」，让调用方拿到明确的拒绝而不是垃圾数据。

## What Changes

- **格式判定先于解析**：文件源在解析前判定格式——首部命中 DLT 魔数 `44 4C 54 01` 判为 DLT；文本嗅探判为非文本的判为二进制；其余按日志文本继续。判定早于身份摘要与缓存查找，被拒文件不产出缓存条目。
- **两个判定点，只对实际读得到的副本判**：
  - plan 期（直读打开成功，即自动与显式关闭模式）：同步返回 `UNSUPPORTED_FORMAT`（14），`format` 参数取 `Dlt` 或 `Binary`，不建句柄、不发事件。
  - commit 期（显式开启，或自动模式直开失败转代理后的暂存副本）：发 14 错误事件，句柄进入失败态，不发布任何行。
- **BREAKING**：自动模式的非文本输入不再「转代理」，改为拒绝；显式关闭模式不再无条件直读，非文本同样拒绝。既有前端若依赖「非文本也能打开」需按新错误码处理。
- 显式开启模式的 plan 期不探测原件（该模式的语义就是跳过直读）；采集源不参与判定。

非目标（out of scope）：

- 不做行级格式匹配——CSV、任意 `.txt` 等「文本但不是 logcat」仍按文本解析并产出垃圾行。
- 不做 DLT 解码，不加 `LocalDecode` 渠道、不改列声明；魔数只用于错误标签。
- 不改 C# 桌面 UI：当前 UI 不走 Rust plan，其覆盖随 cabi 接线自动生效；接线前 UI 打开二进制文件仍出垃圾行。
- 不改本地直读的 Reload / 追加载荷；不新增回退开关；不改文本嗅探的控制字符白名单。

## Capabilities

### New Capabilities

（无新增 capability；新行为归属既有 `logcore/source-acquire`。）

### Modified Capabilities

- `logcore/source-acquire`：新增「不支持的格式拒绝」需求；「代理路由三态判定」删除「否则转代理」并为显式关闭补拒绝语义；「文本嗅探规则」适用范围由「自动模式」扩到全部文件源；「失败分类」补一条按阶段分通道的场景。

## Impact

- 代码：Rust core 的 plan / commit 路径、新增格式判定模块、文本嗅探调用点、源获取测试。
- 契约：错误码 14（已存在）首次有生产者；`format` 参数取值 `Dlt` / `Binary`。
- 不受影响：C# 产品代码、sidecar 字节格式、缓存格式、采集链、代理协议。
