# Spec Delta

## ADDED Requirements

### Requirement: 子串条件的规模上限

正文子串条件的单条取值字符数 MUST 有上限（2000 字符），同一正文子串条件的取值条数 MUST 有上限（16 条）。二者取值 SHALL 在实现口径中固定，不因源文件内容与调用方而变。本条对显式 `substring` 与缺省（不传 `mode`）的取值同等适用，只约束子串模式取值的规模，MUST NOT 改变子串匹配本身的作用域、大小写等价、空词与排除语义。

#### Scenario: 单条超长被拒

- **GIVEN** 文件源装载完成
- **WHEN** 以子串模式提交字符数超过上限的正文取值
- **THEN** 按子串无效拒绝并标明原因是长度超限，不产出结果集

#### Scenario: 条数超限被拒

- **GIVEN** 文件源装载完成
- **WHEN** 以子串模式提交超过上限条数的正文取值
- **THEN** 按子串无效拒绝并标明原因是条数超限，不产出结果集

#### Scenario: 边界值不被误伤

- **GIVEN** 文件源装载完成
- **WHEN** 以恰好 16 条、每条恰好 2000 字符的子串条件提交过滤
- **THEN** 正常接受，不触发规模类拒绝

#### Scenario: 上限与正则档互不串档

- **GIVEN** 文件源装载完成
- **WHEN** 以正则模式提交超过 16 条或单条超过 2000 字符的正文条件
- **THEN** 按正则无效拒绝，不按子串无效拒绝（规模闸分档归因）

### Requirement: 超限子串条件被拒绝

正文子串条件超出规模上限（条数超限、长度超限）时 MUST 在开启查询时同步拒绝，MUST NOT 静默降级为更小的条件集、MUST NOT 产出部分结果集、MUST NOT 改变源句柄状态。拒绝 SHALL 使用专用错误码「子串无效（18）」而非参数错误，参数 MUST 只携带语义键：必带原因（条数超限 / 长度超限），能归因到具体某条时附带其序号，MUST NOT 携带文案。

#### Scenario: 长度超限同步返回并定位到单条

- **GIVEN** 文件源装载完成
- **WHEN** 以子串模式提交第二条取值超过长度上限、其余各条合规的正文条件开启查询
- **THEN** 同步返回子串无效、原因为长度超限、序号指向第二条，不产出结果集，句柄仍可正常用于后续查询

#### Scenario: 原因区分条数与长度

- **GIVEN** 文件源装载完成
- **WHEN** 分别以超过条数上限与单条超过长度上限的子串条件开启查询
- **THEN** 两次返回同一错误码，参数中的原因互不相同

#### Scenario: 条数超限不附带序号

- **GIVEN** 文件源装载完成
- **WHEN** 以超过条数上限的子串条件开启查询
- **THEN** 返回原因为条数超限，不附带序号（该拒绝无法归因到单条）

#### Scenario: 超限不降级为截断匹配

- **GIVEN** 文件源装载完成
- **WHEN** 以超过条数上限的子串条件开启查询
- **THEN** 返回子串无效，不返回按前若干条子串匹配的结果集

#### Scenario: 合规规模内空词语义不变

- **GIVEN** 文件源装载完成
- **WHEN** 以合规条数内含空词、无超限的子串条件过滤
- **THEN** 仍按既有空词、全部/任一与排除语义处理，不触发规模类拒绝

#### Scenario: 排除模式不豁免规模上限

- **GIVEN** 文件源装载完成
- **WHEN** 以超过条数上限且开启排除的子串条件开启查询
- **THEN** 仍按子串无效拒绝并标明原因是条数超限，不因开启排除而放行
