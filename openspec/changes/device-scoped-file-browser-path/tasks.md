## 3. 面板层：静默尝试与「最后成功打开的目录」

> 本组验证以**自动化为主**：现有单测已能实例化 `FileBrowserDialog` 并以 `StubDevicePane : DeviceFilePane` 覆盖 `ListAsync`（见 `tests/logcat.Tests/FileBrowserTransferTests.cs`），且面板基类的失败钩子 `OnLoadFailed` 是 `protected virtual`，可由桩覆写以断言「未进入钩子」。仅真正依赖视觉表现的项才留手工。

- [ ] 3.1 面板基类**新增**「尝试打开指定目录」接口（与现有 `NavigateTo` 并存，非替换），且**另起一条独立加载路径、现有 `LoadIntoAsync` 与手动导航完全不动**（design D6）：现有 `LoadIntoAsync`（`Controls/FilePane.cs:361`）在 `await ListAsync` **之前**就 `List.Items.Clear()` + 写「加载中…」+ 显示进度条，失败时再写「加载失败」并调钩子——「先清场后加载」形态无法满足「失败则保持原状态」，新路径须**先列举成功、再一次性提交列表与状态**。尝试某路径时：成功则提交当前目录与列表并触发路径变更事件、返回成功；失败则保持原状态、返回失败，且**不进入加载失败钩子**（不弹消息框、不触发设备端的 run-as 引导分支）、**也不写「加载失败」状态文案**（静默须界面完全无痕，见 3.3）。失败时是否静默由参数决定（起始目录解析用静默模式）。**手动导航（`NavigateTo`）保持现状的「先提交路径、后加载」语义不变**（design D6 的范围限定），失败仍照旧报错且当前目录仍停在用户输入的失败路径。验证：新增自动化用例——以桩面板让指定路径列举失败，断言失败钩子未被调用且面板状态标签无「加载失败」文案（静默路径）、且手动导航路径下钩子被调用（报错路径）；`dotnet test` 口径声明数字。
- [ ] 3.2 面板基类的「加载成功」路径更新「最后成功打开的目录」；手动导航到打不开的路径时该值保持为上一次成功打开的目录。验证：新增自动化用例——先成功打开一个目录、再导航到无效路径，断言「最后成功打开的目录」仍为前者；`dotnet test` 口径声明数字。
- [ ] 3.3 起始目录解析**经由 3.1 的尝试接口**进行，候选链上的失败候选**不产生任何 UI 变化**——当前目录、路径栏、列表状态、**面板状态标签**（`LblStat`）、传输按钮文案均不得在失败候选上出现中间态（静默是界面完全无痕：不弹框 + 不留失败文案，见 spec「静默降级在界面上不留失败痕迹」）。验证：自动化用例——经由失败候选后，断言当前目录与路径栏最终显示成功候选、失败候选期间未提交、面板状态标签无「加载失败」文案；余下纯视觉部分（按钮文案无中间态闪烁）走手工验收。

## 4. 窗体层：按设备记忆的写入与起始目录回落

- [ ] 4.1 文件浏览窗体持有设备标识（新增 `_serial` 字段保存；现有公开构造与 internal 测试构造**均已带 `serial` 参数**、只是没存字段，故**不改构造签名**，见 design D4）；关闭时把「最后成功打开的目录」写入该设备的记忆记录（同一设备重复记录只保留一条并置首）。**不再写任何全局单值字段**（该字段已按 1.4 移除）。**本机侧同源同修**（design D9）：`LastLocalPath` 的写入值同样改取「最后成功打开的目录」而非当前路径，消除「手动输入无效本机路径 → 失败路径被记忆 → 下次开页直接报错」的同型缺陷。**边界**：本次会话一次都没列举成功过（起始目录全部候选失败）时，窗体内没有「最后成功打开的目录」，此时不写任何值、该设备的旧记录保持不变，不得用空串或根目录顶掉。验证：新增测试覆盖记忆写入目标的正确性（写入的是记录集合而非全局字段）、以及本机侧写入取「最后成功打开的目录」，`dotnet test` 口径声明数字；手工验收——关闭文件浏览页后检查设置文件，确认记忆集合新增该设备条目。
- [ ] 4.2 文件浏览窗体打开时按第 2 组的纯逻辑解析起始目录：构造候选链、逐级静默尝试、采用首个成功者；全部候选失败时按目录不可访问的既有方式报错。构造签名中「设备端起始目录」参数移除（改由窗体内部按设备解析），本机侧起始目录参数保留。验证：手工验收——在无记忆记录的设备上打开，落在设备可写存储根目录；记忆目录被删后打开，静默落到下一级候选且不弹框。
- [ ] 4.3 设备操作窗口侧适配构造签名变更，设备端起始目录不再由外部传入（`CreatePage` 相应简化）；核对「先关闭旧页签（写旧设备记录）后重建新页签（读新设备记录）」的既有顺序未被破坏。验证：手工验收——在设备甲浏览到某目录后切到设备乙再切回甲，甲的起始目录仍是甲自己的目录，乙的起始目录不是甲的目录。
