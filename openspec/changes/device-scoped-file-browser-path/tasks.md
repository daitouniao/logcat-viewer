## 3. 面板层：静默尝试、「用户最后导航目录」与加载中占位

> 本组验证以**自动化为主**：现有单测已能实例化 `FileBrowserDialog` 并以 `StubDevicePane : DeviceFilePane` 覆盖 `ListAsync`（见 `tests/logcat.Tests/FileBrowserTransferTests.cs`），且面板基类的失败钩子 `OnLoadFailed` 是 `protected virtual`，可由桩覆写以断言「未进入钩子」。仅真正依赖视觉表现的项才留手工。

- [ ] 3.1 面板基类**新增**「尝试打开指定目录」接口（与现有 `NavigateTo` 并存，非替换），且**另起一条独立加载路径、现有 `LoadIntoAsync` 与手动导航完全不动**（design D6）：现有 `LoadIntoAsync`（`Controls/FilePane.cs:361`）在 `await ListAsync` **之前**就 `List.Items.Clear()` + 写「加载中…」+ 显示进度条，失败时再写「加载失败」并调钩子——「先清场后加载」形态无法满足「失败则保持原状态」，新路径须**先列举成功、再一次性提交列表与状态**。接口须支持**两种失败模式**：静默模式（失败不进入失败钩子、不弹消息框、不触发设备端的 run-as 引导分支、**不写「加载失败」状态文案**，且不改动路径栏与列表）与报错模式（失败走既有失败钩子，与手动导航失败同一路径与文案）。**手动导航（`NavigateTo`）保持现状的「先提交路径、后加载」语义不变**（design D6 的范围限定），失败仍照旧报错且当前目录仍停在用户输入的失败路径，且**不经本接口**。尝试路径**复用面板既有 `_cts` 取消链**（design D4 竞态约束）：用户导航与关窗都会取消进行中的尝试，尝试循环须区分「已取消」与「候选失败」（取消时中止整个解析，不得当成失败去试下一个候选），提交前再校验一次取消状态；成功提交的内容与 `NavigateTo` 的提交面一致（当前目录、路径栏、收藏高亮、列表、状态、路径变更事件）。验证：新增自动化用例——以桩面板让指定路径列举失败，断言静默模式下失败钩子未被调用、状态标签无「加载失败」文案、路径栏与列表未被触碰；报错模式下钩子被调用；`dotnet test` 口径声明数字。
- [ ] 3.2 面板基类新增「用户最后导航目录」跟踪，**按来源区分更新**（design D9）：用户主动导航（手动输入路径 / 双击目录 / 点上级 / 收藏跳转）成功列举后更新为该目录；手动导航到打不开的路径时该值保持为上一次成功导航的目录。**起始目录解析（含降级到下一级候选）的成功结果不更新该值**——它走 3.1 的独立路径，与用户导航路径分开。**该值须能表达「从未导航过」**：用无值表示从未手动导航成功，与「导航到了本机驱动器列表」对应的空串区分开。验证：新增自动化用例——先成功手动导航一个目录、再导航到无效路径，断言该值仍为前者；再经由 3.1 的尝试接口成功打开另一目录，断言该值**不变**；`dotnet test` 口径声明数字。
- [ ] 3.3 起始目录解析**经由 3.1 的尝试接口**进行，候选链上的失败候选**不产生任何 UI 变化**——当前目录、路径栏、列表状态均不得在失败候选上出现中间态；**面板状态标签**（`LblStat`）在解析期间显示「加载中…」占位（该文案是 `LocTable.Common.cs` 已有的资源键，**不新增 i18n 键**），解析完成后由结果取代（成功为「{N} 项」、失败候选期间保持「加载中…」不变），成功候选落地后不得残留失败文案（静默是界面完全无痕，见 spec「静默降级在界面上不留失败痕迹」）。传输按钮文案在失败候选上不得出现中间态。验证：自动化用例——经由失败候选后，断言当前目录与路径栏最终显示成功候选、失败候选期间未提交、面板状态标签无「加载失败」文案；余下纯视觉部分（按钮文案无中间态闪烁、「加载中…」占位的显示时机）走手工验收。

## 4. 窗体层：按设备记忆的写入与两侧起始目录回落

- [ ] 4.1 文件浏览窗体持有设备标识（新增 `_serial` 字段保存；现有公开构造与 internal 测试构造**均已带 `serial` 参数**、只是没存字段，故**不改构造签名以存序列号**，见 design D4）；关闭时把「用户最后导航目录」写入该设备的记忆记录（同一设备重复记录只保留一条并置首）。**写入条件**：仅当本次会话发生过手动导航成功（即 3.2 的值存在）才写；**未发生导航时不写任何值、该设备的旧记录保持不变**，不得用空串或根目录顶掉。**降级结果不写回**（design D9）：起始目录解析降到 `/sdcard` 不影响该设备既有记忆。**不再写任何全局单值字段**（该字段已按 1.4 移除）。**本机侧同源同修**（design D9/D11）：`LastLocalPath` 的写入值同样改取「用户最后导航目录」而非当前路径，消除「手动输入无效本机路径 → 失败路径被记忆 → 下次开页直接报错」的同型缺陷；本机侧该值为空串（导航到了本机驱动器列表）时按既有习惯**不写**，保留旧值。验证：新增测试覆盖记忆写入目标的正确性（写入的是记录集合而非全局字段）、**降级不覆盖既有记录**、**未导航不写回**，以及本机侧写入取「用户最后导航目录」；`dotnet test` 口径声明数字；手工验收——关闭文件浏览页后检查设置文件，确认记忆集合新增该设备条目。
- [ ] 4.2 文件浏览窗体打开时按第 2 组的纯逻辑解析**两侧**起始目录：构造各自候选链、逐级静默尝试、采用首个成功者。**设备侧**（device panel）按「本设备记忆目录 → 设备可写存储根目录」，**本机侧**（local panel）按「本机记忆目录 → 本机驱动器列表」。全部候选失败时以末位候选走 3.1 的报错模式，按目录不可访问的既有方式报错。**解析结果不得覆盖用户已发生的导航**（design D4 竞态约束）：提交前校验取消状态，用户已手动导航则丢弃解析结果、保留用户当前状态。构造签名中「设备端起始目录」与「本机端起始目录」两个参数**均移除**（改由窗体内部按各自记忆解析），本机侧参数一并移除是为避免「外部注入 + 窗体内部解析」双来源（design D5）。验证：手工验收——在无记忆记录的设备上打开，落在设备可写存储根目录；记忆目录被删后打开，静默落到下一级候选且不弹框；本机侧记忆目录被删后打开，静默落到本机驱动器列表且不弹框。
- [ ] 4.3 设备操作窗口侧适配构造签名变更，起始目录不再由外部传入（`CreatePage` 相应简化）；核对「先关闭旧页签（写旧设备记录）后重建新页签（读新设备记录）」的既有顺序未被破坏。验证：手工验收——在设备甲浏览到某目录后切到设备乙再切回甲，甲的起始目录仍是甲自己的目录，乙的起始目录不是甲的目录。
