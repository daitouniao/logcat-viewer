# Tasks

## 1. 设置层：按设备记忆目录的存取

- [ ] 1.1 新增按设备记忆目录的模型（设备标识 + 目录路径）与设置项集合（最近在前），并提供三个操作：按设备查询记忆目录、记录某设备的目录（记录时把该设备原有条目移到最前）、集合超上限时从尾部淘汰最久未用者（上限 16）。验证：新增 `AppSettingsTests` 用例覆盖「同设备重复记录只留一条且置首」「超过 16 条时最旧的被淘汰」「查不到返回空」，tstrun 口径跑 `AppSettingsTests` 全过并声明数字。
- [ ] 1.2 记忆集合的反序列化容错：旧配置文件缺少该字段时得空集合（不得抛异常），显式 null 字段同样得空集合。验证：新增 `AppSettingsTests` 用例，分别以「完全无该键的旧配置」与「该键显式为 null 的配置」构造临时文件加载，断言集合为空且后续记录操作正常；tstrun 口径声明数字。
- [ ] 1.3 记忆集合的持久化往返：写入某设备的目录后落盘再读回，该条仍在首位。验证：新增 `AppSettingsTests` 用例（临时文件 + `SaveTo` + `LoadFrom`），断言读回后首条为该设备与目录；tstrun 口径声明数字。

## 2. 起始目录解析的纯逻辑（不依赖 WinForms）

- [ ] 2.1 起始目录候选链构造：按「本设备记忆目录 → 全局兜底目录 → 设备可写存储根目录」产出有序去重的候选序列；本设备无记忆记录时序列以全局兜底目录起头；全局兜底目录为空或与存储根目录相同时不产生重复项。验证：新增测试类覆盖三种组合（有记忆 / 无记忆有兜底 / 无记忆无兜底）并断言序列顺序与去重，tstrun 口径跑该类全过并声明数字。
- [ ] 2.2 首个可用候选的选取：接受「尝试打开某路径并返回成败」的委托，依次尝试候选并返回首个成功者；全部失败时返回无结果；委托不被传入多余调用（成功即停）。验证：新增测试类，用可控委托覆盖「第一个就成功」「前两个失败第三个成功」「全部失败」三种情形，断言返回结果与委托调用次数，tstrun 口径跑该类全过并声明数字。

## 3. 面板层：静默尝试与「最后成功打开的目录」

- [ ] 3.1 面板基类增加「尝试打开指定目录」的能力：列举成功则返回成功，不改变当前目录与列表状态；列举失败则返回失败，**不进入加载失败钩子**（不弹消息框、不触发设备端的 run-as 引导分支）。手动导航路径的行为保持不变（失败仍照旧报错）。验证：手工验收——在文件浏览页手动输入一个不存在的路径，确认仍弹出原有错误提示；起始目录解析路径不弹框（由第 5 组的集成验收覆盖）。
- [ ] 3.2 面板基类的「加载成功」路径更新「最后成功打开的目录」；手动导航到打不开的路径时该值保持为上一次成功打开的目录。验证：手工验收——手动打开一个有效目录后输入一个无效路径，界面提示失败后关闭文件浏览页，再打开时起始目录仍是那个有效目录（与第 1 组的记录写入联动）。
- [ ] 3.3 面板基类的导航入口改为「列举成功后再提交当前目录、路径栏与列表状态」，避免逐级尝试过程中路径栏与传输按钮文案在失败候选上闪动。验证：手工验收——起始目录解析经过失败候选时，路径栏与底部传输按钮文案不出现中间态闪烁，最终显示成功候选。

## 4. 窗体层：按设备记忆的写入与起始目录回落

- [ ] 4.1 文件浏览窗体持有设备标识；关闭时把「最后成功打开的目录」写入该设备的记忆记录（同一设备重复记录只保留一条并置首），并停止再写全局兜底字段（该字段保留为稳定兜底取值）。验证：新增测试覆盖记忆写入目标的正确性（写入的是记录集合而非全局字段），tstrun 口径声明数字；手工验收——关闭文件浏览页后检查设置文件，确认记忆集合新增该设备条目、全局兜底字段取值未变。
- [ ] 4.2 文件浏览窗体打开时按第 2 组的纯逻辑解析起始目录：构造候选链、逐级静默尝试、采用首个成功者；全部候选失败时按目录不可访问的既有方式报错。构造签名中「设备端起始目录」参数移除（改由窗体内部按设备解析），本机侧起始目录参数保留。验证：手工验收——在无记忆记录的设备上打开，落在全局兜底或存储根目录；记忆目录被删后打开，静默落到下一级候选且不弹框。
- [ ] 4.3 设备操作窗口侧适配构造签名变更，设备端起始目录不再由外部传入；核对「先关闭旧页签（写旧设备记录）后重建新页签（读新设备记录）」的既有顺序未被破坏。验证：手工验收——在设备甲浏览到某目录后切到设备乙再切回甲，甲的起始目录仍是甲自己的目录，乙的起始目录不是甲的目录。
