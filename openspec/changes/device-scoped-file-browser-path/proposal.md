# Proposal

## Why

文件浏览页的起始目录记在**一个全局单值**里（`AppSettings.LastRemotePath`），所有设备共用。切换设备时，设备操作窗口会重建文件浏览页签，新页签读到的正是上一台设备留下的目录——A 机（已 root）停在 `/data/local/tmp`，切到无 root 的 B 机就落在同一路径，直接弹权限不足提示。这不是偏好问题而是行为错误：用户看到的起始目录属于另一台设备。

修法是把「上次目录」从全局单值改为按设备分别记忆，未记录的设备回落到 `/sdcard`。

## What Changes

- **新增**：按设备（设备序列号）分别记忆的文件浏览起始目录。记录条数上限 16，超出淘汰最久未用者。
- **修改**：文件浏览页打开时的起始目录解析顺序改为「本设备记忆目录 → `/sdcard`」两级，并逐级尝试打开。
- **修改**：起始目录打开失败时**静默**改用下一级候选目录，不弹提示、也不在面板状态标签留下失败文案（静默是界面完全无痕）；仅当全部候选都无法打开时才按原有方式报错。
- **修改**：**本机侧与设备侧对称**——本机侧起始目录同样建立「记忆目录 → 本机驱动器列表」两级回落，记忆目录失效时静默降级，不弹框。
- **修改**：**记忆记录只来自用户在文件浏览页的手动导航成功**。起始目录解析的结果（含降级到下一级候选的结果）**不写回**记忆——否则一次降级就会把设备在另一身份模式下记住的目录冲掉（root 下记住的 `/data/local/tmp` 会被普通身份的降级结果 `/sdcard` 覆盖，切回 root 也回不去了）。
- **修改**：起始目录解析期间面板状态标签显示「加载中…」占位（解析设备端目录需往返 adb shell，可能耗时数百毫秒至数秒；完全无反馈会让用户以为界面卡死）。该提示在解析完成后被结果取代，失败候选不留失败文案。
- **BREAKING（行为变化）**：切换设备后文件浏览页不再继承上一台设备的目录；每台设备首次打开时从 `/sdcard` 开始。
- **删除**：`AppSettings.LastRemotePath`（全局单值字段）整体移除——新功能不再读写它。该字段承载的正是「跨设备继承上一台设备目录」的串味源，保留它（哪怕冻结为只读）仍会在「本设备无记忆记录」时把别的设备的目录当兜底候选。删除后回落链只有两级，不存在任何跨设备共享的目录候选。
  - **旧配置平滑**：字段移除后，旧 `settings.json` 里的同名键在**下次保存时自然消失**（该字段不再参与序列化，无需迁移代码）；反序列化时旧键被忽略、不抛异常。

### 非目标（out of scope）

- 不做「每设备多条历史目录列表」——只记一个，多条历史的 UI 出口（收藏下拉）不在本次范围。
- **本机侧目录记忆不按设备拆分**：`LastLocalPath` 继续全局共享（本机目录与设备无关）。但**写入值取「用户最后一次手动导航成功的目录」而非当前路径**——修掉与设备侧同型的缺陷（手动输入无效本机路径 → 失败路径被记忆 → 下次开页直接报错）；**读取侧**也补上与设备侧对称的静默降级（记忆目录失效 → 静默回到本机驱动器列表）。
- 不改收藏目录机制：收藏仍是设备端/本机端各一份全局列表，不按设备拆分。
- 不改 run-as 包名记忆、APK 路径记忆等其他既有记忆项。
- 不引入新依赖，不改 csproj。
- 不新增任何「跨设备共享的目录」设置入口：全局单值字段直接移除，不以新名字另起一个同类字段——换了名字仍是全局单值，仍会在「本设备无记忆记录」时把别的设备的目录当候选。
- **不改手动导航的提交语义**：手动导航（输入路径/双击目录/点上级）保持现状的「先提交路径、后加载」，失败仍照旧报错且当前目录仍停在用户输入的失败路径（design D6 的范围限定）。本 change 只改起始目录解析这条路径。
- **不改本机侧候选链的末位选择**：末位取本机驱动器列表而非桌面目录（既有 `LastLocalPath ?? DesktopDirectory` 的 `??` 从未生效，现状真实行为就是本机驱动器列表，且它永远可列举）。

## Capabilities

### New Capabilities

- `file-browser`: 设备文件浏览页的起始目录契约——按设备分别记忆的目录、起始目录的两级回落顺序、记忆目录失效时的静默降级行为。

### Modified Capabilities

（无。`fileproxy` 能力不受影响；文件浏览此前无 spec 契约，本 change 以新能力确立变更后契约。）

## Impact

- **代码**：`Services/AppSettings.cs`（新增按设备目录记录集合 + 记录/查询/淘汰方法；**移除 `LastRemotePath` 字段**）、`Forms/FileBrowserDialog.cs`（新增 `_serial` 字段持有设备序列号、两侧起始目录两级回落；**不再写全局单值字段**；公开构造函数移除「设备端起始目录」与「本机端起始目录」两个参数）、`Forms/DeviceOpsDialog.cs`（构造调用简化）、`Controls/FilePane.cs`（面板基类：新增「尝试打开指定目录」能力与静默失败模式，**另起独立加载路径、现有 `LoadIntoAsync` 不动**；新增「用户最后导航目录」跟踪，按来源区分更新）、`Controls/DeviceFilePane.cs`（设备端失败钩子含 run-as 引导分支，静默降级不得进入该分支）。
- **测试**：`AppSettingsTests`（记录/查询/上限淘汰/JSON 缺字段与显式 null 两态；**旧配置含 `LastRemotePath` 键时反序列化不抛异常、保存后该键消失**）、`StorePersistenceTests`（持久化往返；**移除 `LastRemotePath` 相关断言**）、`ModelTests`（**移除 `LastRemotePath` 默认值断言**）；新增起始目录解析的纯逻辑测试（设备侧与本机侧候选链各一组）。
- **文档**：无入库文档同步——`docs/FEATURES.md` 已停用不再维护、实施跟踪表已停用删除；验收结论登记在本 change 的 `tasks.md`。
- **无新增依赖**，csproj 不动。**移除三处公开契约**：`AppSettings.LastRemotePath` 属性（属性删除）、`FileBrowserDialog` 公开构造函数的「设备端起始目录」参数、`FileBrowserDialog` 公开构造函数的「本机端起始目录」参数（两参数均删除，唯一调用点 `DeviceOpsDialog.CreatePage` 随之简化）。其余新增成员均为追加。
