# Proposal

## Why

文件浏览页的起始目录记在**一个全局单值**里（`AppSettings.LastRemotePath`），所有设备共用。切换设备时，设备操作窗口会重建文件浏览页签，新页签读到的正是上一台设备留下的目录——A 机（已 root）停在 `/data/local/tmp`，切到无 root 的 B 机就落在同一路径，直接弹权限不足提示。这不是偏好问题而是行为错误：用户看到的起始目录属于另一台设备。

修法是把「上次目录」从全局单值改为按设备分别记忆，未记录的设备回落到 `/sdcard`。

## What Changes

- **新增**：按设备（设备序列号）分别记忆的文件浏览起始目录。记录条数上限 16，超出淘汰最久未用者。
- **修改**：文件浏览页打开时的起始目录解析顺序改为「本设备记忆目录 → 全局兜底目录 → `/sdcard`」，且逐级尝试打开。
- **修改**：起始目录打开失败时**静默**改用下一级候选目录，不弹提示；仅当全部候选都无法打开时才按原有方式报错。
- **BREAKING（行为变化）**：切换设备后文件浏览页不再继承上一台设备的目录；每台设备首次打开时从 `/sdcard` 开始。
- **保留（不删）**：全局兜底目录字段继续存在并继续被写入，作为旧配置升级后的平滑过渡与兜底底座。

### 非目标（out of scope）

- 不做「每设备多条历史目录列表」——只记一个，多条历史的 UI 出口（收藏下拉）不在本次范围。
- 不改本机侧目录记忆：`LastLocalPath` 继续全局共享（本机目录与设备无关）。
- 不改收藏目录机制：收藏仍是设备端/本机端各一份全局列表，不按设备拆分。
- 不改 run-as 包名记忆、APK 路径记忆等其他既有记忆项。
- 不引入新依赖，不改 csproj。

## Capabilities

### New Capabilities

- `file-browser`: 设备文件浏览页的起始目录契约——按设备分别记忆的目录、起始目录的多级回落顺序、记忆目录失效时的静默降级行为。

### Modified Capabilities

（无。`fileproxy` 能力不受影响；文件浏览此前无 spec 契约，本 change 以新能力确立变更后契约。）

## Impact

- **代码**：`Services/AppSettings.cs`（新增按设备目录记录集合 + 记录/查询/淘汰方法）、`Forms/FileBrowserDialog.cs`（持有设备序列号、起始目录多级回落）、`Forms/DeviceOpsDialog.cs`（起始目录改为按设备解析）、`Controls/FilePane.cs`（起始目录打开失败可静默降级，不弹错误框）。
- **测试**：`AppSettingsTests`（记录/查询/上限淘汰/JSON 缺字段与显式 null 两态）、`StorePersistenceTests`（持久化往返）；新增起始目录解析的纯逻辑测试。
- **文档**：`docs/FEATURES.md`（文件浏览起始目录条目）、`docs/IMPLEMENTATION-TRACKER.md`（状态同步）。
- **无新增依赖**，csproj 不动；无公开 API 移除（新增成员均为追加）。
