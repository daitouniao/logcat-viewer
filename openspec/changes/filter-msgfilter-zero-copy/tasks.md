## 1. 零拷贝读取能力（文档层）

- [ ] 1.1 开启主工程的不安全代码编译（`logcat.csproj` 加 `AllowUnsafeBlocks`），确认现有代码零警告构建通过。验证：`dotnet build logcat.csproj` 成功且无新增警告（注意 csproj 内 `SelfContained` 禁令不涉及此项）。
- [ ] 1.2 在文档层实现零拷贝正文读取：一个可获取的读取会话，**复用文档已有的 `_view`**（`MemoryMappedViewAccessor`）的 `SafeMemoryMappedViewHandle`，用 `AcquirePointer` 取指针；会话提供**回调式取正文**（正文 span 只在回调执行期间有效，调用方无法把它带出作用域），正文边界取 `行首偏移 + 消息偏移` 与 `行长度 - 消息偏移`（与现有 `MessageBytes` 的边界计算逐字一致），会话释放时 `ReleasePointer`（幂等）。**不可自持独立映射**：另开映射的 `Capacity` 冻结于创建时刻，文件增长后读新追加行即越界 → 进程段错误（实测 exit 139），实时采集路径必踩。验证：新增测试类 `LogDocumentZeroCopyTests`，用例 `ZeroCopy_正文边界与MessageBytes逐字节一致`（同一行分别用两条路径取值，断言字节序列相等）与 `ZeroCopy_会话释放后可重新获取`（释放后再次获取不抛异常）。
- [ ] 1.3 读取会话的健壮性边界：行号为负、超出行数、消息偏移大于等于行长（无正文）三种输入都返回空片段而非越界；**构造 span 前校验「偏移 + 长度 ≤ 当前映射容量」**（容量随 `Append` 重映射，越界读是段错误而非托管异常）；回调取到的 span 不得逸出回调作用域（形态上以 `ReadOnlySpan<byte>` 回调参数保证）。验证：新增用例 `ZeroCopy_越界行号返回空`、`ZeroCopy_无正文行返回空`、`ZeroCopy_超出映射容量返回空`，`dotnet test` 口径跑 `LogDocumentZeroCopyTests` 全过并声明数字。

## 2. 过滤引擎改为零拷贝消费

- [ ] 2.1 段 2 的大小写敏感路径改为零拷贝：直接用行正文片段做字节查找，替换现状「每行 `new byte[]` + `ReadArray` 拷贝」。区分大小写时按原始字节精确比较（与现状一致）。验证：现有用例 `按message子串过滤`、`message过滤只看正文_不碰tag与头部`、`message过滤能命中多行记录的续行内容` 全绿；新增用例 `MsgFilter_区分大小写_零拷贝后命中集合不变`（与改造前的逐行命中集合对比）。
- [ ] 2.2 段 2 的大小写不敏感路径改为「按行分派」：行内全部字节 < 0x80 走字节级比较路径；行内含 ≥ 0x80 字节走整行 Unicode 小写化路径（与现状的 `FoldLowerAsciiInPlace` 判定同界）。needle 侧仍按 `ToLowerInvariant` 预编码。**needle 侧同样要分派**：needle 含 ≥ 0x80 字节时不能走字节路径（ASCII 行不可能命中它）→ 判为不命中；needle 首字节为数字/标点时大小写两种形态退化为一种。**不可采用「两侧 OR 0x20 比较」**：实测 OR 0x20 会把 `@` 与 `` ` ``、`[` 与 `{` 判为相等，与现状「只折 A–Z」不等价。验证：现有 Unicode 语义用例全绿 —— `message忽略大小写_纯ASCII双向对称`、`message忽略大小写_重音不与非重音等价`、`message忽略大小写_德语eszett大小写等价`、`message忽略大小写_土耳其无点i不等于ASCII_I`、`message忽略大小写_中文term正常匹配`、`tag忽略大小写与message行为一致`；新增用例 `MsgFilter_非ASCII行走Unicode路径`（构造含 `ß` 与 `ẞ` 的行，断言与改造前一致的命中行号）。

## 3. 匹配算法：候选首字节定位 + 逐字节验证
