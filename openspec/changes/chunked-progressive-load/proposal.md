# Proposal

## Why

大文件加载现状为整份构建：1 GB / 1,580 万行样本首屏延迟约 12.5 s（首屏 = 全量，构建期间无任何行可看），内存峰值约 3.6 GB。分块探针实测（`openspec/notes/CHUNKED-PROGRESSIVE-LOAD.md` §4）：分块读入 + 分块解析 + 渐进发布下首屏 212 ms、内存峰值 663 MB，且与整份构建逐元素零差异（4/16/64 MB 三种块长均验证）。既有积压方向（重启卡 B1）与本轮探索结论一致，趁解析原语（区间扫描、跨块续行合并、增量并入、尾部追加、增量过滤）均已在主工程落地，把这条路落成正式行为。

## What Changes

- 本地文件加载改为「分块读入 + 分块解析 + 渐进发布」流式管线：首块小块抢首屏，稳态放大块长提吞吐（自适应两段式）。
- 加载期文档增量并入既有文档：跨块续行经 carry 语义合并；末条记录滞后一条发布，保证已发布前缀字节不再变化。
- 加载期 UI 可用性：过滤器与时间过滤随发布增量生效；导出与崩溃面板置灰至加载完成。
- 加载期含 Message 关键词的过滤走**增量块扫描**（按已发布前缀的增量区间轮），结论与全量过滤一致，加载完成后无需全量重过滤。
- 取消加载语义为整份清空、回到空文档状态。
- 视图行号数组改为可增量追加结构，消除小块长下逐块整表拷贝的 O(n²) 开销。
- 小文件统一走同一条流式管线（单块即整份，无独立路径）。
- 代理路径行为不变：先 spool 后加载，spool 完成的本地文件走同一条流式管线；代理路径边 spool 边解析本期不做。

## Capabilities

### New Capabilities

- `chunked-file-load`: 本地日志文件的分块读入、分块解析、渐进发布与加载期行为——首屏时延、发布语义（滞后一条、前缀稳定）、加载期过滤/取消/进度、与整份加载的等价性、验收线。

### Modified Capabilities

（无——Message 过滤的增量块扫描是过滤内部路径扩展，spec 级「不同扫描路径结论一致」的既有需求继续覆盖新路径，不产生需求变更。）

## Impact

- `Services/LogDocument.cs`：加载编排改为区间扫描 + 增量并入（复用既有 `ScanRange` / carry / `Append` 原语）。
- `Services/FilterEngine.cs`：块扫描主流程拆出「可指定字节区间的增量一轮」形态，供加载期过滤复用。
- `Controls/LogListView.cs`：视图行号模型由整表替换改为可增量追加，`AppendRows` 等访问点一并调整。
- `frmMain.cs`：加载编排、加载期控件置灰、取消清空、进度状态。
- `docs/TESTING.md`：用例数变化按口径联动更新；等价性不变量进 CI 断言。
- 代理路径（`fileproxy`）无行为变化。
