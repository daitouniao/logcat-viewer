# Design

## Context

大文件加载现状为整份构建路径：`DoBuild` 一次 `ScanRange(0, Size)` 扫完整个文件（多分片合并形态已随旧分块方案删除，只有单分片一种）。join 机制已由 change `remove-join-merge` 删除，索引口径为**自然行**（空行与横幅行不索引，每物理行一条记录，约 +11.3% 记录数）：

- `ScanRange` 为区间语义（行首落在本区间才计数），`ScanPart` 为纯列批次（`Offs` / `Lens` / `Moff` / `Minutes` / `Pids` / `Tids` / `Lvls` / `TagIds` + 崩溃事件 + 局部 tag 字典），无 carry 字段；
- `Reload` → `Append(newSize)` 为文件增长路径：`TrimPartial` 把边界裁到最后换行符（不完整行留待下次），tag 重映射后拼列；头部变化则整体重建；
- 全量 Message 过滤的块扫描（`MsgFilterBlockScan`，并行 SIMD）已由 change `filter-msgfilter-block-scan` 实现并归档（2026-10-30）于 master；message 匹配作用域为物理行；
- 增量过滤 `FilterTail` 为逐条增量形态；视图尾部追加 `LogListView.AppendRows`；增量上屏编排 `frmMain.ApplyIncremental`。

分块探针实测（`openspec/notes/CHUNKED-PROGRESSIVE-LOAD.md` §4，**join 口径**）：分块读入 + 分块解析 + 渐进发布下首屏 212 ms、内存峰值 663 MB，与整份构建逐元素零差异（4/16/64 MB 三种块长均验证）。自然行口径的数字以实施前复测为准（见决策 10）。本设计不重复笔记数据。

## Goals / Non-Goals

**Goals:**

- 本地文件（含代理 spool 完成后的本地文件）统一走分块流式管线，达成 specs 的首屏、等价性、内存、取消验收线。
- `Build` 与 `Reload` 增长路径统一进同一条流式管线（兑现 `remove-join-merge` 留下的口子）。
- 加载期 Message 关键词过滤走增量块扫描（C′），不发生「加载期比加载完成后更慢」的体感倒退。
- 加载期已发布前缀字节稳定，作为增量过滤正确性基础。

**Non-Goals:**

- 代理路径边 spool 边解析（D5=A，后续另行立项）。
- 流式加载的总时长优化（分块买首屏与内存；总时长验收线为不劣于现状 5%）。
- 修改 `message-filter` 的 spec 级行为（增量块扫描是内部路径扩展，既有「不同扫描路径结论一致」需求继续覆盖）。
- 重新引入续行合并（join 已删，索引为自然行，不做任何形式的跨行合并）。

## Decisions

1. **管线形态：分块读入 → 区间扫描 → 增量并入 → 逐块发布**。加载循环 = 读一块（边界裁到最后换行符）→ `ScanRange` 解析该区间 → 增量并入既有列（tag 重映射、崩溃事件行号偏移）→ 发布新完成记录。小文件单块即整份，无独立路径。自然行口径下记录互不延伸，无需任何跨块续行处理。理由：解析与追加原语均为既有形态，探针已证逐元素零差异；不发明新模式。

2. **块长：自适应两段式，首块 4 MB、稳态 32 MB**（D2）。理由：首块 4 MB 实测 212 ms 出首屏（join 口径）；D10 落地后视图拼接 O(n²) 解除，块长不再被 UI 拷贝绑架，稳态取较大块降块数与过滤轮次开销。32 MB 为可调参数，默认值以内存（≤1.0 GB）与首屏不回退为约束，**以自然行口径探针复测结果定稿**（见决策 10）。

3. **前缀稳定：块末换行对齐，无滞后发布**（原 D3=A 作废）。每块发布前把字节末尾裁到最后一个换行符（复用 `TrimPartial` 思路），只发布完整物理行；不完整行留待下一块并入后发布。自然行口径下记录互不延伸，「已发布前缀内容不再变化」由此天然成立——原「末条滞后一条发布 + EOF 补发」机制的前提（续行延长末条）已随 join 删除而消失，不再保留。备选「保留滞后一条作双保险」否决：无延长场景，纯属冗余机制。

4. **加载期 Message 过滤：C′ 增量块扫描**（D9）。把 `MsgFilterBlockScan` 的「全文档一轮」拆为三个阶段：
   - **会话**：按当前 RowCount 分配（或复用）`counts` / `nonAscii` 累计数组；
   - **区间轮**：给定字节区间 `[from, to)`，只扫该区间（`from` = 上轮扫描末尾，`to` = 本轮末条记录末尾，扫描起点前移 `overlap = 最长词 - 1` 防跨轮边界漏配）；归属逻辑复用现有扫描体（只计行首落在新区间的记录）；
   - **行段判定**：`VerdictPass` 只对本轮新增候选行跑，产出本批命中行号供 `FilterTail` 现有增量上屏路径消费。
   调度：每发布一块跑一轮（块内 SIMD 对稳态块长为毫秒级/词）。加载中途修改过滤条件：对已发布前缀走既有全量路径（`BlockScanEligible` 满足即块扫描），随后继续增量轮。
   不可扫形态（非 ASCII 词、超词数上限、小文档）沿用既有三条件分派，回退逐条增量（`FilterTail` 现状），行为仍正确。message 匹配作用域为物理行正文（`remove-join-merge` 后口径）。
   理由：分派逻辑已在 master，C′ 落点是该函数的形状拆分；备选 B（逐条 + 完成后重过滤）的重过滤语义冗余（两路径结论一致，重过滤无消费方）且逐条总量 ≈ 19 s 摊在加载期仍是最慢段，降级为兜底；A（加载期不支持 Message 过滤）牺牲可过滤性，仅作 raw 视图依赖不可行时的回退。

5. **raw 视图：加载期保持整文件映射**（D9 硬前提的落法）。分块管线不改变文档映射的生命周期——映射在加载期即存在，`OpenMessageSession` 照常提供基指针，块扫描增量轮直接复用；不为块扫描新造「自有缓冲区」形态。理由：优先复用既有模式；**需先核实**现状文档的映射是否在解析开始前就绪（见风险 1），若不成立再评估加载期建映射的成本。

6. **视图行号数组：分段可增量追加结构**（D10=B）。`_rows` 从「整表替换数组」改为分段块数组 + 段索引，覆盖 `SetRows` / `AppendRows` / `CaptureAnchor` / `PinAnchor` / `NearestModelRow` / `DocRow` / `ModelRowOf` 全部访问点。理由：4 MB 块长下整表拷贝已占 9%、1 MB 达 26%，为迁就不改 UI 而被迫用大块会把首屏从 212 ms 劣化到 539 ms，不划算；O(n²) 实测成立，必须根治。

7. **取消：整份清空**（D4=B）。沿用既有 worker 换代取消机制（`StopWorker` / `_workerGen`），分块管线在任意块边界检查取消；清空文档与视图回到空状态。理由：部分保留会引入「半份文档」的一致性问题（tag 重映射、崩溃事件、统计），清空语义最简单且可验证。

8. **加载期 UI**（D6=A / D11=A）：过滤器与时间过滤随发布增量生效；导出与崩溃面板置灰至完成；进度状态记录「已发布到第几块」。视图跟随沿用既有开关，不改语义。发布上屏按时间片节流（约 100 ms 聚合一批），避免高频 UI 抖动——块耗时 p95 在 16 MB 块下达 254 ms（join 口径），逐块上屏会造成锯齿。

9. **存量私有设计处置**（D7=A）：以公开探索笔记为事实基座，不读、不引私有文档。

10. **探针复测前置 + Build/Reload 路径统一**。两件事均随 join 删除产生：
    - **探针复测**（实施前置任务）：旧探针数字为 join 口径，自然行口径下记录数 +11.3%，首屏 / 内存 / 总时长均可能漂移。实施前按自然行口径重跑分块探针（首屏、内存峰值、总时长、逐元素等价性），结果回填决策 2 的默认块长与 spec 验收线基数。
    - **路径统一**：`Reload` 保留头部一致性检查（头部变化 → 整体重建），增长部分改为交给分块管线从 `IndexedSize` 起续扫——与首次加载同一条循环，不再维护独立的 `Append` 拼列代码。外部行为不变，spec 不加需求。

## Risks / Trade-offs

- [文档映射在加载期是否已就绪未核实——若现状是解析完成后才建映射，C′ 无指针可用] → 实施首任务先写探针/测试核实映射生命周期；不成立则评估加载期提前建映射（文件已打开，成本低），仍不可行则按决策 4 的回退链降级（增量逐条 → A）。
- [增量并入 API 现状只有「文件增长一次追加」形态，分块循环消费需重塑（列拼接、崩溃事件行号偏移、tag 重映射的循环化）] → 在 `Append` 现有重映射逻辑基础上循环化，等价性测试覆盖多块拼接；不新造数据结构。
- [探针数字为 join 口径，自然行口径验收线基数可能失真] → 决策 10 前置复测，以复测值定稿默认块长与验收线；等价性测试不受口径影响。
- [总时长持平略慢 2–5%，验收线 ≤1.05× 在边界] → 稳态 32 MB 降低块边界与对齐裁剪占比；实施后以同口径复测，超线则调块长。
- [分段行号结构改 7 个访问点，回归面大] → 虚拟列表行为有既有测试；为分段结构补等价性用例（`ModelRowOf` / `DocRow` 双向往返），UI 回归按 96 DPI 口径 + 用户实机验证。
- [Reload 续扫与首次加载共用管线，取消 / 头部变化分支的交互需验证] → 等价性用例覆盖「增长续扫 vs 整份重建」「头部变化回退重建」两场景。

## Migration Plan

- apply 在 change 专属 worktree（`wt/chunked-progressive-load`）实施，主树保持干净。
- 旧整份构建路径保留为内部等价性基准（等价性不变量测试依赖它比对），不作运行时开关；回滚 = git revert 整个 change。
- 测试口径按 AGENTS §一.4：dotnet test 优先，口径数字进 docs/TESTING.md。

## Open Questions

- 稳态块长默认值（32 MB）与发布节流时长（100 ms）为可调参数，以自然行口径探针复测微调，不影响 spec 与任务拆分。
