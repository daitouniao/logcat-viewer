# Proposal：文件代理（fileproxy）

## Why

本机部分日志文件应用打不开。维护者宣布本模块时点名的两类触发：**路径不受支持**（.NET 传统 API 打不开的路径形态，如超出 260 字符上限）与**读取到的内容不是文本**；设计侧另枚举了 Windows 上几种常见的限制根因——NTFS 权限被收、共享模式冲突（写入进程独占）、EDR/组策略拦截，以及目录 LIST 收紧导致文件对话框里根本列不出。**五种情形均为根因枚举，未逐一附实际案例记录（维护者点名 / 设计侧枚举的区分见上）**；本 change 的行为契约不按根因分支——凡直接打开失败统一进入分流判定（见 spec「代理使用判定」），因此范围不依赖任一情形真实发生过，如后续确认任一条为实际遇到可在此补记。可核实的锚点是现状失败处理：装载入口一个 catch 弹「建立索引失败」了事——失败无分类，用户看不出该不该补救、也没有补救入口。本 change 新增一条「经外部代理读入」的通道：用户自写的 node/python 代理以任意手段（换身份、调别的 API、解密、从远端拉）读取受限文件，经 Windows 命名管道把字节流交给应用；应用 spool 成本地临时文件后走既有装载链路，UI 全链路显示原路径，用户无感知临时文件的存在。

## What Changes

- 新增文件代理模式配置：关闭 / 开启 / 自动三态互斥，**默认关闭**；自动模式的触发条件 = 直接打开失败，或直接打开成功后嗅探判定内容不是文本
- 新增命名管道协议客户端（v1）：`hello` / `open` / `read` / `close` 控制消息（单行 JSON）+ 带长度前缀的裸数据块；`proto` 缺失或不匹配一律判连接失败，不做兼容降级
- 新增 spool 机制：代理流按 8MB 块顺序写入应用所在目录下的临时目录；完整性以「实收字节 == `open` 响应的 size」判定，不符即删目录报错；取消 / 关闭即删，启动时后台清理崩溃残留
- 新增自动拉起与生命周期：可配置「可执行文件（解释器或 exe 完整路径）+ 参数」；仅在连不上手动代理时才拉起；应用退出即杀拉起的进程
- 新增设置对话框「文件代理…」与状态栏渠道状态区（直接读文件 / 文件代理读 / ADB 采集，三态互斥）
- 新增失败分类与 i18n 文案映射，替代现状笼统的「建立索引失败」；代理侧错误原文透出不翻译
- 改动装载入口：打开文件前增加分流段（探测 → 判定 → spool → 既有索引构建）；文档增加「显示路径 = 用户原路径 / 源路径 = 实际读取文件」的分离，Reload 经代理时全量重拉
- **BREAKING（已拍板 2026-10-17）**：新增单实例守卫，此后应用不允许同时开多个窗口；这是 spool 启动清理安全的前提，备选的跨进程活跃登记方案复杂度显著更高、不采用（见 design.md 决策 D13）

### 不在范围（out of scope）

- 目录枚举：代理只按完整路径取单文件，不进目录面板 / 时间轴
- MCP 不接入代理能力（白名单安全边界不因本 change 松动）
- DLT 格式的 auto 触发联动：DLT 立项时按其魔数形态另行设计
- 模式 B（管道随机读直替 mmap，不动索引层）：`read` 的 `off` 参数为它留门，v1 不做
- Reload 增量续拉：v1 全量重拉，续拉留后续
- BIGFILE 改造：本 change 按现状打开处实现，BIGFILE 到来时侧重接（登记为协同改动点）

## Capabilities

### New Capabilities

- `fileproxy`: 经外部代理读取本机无法直接打开的日志文件的行为契约。spec 共 27 条 ADDED 需求，分五组（组名为分组标签，并集 = spec 全部需求，无遗漏、无组外需求）：

  1. **模式判定与装载分流**（6）：模式配置与默认关闭、代理使用判定、关闭模式零行为变化、分流时序、经代理文档的路径语义、文本嗅探判据
  2. **协议与代理生命周期**（6）：连接与协议握手、协议消息帧格式、协议错误处理与句柄生命周期、代理拉起条件与超时、启动命令构造与管道名校验、拉起进程的生命周期
  3. **spool 生命周期**（7）：暂存位置与目录结构、暂存完整性与短读处置、暂存期间源文件增长不兜底、取消即删、文档关闭即删暂存目录、启动清理暂存残留、拉取进度分配
  4. **设置与渠道状态**（4）：设置对话框、渠道状态区、拉取期间渠道状态、渠道状态随语言切换重算
  5. **失败降级、可观测性与单实例前提**（4）：失败分类与错误消息、手动输入路径入口、诊断留痕、单实例守卫（BREAKING，已拍板）

### Modified Capabilities

（无。`openspec/specs/` 当前为空，装载链路的既有行为尚无 spec 覆盖；本次为全新 capability，装载入口的分流行为作为 `fileproxy` 的需求组一并纳入。）

## Impact

- 新增：管道客户端、编排服务、文本嗅探、设置对话框、单实例守卫、i18n 资源键（对话框文案 + 状态栏文案 + 错误消息）
- 改动：装载入口（分流段 + Reload 转向）、`LogDocument`（显示路径 / 源路径分离 + spool 目录自删）、`AppSettings`（5 个新字段，旧 settings.json 缺字段走属性初始化器，天然兼容）、`Program.cs`（单实例守卫 + 启动后台清理）
- 无新第三方依赖（命名管道为 .NET 内置）；实时采集链路零改动；列索引 / 过滤 / 崩溃提取零改动
- 后续协同：BIGFILE 落地时，本 change 留下的分流段与源路径打开处作为既有输入重接，由 BIGFILE 侧登记协同改动点
