# Proposal

## Why

core 已有装载、分页、结果集与过滤内核，但过滤结果至今没有出口：`filter::scan` 只在 Rust 测试里被调用，cabi 的导出面没有任何过滤入口，C# 绑定层只到分页，生产 UI 仍走自己的过滤引擎。D1 的「日志操作归 core」在过滤这条线上断开，后续 UI 切流与 MCP 都缺少同一块接缝。

现在做：上一刀 `rust-core-filter-kernel` 刚把条件模型、扫描与 `ResultSet` 定案，`scan` 是纯函数，本刀只把它包进查询生命周期并导出到 C ABI，不需要改过滤语义。

## What Changes

- Rust core 新增查询句柄：在已装载的文件源上按过滤表达式开启查询，持有开启时刻的装载快照与结果集；同一文档允许多个查询并存、互不影响。
- 查询对外提供四项读取：结果行数、按真实文档行号定位最近结果行、按真实文档行号向后取页、按真实文档行号向前取页（向上滚动与跳到尾部）；坐标一律为真实文档行号。页内容与既有分页同构，缓冲所有权与释放口径不变。
- cabi 新增查询导出（开启、行数、定位、向后取页、向前取页、释放），沿用现有错误码表与 `catch_unwind` 口径；查询句柄与源句柄生命周期解耦。
- C# 绑定层新增查询包装与集成测试；页行字段由 `Ord` 更名为 `DocRow`（字节不变，产品零引用）。
- 新增 `logcore/query` 规格，作为查询句柄行为的权威契约。

**范围外（out of scope）：**

- UI 切流：`frmMain` 的过滤调用、C# `FilterEngine` 的退役不在本刀。
- MCP 接线与 koffi 绑定。
- 正则条件、时间区间、标记与 `markedOnly`/`.lcm`、导出、流式统计档。
- 采集源过滤与采集统一快照；查询开启的异步化、进度、取消。
- 并行扫描与性能目标（本刀只验正确性与接口形态）。

## Capabilities

### New Capabilities

- `logcore/query`: 查询句柄的开启、结果读取、导航定位、生命周期与错误口径；行/页坐标一律为真实文档行号。

### Modified Capabilities

- 无。`logcore/paging` 继续描述未过滤分页（该场景下结果集序号即文档行号）；查询分页在新能力内自述「与分页同构」，不改 paging 的需求。`logcore/filter` 的条件与扫描语义不变，查询只负责把它接到句柄与分页上。

## Impact

- 代码：`crates/core` 新增查询模块并在 `lib.rs` 挂载；`crates/cabi` 新增五个导出；C# 绑定层扩查询包装与页行字段更名。
- 对外：新增 C ABI 符号；LPAG、`.lcs`、`.lcm` 字节不变；C# UI 行为不变。
- 依赖：不新增 crate。
- 文档：`docs/TESTING.md` 的 Rust 与 C# 用例数按实测同步。
