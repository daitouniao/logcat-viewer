# Proposal

## Why

新壳打开日志每次都只能走文件对话框，反复查看同一批日志要重复导航。旧查看器已有「文件 → 最近打开」，新壳没有，这是两条应用之间最直观的能力落差之一。

本刀补上最近文件，并为其落一个可持久化的设置项；同时把设置层的「本轮键面」从两项扩到三项，为后续列宽等设置键建立可复用的追加方式。

## What Changes

- 文件菜单新增「最近打开」子菜单：最近在前，最多 10 条；条目过宽时中部省略，悬停显示完整路径；没有可显示条目时子菜单禁用。
- 日志装载成功（含 0 行文件）即记录该文件；装载失败、被新的打开操作顶替或被取消时不记录。
- 最近文件列表持久化到设置文件的新键（字符串数组），设置 schema 保持 v1，作为可选键追加，不 bump 版本；旧设置文件没有该键时按空列表处理。
- 本地路径条目在显示时检查存在性：缺失则不显示但记录保留；网络路径不做存在性探测，始终显示。
- 规范：新增能力 `next/recent-files`，冻结记录时点、上限与去重、持久化与降级、菜单展示、失效处理；修改 `next/app-storage` 的「本轮设置键面」与「设置项互不覆盖」。

**范围外（out of scope）：**

- 列宽可调整：另起一刀，本 change 不涉及任何列宽设置。
- 行标记：归属 core、与过滤同批，本刀不做（另登记待办）。
- 单条移除与清空最近文件：本刀不提供。
- 拖拽打开并入最近文件：本刀只覆盖菜单与文件对话框两条打开路径，拖拽留待其自身切片。
- 最近文件的分组、固定项、跨设备同步。
- 改动旧查看器与 `uicore` 的最近文件实现、设置文件与菜单。

## Capabilities

### New Capabilities

- `next/recent-files`: 新壳最近文件的行为契约——记录时点与来源范围、上限与去重、持久化与会话内降级、菜单展示与省略规则、失效条目的显示与保留。

### Modified Capabilities

- `next/app-storage`: 「本轮设置键面」由语言与主题两项扩为语言、主题与最近文件三项；「设置项互不覆盖」覆盖三个键；未知键口径不变。

## Impact

- **代码**：`logcat-next/Next.App` 的设置模型 / 设置服务 / 主窗菜单 / 装载流程；`logcat-next/Next.Tests` 新增与扩展用例；双语字符串目录各加一条子菜单文案。
- **设置文件**：`next-settings.json` 追加最近文件键，v1 兼容；旧文件、缺键、超上限列表均可读取。
- **依赖**：无新增。
- **规范**：新增 `next/recent-files`，修改 `next/app-storage`。
