# Design

## Context

动机见 `proposal.md`；行为契约见本 change 的 `specs/next/recent-files/spec.md` 与 `specs/next/app-storage/spec.md`。

现状要点（2026-11-27）：

- 设置层已具备单一写入入口：内存模型是权威值，任一设置修改都整体落盘；`NextSettings` 目前只有 `SchemaVersion` / `Lang` / `Theme`，`JsonNextSettingsStore.Save` 只写这三个键，`Load` 只认 v1。
- 装载流程在 `MainViewModel.LoadFileAsync`：`Plan` → `Commit` → 轮询事件至 `done` / `error`；`done` 后用 `RowCount()` 决定状态栏与行数；加载失败与被下一次加载顶替各有独立分支。
- 主窗菜单在 XAML 内静态声明（文件 / 语言 / 主题），文件菜单当前只有「打开文件…」；菜单文案走 `{loc:Loc Key=...}`，双语目录在 `Next.App/Assets/Strings.*.json`。
- 旧查看器已有最近文件实现可参照：上限 10、本机路径大小写不敏感去重、最近在前、缺失的本地条目不显示但不删除、网络路径不做存在性探测、中部省略约 80 字符 + tooltip。

## Goals / Non-Goals

**Goals:**

- 最近文件的记录、去重、上限、持久化与会话内降级都有可单独测试的纯逻辑入口，不依赖 Avalonia UI 才能验证。
- 复用既有设置层的「单一写入入口」，不引入第二个设置文件或第二套写盘路径。
- 菜单展示规则（可见性、省略、禁用）抽成可测函数，主窗只负责接线与事件。

**Non-Goals:**

- 不涉及列宽设置（下一刀），不预先为该键占位。
- 不修改旧查看器 / `uicore` 的最近文件实现。
- 不引入路径规范化、符号链接解析或短路径展开。
- 不做最近文件的单条移除 / 清空、分组、固定项、拖拽打开并入。

## Decisions

### D1 列表归设置服务，不建独立文件

最近文件与语言、主题同属「用户设置」，写入既有 `next-settings.json`。

理由：设置层已有原子写、失败降级、互不覆盖的契约与测试；另建文件会重复实现这些语义，还会引入两文件之间不一致。备选「最近文件单独一个 JSON」被否决——它需要在别处再实现一次临时文件 + 替换与容错读。

### D2 schema 保持 v1，追加可选键

`NextSettings` 增加 `RecentFiles`（字符串数组），`Load` 对缺失 / 空值按空列表处理；不 bump `SchemaVersion`。

理由：`Load` 只在版本完全匹配时接受文件，bump 到 v2 会让所有既有设置文件一次性失效，用户语言与主题被重置，代价与收益不匹配。新增键为可选，旧文件天然兼容。读取时对超过上限的列表做截断（防御手工编辑或旧数据），保存时按上限写出。

### D3 去重与顺序：大小写不敏感，保留最新文本

比较用 `StringComparison.OrdinalIgnoreCase`，命中后先移除旧条目再插到最前，新条目文本取本次打开传入的路径；不做任何规范化。

理由：与旧查看器 `FavoritesStore.AddRecentFile` 的本机路径口径一致（Windows 文件系统大小写不敏感）；原样保存避免把用户可见路径改写（相对片段、长路径前缀、分隔符混用都保持原样）。备选「用 `Path.GetFullPath` 规范化」被否决——会改变显示文本，且对网络路径与不存在路径可能抛异常。

### D4 记录时点挂在装载成功路径

只在 `done` 分支、且未被取消时调用记录；`done` 之前 `error` 分支、`OperationCanceledException` 分支都不调用。0 行文件同样在 `done` 后记录。

理由：spec 以「装载成功」而非「用户发起打开」为记录条件；把记录放 `done` 后也与行数状态更新同一处，避免出现「记录了但实际没装载」的假条目。备选「在对话框/菜单点击后立即记录」被否决——失败与取消会污染列表。

### D5 菜单可见性抽成纯函数

展示规则（本地存在性检查、网络路径跳过探测、中部省略、空则禁用）集中在一个无 UI 依赖的构建函数中，输入为记录列表与「条目存在性判定」委托，输出为可显示条目（文本、完整路径）与是否禁用。

理由：Avalonia `MenuItem` 不方便在单测里断言；纯函数可用临时目录与伪造的探测委托覆盖「缺失隐藏、网络不探测、省略长度、空列表禁用」四类场景。主窗只把结果映射成菜单项。备选「直接在窗口里 `File.Exists` 并拼控件」被否决——不可测且易漏网络路径分支。

### D6 网络路径判定与探测失败

以 UNC 前缀（`\\` 开头）识别网络路径，不做存在性探测；本地路径用 `File.Exists`，任何异常按「不存在」处理（隐藏但保留记录）。

理由：与旧查看器口径一致，避免访问不可达网络共享造成菜单卡顿；异常兜底防止权限问题把构建菜单变成崩溃点。

### D7 中部省略到 80 字符 + tooltip

仅当路径长度超过 80 字符时省略，保留首尾、以单个省略号连接；完整路径放入菜单项的 tooltip。不显示序号与快捷键。

理由：沿用旧查看器既定表现，用户已熟悉；80 字符足以容纳多数本地路径的目录特征。备选「不在菜单里省略、交给菜单宽度」被否决——长路径会把菜单撑到屏幕外。

### D8 空状态与全隐藏同表现

没有可显示条目时子菜单 `IsEnabled = false`；当记录非空但全部本地缺失时同样禁用（可见集合为空）。

理由：spec 把「空列表」与「全部不可显示」归一为同一表现，避免出现一个展开后什么都没有的可点菜单。

### D9 打开最近项复用既有装载流程

菜单点击调用与「打开文件…」相同的装载入口（`MainViewModel.LoadFileAsync`）；错误仍落状态栏。打开失败不修改记录。

理由：避免两条打开路径的行为分叉（状态栏、取消、错误码都已有契约）；失败不改记录保证「记录只由成功装载驱动」。

### D10 刷新触发：服务事件 + 语言切换

设置服务在最近文件变化时发出变更事件，主窗订阅后重建子菜单；语言切换沿用既有 `LocalizationService` 的索引器通知，主窗在收到后同时重建子菜单标题。

理由：菜单是静态 XAML，条目需要动态生成；事件驱动避免轮询或在每次菜单展开时重建整个文件菜单。标题走既有本地化机制，不新增并行方案。

### D11 会话内降级沿用设置层

持久化不可用时设置服务已用 `InMemorySettingsStore`；最近文件随内存模型保存，行为与语言/主题一致：本次运行可见，重启清空。

理由：不在最近文件层另做降级判断；`StorageRoots.SessionOnly` 已是唯一事实来源。

## Risks / Trade-offs

- **[每次构建菜单都做本地存在性检查，网络盘或慢盘可能拖慢展开]** → 网络路径不做探测；本地检查只在菜单构建时进行，并吞掉异常；条目上限 10，开销有界。
- **[保存失败后内存列表与磁盘不一致，重启回退]** → 与既有设置契约一致（保存失败不打断、重启回最近一次成功值），已在 spec 的场景中显式约定。
- **[未知键保存时被丢弃]** → 这是本轮明确的契约（`next/app-storage` 已声明），不是回归；携带未知键的外部工具改动会丢失其数据，属可接受取舍。
- **[列表读取截断可能让手工编辑写入的更多条目静默消失]** → 截断发生在读取侧且上限在 spec 中公开；保存侧同样截断，行为可预期。
- **[用 80 字符定长省略对宽字符不精确]** → 沿用旧查看器字符数口径，不引入字体测量；菜单本身不承担完整信息展示，tooltip 兜底。
