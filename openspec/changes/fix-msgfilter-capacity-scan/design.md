# Design

## Context

缺陷位于 message 大小写不敏感过滤路径：折叠判定函数按传入缓冲区的整个 `Length` 扫描，而调用点把每行消息拷入一个只增不减的复用缓冲（首次 1 KB，按 2 的幂翻倍），导致每行扫描量 = 缓冲容量而非行内字节；且残留字节 ≥ 0x80 会让纯 ASCII 行误判为非 ASCII，走 Unicode 回退。完整根因、实验数据（A–H）与成本反算见探索笔记 `openspec/notes/NETWORK-FILE-FILTER-PERF.md`（归档后按归档路径查阅）。

G′ 实测（2026-10-23，探针口径，同一测试文件 176 MB / 2,719,107 行）：保留全容量扫描、跳过回退与匹配后，扫描本体 **12,322 ms**、累计扫描 **26.58 GB**（行均容量 10,498 B，吞吐 2.16 GB/s）；对照 G（现状复刻）13,643 ms、H（切片修复形态）432 ms，命中数三者全等（49,602）。「容量扫描是主因」由反算（~1 GB/s × 16.2 GB ≈ 16 s）升级为实测：G 耗时约 90% 来自按容量逐行扫描。

约束：

- 行为不变是硬约束——命中数在 G/H 及全部对照实验中必须全等；非 ASCII 行的 Unicode 回退路径（ß/ẞ、İı 等长宽变化规则）原样保留。
- 测试口径以 docs/TESTING.md 为唯一权威源，优先 dotnet test，声明必须带数字。
- 现有模式沿用：`InternalsVisibleTo("logcat.Tests")` 已配置，internal + 单测直测是仓库既有做法。

## Goals / Non-Goals

**Goals:**

- 消除「每行 O(缓冲容量)」扫描：单行成本只与该行自身字节数相关。
- 回退率回落到数据下限（只对真正含非 ASCII 的行走 Unicode 回退）。
- 把「容量扫描是主因」从反算升级为实测（G′ 实验）。
- 用回归测试钉死「每行只扫自身字节」不变式，防止未来改动复发。

**Non-Goals:**

- 不重写过滤引擎、不动 scratch 结构（方案 2 另议）。
- 不处理 IO 侧、索引构建（`LogDocument.Build`）等已排除项。

## Decisions

1. **修复形态 = 方案 1 最小切片**：折叠函数新增 `Span<byte>` 重载，调用点改为按 `msgBuf.Length` 切片传入（`scratch.AsSpan(0, msgBuf.Length)`）。
   理由：一条改动同时消掉主因（扫描量回落）与次因（不再读残留字节，回退判定只看本行）；对现有 `byte[]` 版本零破坏（保留给既有调用或改为委托切片实现）；探针 H 形态实测 17.4 s → 516 ms，命中数与现状全等。
   备选（已否决/缓议）：方案 2（删 scratch、对 `msgBuf` 原地折叠）结构更净且省每趟 ~176 MB 拷贝，但改动面更大，维护者拍板本次不做，记为可选后续优化。

2. **可测性调整**：折叠函数从 `private` 放宽为 `internal`，测试工程经既有 `InternalsVisibleTo` 直测。
   理由：直测重载是回归测试的一半（Q2-①）；仓库已有 CommandStore、AppSettings 等同款先例，不发明新模式。

3. **不变式钉法 = 扫描字节计数器**（Q2-②，主钉）：折叠路径增加 internal 只读计数（仅测试观测用），断言「一次过滤的扫描总字节 == Σ 各行正文长度」。
   理由：直测只能钉单行行为，钉不住「调用点传了多大切片」；计数器把不变式（每行只扫自身）变成可断言契约。计数走 `internal` 字段/属性，不进公开 API。

4. **G′ 对照实验在修复前跑**（Q1-B）：复用 `.tmp-test/realprobe/` 探针工程（git-ignored，不入库；csproj 需显式枚举新增 .cs），保留全容量扫描、仅统计扫描字节/跳过回退，与 G/H 组成三点对照。
   理由：探索结论的「主因」目前是反算（~1 GB/s × 16.2 GB ≈ 16 s），G′ 把它坐实为实测；探针与测试文件本机已具备，可复跑。探针跑不了时降级：design 如实标注「反算口径」，不阻塞修复本体。

5. **不加防护**：不给 scratch 设容量上限、不加超长行分支。
   理由：修复后单行成本与容量无关，容量只影响一次性的拷贝分配，属「不需要的防护」。

## Risks / Trade-offs

- [计数器引入额外分支/字段，微慢热路径] → 计数是单次整型加法，量级远低于被消除的 KB 级扫描；H 实测已含同形态开销仍 34 倍提升。若实现后 dotnet test 数字异常再评估。
- [重载分叉造成两份折叠逻辑漂移] → `byte[]` 版本实现为对 `asSpan()` 的转发，逻辑单源。
- [切片边界错（如用 scratch.Length 而非 msgBuf.Length 切匹配）会静默扩大匹配范围] → 既有匹配切片本就按 `msgBuf.Length`；回归测试用「长缓冲 + 短行」用例覆盖（先长中文行污染容量、再短 ASCII 行，断言命中一致）。
- [G′ 实验环境不可复现（探针文件缺失等）] → 降级为反算口径并在 design 留痕，不影响修复本体与回归测试推进。

## Migration Plan

无部署/迁移问题：单程序集内行为不变的性能修复，随常规发版携带；回滚即还原单文件改动。
