# Spec Delta

## ADDED Requirements

### Requirement: 设备列表变更通知的线程安全与快照语义

设备列表发生变更时，系统 SHALL 以**变更时刻的快照**通知订阅方，通知参数 SHALL NOT 随内部列表的后续变更而改变；内部列表的读写 SHALL 互斥，读取方 SHALL NOT 观察到「已清空但尚未重建完成」的中间状态。订阅方在 UI 线程枚举通知参数时 SHALL NOT 因后台线程并发刷新而抛异常。通知 SHALL 在释放内部锁之后发出，SHALL NOT 要求订阅方在回调期间重入该锁。

#### Scenario: 连续两次刷新交错

- **WHEN** 后台线程连续两次刷新设备列表，UI 线程在两次之间枚举第一次通知拿到的参数
- **THEN** 枚举正常完成（不抛 `Collection was modified`），且枚举到的内容与第一次变更后的设备集合一致

#### Scenario: 通知参数不随后续变更

- **WHEN** 订阅方保留某次通知拿到的列表引用，之后设备列表再次变更或被清空
- **THEN** 先前拿到的列表内容保持原样，不随之改变

#### Scenario: 自愈失败清空与后台刷新并发

- **WHEN** UI 线程因自愈失败清空设备列表，同时后台监控线程正在写入新的设备集合
- **THEN** 两个操作互斥完成，最终状态是「空列表」或「新集合」之一，不出现部分写入的中间状态，且不抛异常

#### Scenario: 当前设备查询与并发变更

- **WHEN** 在后台线程变更设备列表的同时，UI 线程查询当前选中设备的序列号或 RootMode
- **THEN** 查询返回「变更前」或「变更后」的一致结果，不抛异常、不越界
