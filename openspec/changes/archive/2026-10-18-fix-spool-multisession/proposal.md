# Proposal：修复跨会话并存下的暂存目录互删（fix-spool-multisession）

## Why

单实例互斥量使用 `Local\` 前缀，作用域是**每个 Windows 会话**而非整机。远程桌面多会话并发、快速切换用户两种场景下，两个会话可以各运行一个应用实例，互斥量互不感知——「已有实例运行时第二实例退出」的承诺在这两种场景下今天就不成立。

而启动清理（暂存根目录全部子目录无时间阈值删除、只跳过本进程活跃集合）会把另一实例正在使用的暂存目录当作崩溃残留删掉。主规范「单实例守卫」需求把「单实例」写成「暂存启动清理安全的前提」，但该前提只在**同会话**内成立：跨会话并存时两个实例会互删对方的活跃暂存目录，且没有任何机制兜底。真实危害窗口在「spool 完成 → 文档关闭」之间——spool 写盘期间暂存文件带排他共享、删不掉，但写盘结束后目录无任何保护，此时被删意味着代理文档的索引构建读不到文件或读到残缺内容（直接失败，或更坏地部分读到）。

本 change 不引入多开功能，只修复这个已存在的数据丢失风险：让暂存目录的安全性不再依赖互斥量的覆盖范围，而是由每个暂存目录自身的跨进程活性判定独立保证。这也是未来任何形式多开（多进程）的必要地基。问题发现过程与窗口分析见 `docs/bugfixes/MULTISESSION-SPOOL-DELETION.md`。

## What Changes

- **修改「启动清理暂存残留」需求**：清理前对每个候选子目录做跨进程活性探测——被任何存活实例持有（含本进程自己）的目录跳过；无活性标记或标记已释放的按死亡目录删除。无时间阈值、后台线程、删不掉只留痕的口径不变；删除 / 跳过 / 失败计数留痕不变。
- **修改「单实例守卫」需求**：措辞从「本机单实例」收敛为「本会话范围单实例」，明确跨会话并存（远程桌面多会话 / 快速切换用户）为设计容忍状态；暂存目录安全性不再依赖互斥量，改由活性判定独立保证（原需求中「单实例是启动清理安全的前提」这一前提性描述删除）。2026-10-17 的 BREAKING 拍板记录（同会话内不再允许多开）不变。
- 实现侧：暂存目录活性锁原语 + 清理探测改造 + 暂存目录全生命周期持锁 + 失败/取消路径释放（细节见 design.md）。
- 对用户可见行为：同会话内零变化；跨会话从「互相删除对方暂存目录」变为「安全并存」。

### 不在范围（out of scope）

- 完整多实例功能：设置文件（settings / favorites / commands）并发覆写的合并策略、每实例独立暂存根、`Global\` 前缀互斥量等——本 change 后跨会话并存已无害于暂存数据，但设置文件的 last-writer-wins 语义仍在，登记为后续候选，不在本 change 解决
- 同进程多窗口（单文档模型、`YearTables` 无锁静态缓存等既有约束不动）
- 自动拉起代理的双拉竞态（危害仅一个短命孤儿进程 + 一条失败日志，记录备查不修）

## Capabilities

### New Capabilities

（无。本 change 不引入新能力，只修正既有能力的两条需求。）

### Modified Capabilities

- `fileproxy`: 修改两条需求的行为契约——
  1. 「启动清理暂存残留」：跳过判据从「本进程活跃集合」改为「跨进程活性探测，任何存活实例持有即跳过」；
  2. 「单实例守卫」：保证范围从「本机」收敛为「本会话」，跨会话并存为设计容忍状态，暂存安全性改由活性判定独立保证。

## Impact

- 改动代码：`Services/FileProxyService.cs`（清理逻辑改造 + `SpoolPaths` 活性锁原语：session 目录创建即持锁，新增公开类型 `SpoolDirLease`）、`Services/LogDocument.cs`（`SpoolDir` 属性改持租约，Close 删目录后释放）、`frmMain.cs`（spool 分流段的失败 / 取消路径释放活性标记）、`Program.cs`（启动清理调用点适配新签名）；API 面：新增 `SpoolDirLease`，`NewSessionDir` 返回类型与 `LogDocument.SpoolDir` 属性类型随改，均限仓内调用点
- 测试：新增活性锁语义用例（持有即跳过、释放即删除、无标记按死亡删除）；`SpoolCleanupTests` 的「活跃目录跳过」判据从参数传入改为锁持有；`LogDocumentProxiedTests` 补「Close 后锁释放、目录可再清理」语义；`SingleInstanceTests` 不变（同进程语义不受影响）
- 无新第三方依赖；无 UI 变化；无设置字段变化；实时采集 / 索引 / 过滤 / 崩溃提取零改动
- 公开文档：README 与 `docs/FEATURES.md` 中单实例相关描述在打 tag 时按活文档规则联动更新（本 change 不提前改，避免与 tag 口径重复）；README 测试数徽章已随实施刷新（623 → 628，§3.3 徽章例外口径）
- 双文档实践：按仓库 bug 修复规矩，本 change 同时携带 bug 报告 `docs/bugfixes/MULTISESSION-SPOOL-DELETION.md`（含 §3.7 统一文档头）
