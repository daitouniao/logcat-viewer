# Proposal

## Why

本仓库已有 MCP 服务端壳（`mcp/`，包名 `logcat-mcp`，stdio 传输，能力仅一个 `info` 自述工具，规范已归档在 `openspec/specs/mcp/server-shell/spec.md`）。但它是**单服务端形态**：一个进程、一个上游、零工具。

真实使用场景里，一个 Agent 往往要同时用多个 MCP（文件系统、浏览器、数据库、日志……）。若每个都单独配一份、单独起进程，配置散落、启停靠手改 JSON、状态无从查看；同时对外暴露多个 stdio 服务端也不现实——多数 MCP 客户端只支持配一个 stdio 命令。

因此需要一个**代理层**：对下游 Agent 它是一个 MCP 服务端（stdio），对上游它拉起并管理多个 MCP 服务端（v0 仅 stdio 子进程），把上游工具聚合后以命名空间形式暴露给 Agent；配套一个本机管理页面，用于查看上游状态、增删改上游、启停与重启。

本刀的价值独立于日志业务：它解决的是「MCP 怎么被组织起来」，与 `MCP-FUNCTIONALITY.md` 里的业务工具面口径（D5 待拍板）互不影响——代理不定义任何业务工具。

**本刀是 v0**：只做代理骨架 + 配置 + 生命周期 + 聚合路由 + 管理页面。刻意不接日志数据能力、不定义业务工具面。

## What Changes

- 新增 Node 工程 `mcp/proxy/`（包名 `logcat-mcp-proxy`）：一个进程同时扮演 MCP 服务端（对下游，stdio）与 MCP 客户端（对上游，stdio 子进程）。
- 上游以配置文件列举（id / 命令 / 参数 / 环境变量 / 工作目录 / 启用开关），由代理拉起、监控、重启。
- 上游工具按 `server__tool` 前缀命名空间聚合后暴露给下游 Agent；调用按前缀路由回对应上游。
- 新增本机管理页面（HTTP，绑定回环地址）：查看上游状态与工具数、增删改上游、启停与重启上游、查看上游诊断输出尾部。
- 代理内置两个管理工具（`proxy_servers` / `proxy_restart`），使 Agent 也能查询与重启上游，而不必打开页面。
- 上游调用有**时限**（默认 60 秒，超时按上游不可用族返回），上游就绪有**时限**（默认 10 秒）；错误描述保留上游返回的原始错误文本，错误码归一为四个稳定英文码。
- 新增规范能力 `mcp/proxy`，冻结代理的行为契约（配置持久化、生命周期、聚合与命名空间、路由与错误语义、管理页面与访问控制、资源释放与通道纪律）。

**范围外（out of scope）：**

- 不支持 http / sse 上游：v0 只拉起本机 stdio 子进程。
- 不做 http 下游传输：代理对下游只有标准输入输出，**只支持能以子进程方式拉起 stdio 服务端的 MCP 客户端**；HTTP 下游列为下一个切片的候选。
- 不做多下游客户端共享：**一个代理实例同时只服务一个下游客户端**（stdio 形态的必然结果）；「多 Agent 直连」在 v0 的形态是**各 Agent 各起一个代理实例**，共享同一份配置文件路径，但上游进程各拉各的、页面启停各管各的。
- 不做调用取消转发：客户端取消时代理中止本次转发，**不把取消信号转给上游**。
- 不做按下游 Agent 隔离上游会话：v0 同一上游的会话由所有下游共享。
- 不做工具级暴露开关：上游工具全量聚合，页面只能整体停用某个上游。
- 不引入上游认证与凭据管理：环境变量以配置文件明文存放，页面不回显明文。
- 不定义任何业务工具面：不读日志、不产出日志数据、不实现检索 / 统计 / 崩溃清单等任何业务工具；聚合的上游工具原样透传，不改写、不裁剪。
- 不做代理自身的多实例、负载均衡与跨机部署。
- 不发布 npm 包、不占公共包名、不进版本号同步点；只保证本地可运行。
- 不改动既有 `mcp/` 服务端工程、Rust 内核、C# 宿主与既有规范。

## Capabilities

### New Capabilities

- `mcp/proxy`: MCP 代理的行为契约——上游配置与持久化、上游生命周期与状态、工具聚合与命名空间、调用路由与错误语义、管理页面与访问控制、进程退出时的资源释放与通道纪律。

### Modified Capabilities

- 无。本刀不改动 `mcp/server-shell` 与任何既有 capability 的需求（代理是独立进程，与 `logcat-mcp` 服务端无耦合）。

## Impact

- **新增工程**：仓库根 `mcp/proxy/`（Node + npm + tsc + node:test），包名 `logcat-mcp-proxy`，构建产物与依赖目录不入库。
- **新增依赖**：引入 MCP 客户端 SDK（`@modelcontextprotocol/client`）；既有 `mcp/` 用的服务端 SDK 与模式校验库在代理工程内为独立依赖。均不进入 .NET 与 Rust 依赖树。
- **配置产物**：代理运行时的配置文件写在用户配置目录（不进仓库），仓库内只留一份示例配置作为默认形状的说明。
- **CI**：流水线新增代理工程的构建与测试作业（Node 版本矩阵与既有 `mcp` 作业一致）。
- **文档**：`docs/TESTING.md` 增补代理工程的测试说明与实测用例数（单独记录，不并入既有合计口径）；`docs/BUILDING.md` 在出现新的构建动作时更新。
- **忽略规则**：`.gitignore` 需覆盖代理工程的依赖目录、构建产物与本地配置文件。
- **不动**：既有 `mcp/` 工程、Rust workspace、C# 宿主与解决方案、既有规范文件。
