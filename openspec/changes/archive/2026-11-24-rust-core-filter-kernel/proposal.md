# Proposal

## Why

core 已有装载、索引、分页与结果集模型，但结果集的显式行号分支至今没有生产者：过滤仍只在 C# 侧，UI 与未来的 MCP 会各自长出一套入口；MCP 需要的 tag 精确匹配、正文子串语义也无处落地。

现在做：上一刀「结果集内核」刚把「结果集序号 → 文档行号」与 `resolve`/`page` 的地基铺好，过滤内核是它的直接消费者，先做不会返工的结构。

## What Changes

- 新增 Rust core 过滤内核：过滤条件模型（级别、进程号、线程号、时间戳分钟 0–59、tag、正文子串；多值组合方式、大小写、排除），对装载完成的文件源做全量扫描，产出升序、不重复的文档行号结果集。
- 无任何条件时返回恒等视图，不复制行号；有条件时结果集进入显式行号分支，可直接交给既有的分页与导航路径使用。
- 正文匹配沿用既有的可见语义（行头不参与、Unicode 小写等价、空词、排除），正文从装载时的常驻文件句柄按需回读，不整份复制正文、不 mmap。
- 新增 `logcore/filter` 规格，作为该行为的权威契约。

**范围外（out of scope）：**

- 正则条件、时间区间条件、标记与 `markedOnly`/`.lcm` 持久化、导出、流式统计档。
- 查询句柄、queryId、查询状态机、异步/进度/取消、`set_result`。
- cabi 导出、C# 绑定、UI 切流、MCP 接线。
- 采集源过滤与采集统一快照；并行扫描与性能目标（本刀只验正确性）。
- `old/message-filter` 规格与 C# 现行行为不动：那是 C# 宿主的现行契约，UI 切流时再整条迁移或退役。

## Capabilities

### New Capabilities

- `logcore/filter`: 过滤条件模型与全量扫描的行为契约——条件组合与元数据可见性、正文作用域与大小写等价、结果集形态与导航定位、错误与一致性口径。

### Modified Capabilities

- 无。`logcore/paging` 保持只描述未过滤的分页面；本能力在自身上下文中说明「过滤结果如何交给分页」（按真实文档行号起页，区分锚点定位与顺序翻页），不改 paging 的需求。

## Impact

- 代码：`crates/core` 新增过滤模块并在 `lib.rs` 挂载；新增过滤测试与固定样本。
- 对外：无 FFI 导出、无 LPAG/`.lcs`/`.lcm` 字节变化；C# 侧零改动。
- 依赖：不新增 crate（JSON 解析复用现有依赖）。
- 文档：`docs/TESTING.md` 的 Rust 用例数与覆盖率按实测同步。
