# Design

## Context

现状：`logcore/` 是单箱 cdylib（`logcore.dll`），同时承载 FFI 面、源获取编排、解析雏形与 sidecar 编解码；解析缺方括号 long 格式、时间戳字段校验与崩溃打标，装载是整份 `fs::read` + 解析完才落缓存；plan 阶段查询缓存时整份读取条目并解码。约束来源：

- sidecar v1 字节格式冻结，旧条目必须可直接复用；切流后 Rust 成为唯一读写者，键派生只需 Rust 自洽。
- 归档的 `logcore/source-acquire` 规定命中判定在 plan 阶段完成；本 change 的 delta 把判据限定为定长头部，并允许解码后移。
- C# 集成测试经 FFI 调真实 core（36 条），dll 装载路径与产物名 `logcore.dll` 由 C# 侧探测，本刀不改 C# 产品代码。
- 解析语义的期望值以 C# 基线规范为准（`old/chunked-file-load`、`old/time-column`、`old/sidecar-index-cache`），不新增 capability。
- 验收口径：Rust UT + IT；`cargo test` 必须串行（进程级代理登记表导致并行不稳定）。

## Goals / Non-Goals

**Goals:**

- 三箱 workspace 落地，内核改造后仍保持 `logcore.dll` 产物名与开发树路径不变。
- 解析与索引语义对齐 C# 基线：8 列、long 格式、时间戳字段校验、崩溃打标、tag 字典。
- 未命中路径分块渐进发布；"分块 ≡ 整份"成为可自动断言的不变量。
- plan 阶段缓存探测只读定长头部；解码移到装载开始，失败静默降级并只更新一次装载模式。
- sidecar 写侧流式、后台落盘、临时名进程内唯一。

**Non-Goals:**

- 不出 C ABI 新导出面、不做分页（刀2）；不迁过滤（刀3）；不清理遗留 v1 条目（刀5）。
- 不改 sidecar 字节格式与键派生算法；不引入 mmap 或借用式 payload。
- 不改 C# 产品代码；UI 行为不变化。
- 不上并行建索引；不做 DLT 解码与正则。

## Decisions

### D1 workspace 拆分保持产物路径不变

仓库根新增 `Cargo.toml` 作为 workspace，成员为：

```
crates/core   包名 logcore_core：解析、索引装配、sidecar 编解码、源获取编排（含 plan/commit/事件）
crates/cabi   包名 logcore：cdylib + rlib，只保留 FFI 薄面与测试代理 bin（刀1 不扩面）
crates/cli    包名 logcore_cli：调试/对拍用的可执行壳
```

仓库根 `.cargo/config.toml` 固定 `build.target-dir = "logcore/target"`，使开发树产物仍落在 `logcore/target/<配置>/logcore.dll`；cabi 包名保持 `logcore`，产物名不变。`.github/workflows/ci.yml` 的构建入口改为仓库根 workspace，`docs/BUILDING.md` 中路径段落同批更新。仓库根另补 `rust-toolchain.toml` 固定工具链 1.99.1，使 CI 与本地使用同一编译器；CI 只维护 GitHub 工作流，GitCode 侧不做 CI 覆盖；新建根 `Cargo.toml` 的版本号与 `Directory.Build.props` 对齐，消除发版清单的手工同步点。

备选：workspace 根放 `crates/`、产物改 `crates/target`——会使 C# 装载探测失效，本刀不允许改 C#，否决；维持单箱——违反"目录重组早于刀1"，且刀2 还需再拆一次，否决。

### D2 解析语义按 C# 基线对齐，作为固定期望值

- 行首两形态：日期起首（`mm-dd` 或 `yyyy-mm-dd`）与方括号 long（`[` 前缀）。long 行走带回退正则的路径，六列（时间、pid、tid、level、tag、消息偏移）齐备；`]` 后无空格时消息偏移相应前移。
- 时间戳校验只做字段范围检查（月 1–12、日 1–31、时 0–23、分 0–59、秒 0–59 之外收未知元数据）；范围合法但日历非法（如 `02-31`）保持解析，秒为 60 的闰秒形态保持解析并按原始分钟归属——与基线一致。
- 解析失败的行不丢弃：整行按未知元数据收（分钟哨兵 255、pid/tid 为 -1、级别 0、tag 空、消息偏移 0），Time 列渲染空。
- 期望值写成固定字面量，来源是 C# 基线行为，不得用 Rust 现状输出回填。

### D3 崩溃打标绑定索引期父行

对每个块先做字节级快筛，命中后做 3 行前瞻，识别 Java / Native / ANR / Tombstone 四类，归属到崩溃头所在行；提取器只依赖行文本与消息偏移，与解析成败解耦（时间戳非法的行仍可产出崩溃事件）。跨块时保留上一段末 3 行参与前瞻，块内只索引到对齐边界之前，避免重复或丢失。产物为崩溃事件表与两张字典（异常类型、包名），随 sidecar 一起持久化。Kind 编号与基线一致：Java 0、Native 1、ANR 2、Tombstone 3。

### D4 段化列存 + 原子追加发布

每块装配成不可变 `Segment`（按行区间持有 8 列），发布以 `ArcSwap<Vec<Arc<Segment>>>` 追加，读侧按行号定位段；首块 4 MiB、稳态 32 MiB，块边界对齐换行。写侧（sidecar 落盘）按列跨段遍历，避免把段合并成整份。内存峰值目标为不高于整份路径同环境峰值；"分块结果 ≡ 整份结果"（8 列、tag 字典顺序、崩溃行号）作为 IT 不变量。

### D5 sidecar 写侧流式 + 后台落盘

v1 字节格式不变：定长头部（魔数、版本、行数、宽度、8 段长度、总长、身份）→ 三本字典与崩溃表 → 8 个列段。写侧先算出头部（段长与字典大小由内存 payload 得出），用 `BufWriter` 逐列写出，先写临时文件再原子替换；临时名在条目名基础上追加进程内唯一后缀（原子计数），不再用 pid。落盘在装载完成、完成事件发布之后交后台线程，退出不等待；写失败静默，不影响装载结果。写入前检查既有条目头部版本，高于当前实现则跳过写入、不覆盖；低于当前版本原位重写。

### D6 plan 头部探测（乙）

命中判定只读定长头部（当前 124 字节，至身份四要素为止）：

```
magic(4) version(4) rows(4) widths(8) segLen(64) total(8) identity(32)
校验：魔数 / 版本 / rows>=0 / 段长 == rows*width[i] / 文件长度 == total / 身份四要素一致
```

- 任一校验不过即未命中，走完整解析（与现状"解码失败即命中失败"对外等价）。
- 通过即登记在用条目并记录头部信息（行数、身份）；`cache_hit` 不再存放 `Payload`，plan 结束后句柄里只剩"命中头部"。
- 装载开始复核身份：一致则解码条目；解码失败（字典越界、列数据损坏）按条目损坏静默降级，进入索引阶段完整解析，并把装载模式由一次到位更新为分块渐进（仅此一次，spec delta 已覆盖）。
- commit 期解码改为**逐列流式读**：读头部 → 流式读字典与崩溃表 → 依段长逐列读入目标列数组，直接构造 `Payload`；不再 `fs::read` 整份，也不再"整份字节 + 持有列"双份峰值。
- 备选：保留整份读取（甲）——plan 延迟与 2× 峰值仍在，已否决；命中判定后移到 commit——与归档 spec"命中判定在 plan 完成"冲突，否决。

### D7 缓存键派生与回收保持现状

键派生算法不改（切流后 Rust 自洽即可，旧条目一次性清理归刀5）；LRU 与在用登记不变，plan 头部探测通过即登记，保证 plan→commit 之间条目不被本进程回收。

## Risks / Trade-offs

- **workspace 拆分破坏 C# 装载与 CI** → 产物名与 target 路径保持原样，CI 与 BUILDING 路径同批改；验收必须包含一次完整 `dotnet test`（含 36 条 FFI 集成测试）证明无回归。
- **头部完好但列数据损坏** → plan 误判命中，装载开始解码失败即降级重解析，spec 场景已覆盖；代价是一次白读，不产生错误事件。
- **在用登记时机变化** → 由"解码成功"提前到"头部校验通过"；若 commit 最终降级，关闭时照常注销，不泄漏计数。
- **跨块崩溃前瞻** → 边界附近漏标/重复是主要风险；以"崩溃序列精确落在首块与稳态块边界"的生成样本反复验证"分块 ≡ 整份"。
- **流式解码改变校验顺序** → v1 的原有校验（魔数、版本、段长、总长、身份、字典 id 边界）全部保留，只是数据来源从整份切片改为"头部 + 文件长度 + 流式读取"。
- **后台落盘失败不可见** → 与 spec 一致（写入失败不影响装载），通过启动维护下次清理残留临时文件。

## Migration Plan

1. 先拆 workspace（D1），保持 `logcore.dll` 产物名与路径，跑通现有 Rust 与 C# 全量测试作为基线。
2. 再按序补解析差额（long → 时间戳校验 → 崩溃打标），每项先写"按基线必红"的 UT/IT 再转绿。
3. 分块渐进与段化列存落地，断言"分块 ≡ 整份"。
4. sidecar 写侧流式与后台落盘、临时名修正。
5. 读侧切到头部探测 + 装载期流式解码与降级收口。
6. 核对探索笔记 §5.4 第 4 条与 D6 的乙口径一致（笔记已定稿，不再改写）。
7. 回滚策略：全部为代码级改动，按提交回退即可；sidecar 字节格式未变，无数据迁移。
