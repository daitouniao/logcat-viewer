# Proposal

## Why

新 Avalonia 壳的设置层目前只是占位：只有语言与主题两键、非原子写、无版本号、失败无任何留痕；索引缓存放系统临时目录，被清理后重开大文件退化为全量解析。持久化是后续切片（过滤条件、窗口几何、最近文件等）都要落脚的横切面，先立骨架可避免每个切片各自发明落盘方式。

## What Changes

- 新增**可写根解析**：应用所在目录可写则用它，否则回退当前用户的应用数据目录，再否则仅本次运行有效；设置、诊断日志、索引缓存共用同一个解析结果。
- 设置文件补齐：schema 版本、原子写、容错读、单一写入入口；键面仍只有语言与主题。
- 新增最小**诊断日志**：随可写根落盘，单文件追加，达到 20 MB 上限时轮转保留一份旧档，写入失败不影响功能。
- 索引缓存目录从系统临时目录改为**持久化目录**；采集与暂存等临时产物仍留在系统临时目录。
- 语言设置保持独立：新壳只读写自己的设置文件，不读写旧查看器的语言配置。
- **BREAKING（仅内部）**：设置文件从无版本布局改为带版本布局。新壳尚未发布，无外部用户影响。
- **范围外**：过滤、标记、导出等业务功能；窗口几何、最近文件、字号、上次过滤条件等新键；改 core 的缓存行为与容量规则；发布链接入；旧查看器替换；旧设置与旧缓存的迁移。

## Capabilities

### New Capabilities

- `next/app-storage`: 新 UI 宿主的持久化行为契约——可写根的选择与回退、设置文件的版本与落盘语义、诊断日志、派生缓存目录的位置与降级、临时产物与持久化数据的分离。

### Modified Capabilities

- 无。core 的索引缓存行为契约（`logcore/source-acquire`）不改，本 change 只决定宿主把目录指到哪里；旧查看器的 `old/settings-storage` 不改。

## Impact

- 代码：`logcat-next/Next.App` 新增存储模块与设置/日志实现，替换现有设置存取；请求构造改传持久化缓存目录；`logcat-next/Next.Tests` 增相应测试。
- 依赖：无新增 NuGet 包。
- 构建 / 发布：不变。第一版仍不接发布链；运行时产物只落在构建输出目录（已被忽略）。
- 规范：新增 `next/app-storage`；`next` 分类已登记，无新增分类。
- 文档：若测试用例数变化，按既有口径同步测试文档中的数字。
