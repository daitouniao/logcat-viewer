# Proposal

## Why

安卓工具箱与日志查看器目前共用同一枚应用图标。两者常同时运行，被固定到 Windows 任务栏后，任务栏只显示图标不显示名称，两个按钮外观完全相同，用户无法判断哪个按钮打开哪个应用，只能靠悬停提示逐个试。

两者本就是两个独立应用（独立进程、独立配置、独立入口），外观标识应当与这一事实一致。

## What Changes

- 安卓工具箱改用专属应用图标：新增一枚与现有图标同族但主体符号不同的图标资源，只替换工具箱工程引用的图标。
- 日志查看器的图标保持不动，既不重做也不改名。
- 两个应用在系统外壳中的图标由此互不相同：任务栏（含已固定项）、标题栏、Alt-Tab 切换、大/小图标视图、资源管理器中的 exe 文件图标。
- 文档同步：两个 README 的仓库结构说明中「程序图标」的描述由「两个 exe 共用」改为两个图标；构建文档的发布校验增加「两 exe 图标须不同」一项。

### 非目标（out of scope）

- **不**改变任务栏分组行为：不引入显式 AppUserModelID，也不为两应用建立任何跨进程关联。两应用目前按 exe 路径分属两个任务栏按钮，本次不触碰。
- **不**修改窗口标题、产品名、应用显示名、进程名、可执行文件名。
- **不**重做或重命名日志查看器的现有图标资源。
- **不**新增安装器、快捷方式生成器或图标切换设置项。
- **不**引入仓库内的矢量源图 → ico 构建管线（仓库无图形工具链，本次只产出成品 ico）。
- **不**处理本次改动前已固定到任务栏的旧快捷方式的图标缓存刷新（系统行为，见 design 的 Context 说明）。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `android-toolbox`: 新增一条关于外观标识的需求——安卓工具箱在外壳中呈现的应用图标必须与日志查看器不同，使两者在任务栏等只显示图标的界面中可区分；同时约束该图标在各展示尺寸下可用、缺失时不得退化为系统默认空白图标。

## Impact

- 资源与工程配置：新增一枚 ico 资产；工具箱工程的图标引用指向新资产。日志查看器的工程配置不变。
- 分发：两个发布包各自包含两枚图标，产物文件构成不变，仅工具箱 exe 的内嵌图标改变。
- 用户可见行为：已固定到任务栏的**工具箱**按钮需取消固定后重新固定，才会显示新图标；查看器固定项不受影响。
- 既有决策：本次取代已归档的拆分决策「工具箱沿用同一枚应用图标」。该归档记录保持原样不改写，取代关系只在本 change 中记录。
- 无 API、数据模型、配置格式、依赖变化。
