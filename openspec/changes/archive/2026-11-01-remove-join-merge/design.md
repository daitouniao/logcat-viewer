# Design：删除「续行合并」（join）机制

## Context

现状索引以「逻辑事件」为单位：缩进续行被折叠进父记录（上限 200 行），为此索引层维护跨块 carry、批末状态缓存、末条滞后发布、c 轨批末补扫等一整套机制。探索笔记（`openspec/notes/REMOVE-JOIN-MERGE.md`）已完成全部决策收口（第 1–10 批 + §18 七件），本设计只记录实现层的取舍与依据。

关键事实（已代码级多轮复核）：

- 崩溃提取的 a 轨读的是**文件缓冲区的后续物理行**（本行 msg + 最多 3 次前瞻），不看 join 开关 ⇒ 删 join 后崩溃事件的识别、异常类型、包名、PID/TID 一律不变。
- flags 列在生产代码里只承载「多行」一个位，导出、崩溃汇总、摘要显示都不读它 ⇒ 整列删除无隐藏消费者。
- sidecar 尚未实现（全仓 0 命中），「9 段 → 8 段」只影响未来 sidecar 的列定义与体积公式，本 change 无实际落点。
- minute 类「无时间戳 ⇒ 分钟过滤不命中」契约已存在于 `time-column` 规范，本 change 不改它，仅适用集合从约 0.6% 变约 11%。

## Goals / Non-Goals

**Goals:**

- 索引口径改为自然行：除空行与横幅行外，每物理行各成一条记录；空行与横幅行的「不索引」语义保留。
- 一次清净合并机制及其全部派生入口、设置、UI、公开 API，不留半截（不留恒 false 的哑参数、不留 kill switch）。
- 变异测试防线同步重建：清 9 个失效锚点、修回 8 条已漂移的行号型锚点、补 2 个新锚点、runner 指向权威路径。

**Non-Goals:**

- 不实现 sidecar；不统一 Build / Append 两条扫描路径；不碰在途 `chunked-progressive-load` 的任何产物；不补完整元数据过滤规范；不做崩溃块补偿 UI。

## Decisions

### D1 索引口径：自然行，索引结构不进 spec

「记录 = 物理行」写入 design；spec 只承载可观测行为（message 匹配的物理行作用域、无元数据行的可见性）。理由：索引结构是实现细节（config 规范定位：specs 只写行为契约）；若未来出现内嵌换行的格式（如 DLT），另开 change 调整口径。

### D2 一次清净，不拆 change、不留哑参

`Join` 属性与 join 形参必须同批删除——留一半会出现「形参恒 false 但仍读属性」的隐式合并，行为与预期相反。不留紧急开关：留开关等于整套机制还得留着；回滚 = revert 一个 commit。分 4 段实施、每段一个 commit（每段结束可编译、测试无新增失败），缓解 review 压力。

### D3 崩溃提取：删 c 轨整段，a 轨直取

「崩溃头本身是上一条记录的缩进续行」这一形态，今天靠 c 轨批末补扫（依赖多行标志）兜底；删 join 后该行成为独立记录，a 轨直接命中，事件照常产生。c 轨整段删除，不再保留第二道保险；以一条专用测试钉死该形态（无头崩溃头 → 独立记录 + 事件照常识别 + 行锚 = 崩溃头行）。`CrashEvent.LineCount` 的唯一消费方是「+N 行」显示分支，随分支删除而无人读 ⇒ 彻底删字段，`Row` 注释改为「崩溃头所在行号」。

### D4 flags 列整列删除，信号位不预留

生产代码 flags 只有一个位在用，整列删。sidecar 定为 8 段 / 30 B/行（含时间戳 8 B + 偏移/长度/级别/pid/tid/tagId/分钟等列的口径）；不预留信号位——信号功能尚未立项，为一个未定需求付每行 1 B 不划算，需求立项时再设计。仓库内无外部消费者，公开 API `Flags` / `IsMultiline(row)` 一并删除。

### D5 保留项（易误删清单）

- 空行不索引、横幅行不索引两段分支：删 join 后改为不依赖合并状态的重置逻辑，单独标注并补 2 个变异锚点（空行分支恒不跳过 / 横幅分支恒不跳过），否则两条「不索引」路径零锚点守护。
- `LogParser.LooksLikeNewRecord`：保留公共 API 与测试（格式层能力）；加说明注释「删 join 后生产侧无调用点，保留供外部/未来使用」，不标 `[Obsolete]`（仓库无此先例，避免编译警告）。
- `FilterEngine` 块扫描上界依赖「最后一条记录的边界」，不依赖 join 语义，不动。
- 崩溃行「查看完整记录」入口保留（无头续行形态下详情只剩崩溃头一行，行为统一）。

### D6 导出与展示：删到底

导出恒为「一行一条」：删「单行化」菜单项（在设置菜单）+ 设置字段 + 导出行参数 + 文案键。Message 列删 `↵` 可视符处理（记录正文不再含换行，该设置失去唯一消费方）及其设置字段。带格式复制里的「摘要 → 原文」还原**不可整段删**，只删其中变死代码的换行替换部分。不做导出/展示的 spec 落点（规范面缺导出 capability 是既有状况，不在本 change 补）。

### D7 无元数据行契约：通用措辞，落 message-filter

一条需求，不逐类展开（不把 level 默认全选、pid/tid 排除模式保留等 UI 细节固化进 spec，脆且扩域）；排除模式视为反向命中自然保留，不单列。措辞禁用「缺失正文」——那是另一条既有需求（缺失正文 ≠ 无元数据，无头续行有正文）。minute 不复述（time-column 已覆盖）。Purpose 补一句「本能力同时覆盖元数据类过滤下的记录可见性口径」——delta 工具只合并需求块，Purpose 修订在归档 / sync 时手工补入。

### D8 验收基线与阈值（口径可验）

| 指标 | 阈值 / 方法 | 口径说明 |
| --- | --- | --- |
| 结构等式 | 自动化断言进 CI：记录数 == 物理行数 − 空行数 − 横幅数 | 独立计数法：物理行用逐行读取、空行按行首为空、横幅用解析器横幅判定；不用被测文档自己的列反推（自证无效） |
| 索引内存 | **索引列数组总量 ≤ 1.0 GB**（等价 ≤ 约 35.8 M 自然行） | 不写「进程峰值 < 1.0 GB」——整份构建现状 3.6 GB，写了就是假指标 |
| 索引耗时 | ≤ 删前基线 × 1.15 | 基线 = apply 第 1 任务删前同机同探针现测（各跑 3–5 轮取区间，阈值按区间上界 × 1.15）；跨探针跨条件的旧数字不可比 |
| 覆盖率 | 不低于当前基线（行 97.46% / 分支 88.67% / 方法 95.77%，以 `docs/TESTING.md` 为准） | 下降必须找出失去覆盖的路径并补上 |
| 变异测试 | 删前留基线报告；删后判「无新增 SKIP / 无新增 SURVIVED」 | 删码会使部分变异点随测试一起消失，无基线分不清「本来就该 SURVIVED」与「弄坏了断言」 |
| 1G 手测 | 专用探针（`.tmp-test/JoinBaselineProbe`，不入库）：列数组字节量（精确）+ 进程 Private 峰值增量 + 索引耗时 | 1G 样本用仓库脚本固定种子生成（可复现）；sidecar 体积只写推算公式（30 B/行 × 自然行数），标注「推算值，sidecar 未实现，未实测」；只与「整份」基线比，不与分块的 663 MB 比（不同口径） |

#### D8 删前基线实测（2026-10-31，worktree 内，样本固定种子）

- **样本**：`gen_test_log.py --size 1G` → 1,073,855,630 B（1.00 GiB），17,832,678 物理行；索引记录 15,823,120（88.7%，合并掉 11.3%，与 proposal 口径吻合）。
- **索引列数组字节量**：**613,177,613 B ≈ 584.8 MB**（9 列精确合计，5 轮一致；远低于 ≤ 1.0 GB 阈值）。删后推算：584.8 × (自然行数/15,823,120)，自然行数 ≈ 17,832,678 − 空行 − 横幅，预计 +11.3% ≈ 651 MB，仍 ≤ 1.0 GB。
- **索引耗时**：冷启轮 15.0 s；热轮 12.8–13.3 s（13,137 / 13,251 / 13,232 / 12,794 ms）。阈值（×1.15）：热轮 ≤ 15.3 s、冷启 ≤ 17.3 s。
- **进程 Private 峰值增量**：首轮（干净基线）**3,518.9 MB ≈ 3.5 GiB**，与既有「整份构建现状 3.6 GB」口径吻合；第 2–5 轮 63–1,050 MB 失真（前轮释放的堆不归还 OS、基线虚高），仅作参考。该指标为观察项，验收阈值落在列数组字节量上。
- **变异基线**：**KILLED=92 / SURVIVED=9 / SKIP=1 / 未跑完 3**（共 105；用户指示跳过，日志存 worktree `.tmp-test/mutation-log-baseline.txt`）。9 条 SURVIVED 全为已知等价/纯性能变异（FracToMs 补零、MessageBytes 边界、EnsureCap/SetColumns 性能、Reload 单测不可构造、TagIds 短路、FilterTail 边界、SpoolProgress 封顶、LooksLikeNewRecord TAB）；1 条 SKIP 为 MsgExclude 文本锚点漂移（块扫描重构所致），已修回锚点、本条基线值未测，删后对照时补验；未跑完 3 条（CommandStore ×2、TagOf 上界）删后按「无新增 SKIP / SURVIVED」判据重跑。

#### D8 删后实测与验收口径（2026-11-01）

- **1G 复测**（同一样本、同探针、5 轮）：记录数 **17,832,213**（物理行 17,832,678，索引率 99.997%）；列数组字节量 **637.8 MB**（668,738,670 B，5 轮一致，≤ 1.0 GB ✓，与推算 ≈651 MB 吻合）；索引热轮 **11.6–11.9 s**（冷启 15.2 s，≤ ×1.15 阈值 ✓，删后略快于删前 12.8–13.3 s：少了合并判定与 flags 写入）；进程 Private 峰值增量首轮 **4.4 GiB**（删前 3.5 GiB；差值来自扫描侧 List 的瞬时扩容开销，属观察项，验收阈值不在该指标上）。
- **覆盖率**（Debug + coverlet collector）：行 97.42%（3,663/3,760，未覆盖 98→**97**）；分支 88.75%（1,524/1,717，未覆盖 199→**193**）；方法 95.70%（401/419，判据「≥1 行命中」，未覆盖 18→**18**）。三项**未覆盖量全部不增**，百分比微降系删除已覆盖 join 代码（≈104 行）后的分母效应，判「无能力退化」达标。
- **测试**：`dotnet test` Debug **744/744** 全过（756 → 744：删 20 条 join 语义用例、新增 8 条真能力用例）。
- **变异删后对照**：**未跑（用户指示跳过，记待办）**；锚点已全绿校验（98 OK / 0 BAD / 0 SKIP，无副作用 dry-check）。补跑判据：无新增 SKIP / SURVIVED，SURVIVED 集 ⊆ 删前已知 9 条等价/性能项。

### D9 变异脚本修正（轻微扩域，纳入本 change）

- runner 路径改指仓库内权威位置（`.tmp-test/tstrun`）——当前脚本指向临时目录副本，与测试文档口径冲突，验收跑批必须用权威 runner。
- 修回 8 条已失效的行号型锚点（漂移发生在块扫描 feature 之后没人回核）+ 删码后按新行号再核对一遍（上界检查锚点必改、上限锚点随删而删）。
- 清理 9 个 join / singleLine 锚点（整条删除，文本型锚点删码后必然匹配 0 而静默跳过）。
- 同步更新审计文档（唯一订正行号的活文档；归档件与探索笔记是历史快照，不动）。

### D10 测试重整：按能力点，不机械补

删直接测 join 语义的约 22 条 + 顺带依赖 join 的约 13 条；「跨批 carry / 末条滞后发布」这类只在 join 语义下成立的能力点随语义消失，机械补「等价」测试补不出意义。只补四条真能力（新用例放现有按被测类分文件的测试文件里，与仓库风格一致）：

1. 自然行计数（含 D8 的结构等式断言）；
2. 空行与横幅行仍不索引；
3. 无元数据行在元数据过滤下的可见性（三态：启用不命中 / 排除保留 / 未启用照常可见）；
4. 无头崩溃头 → 独立记录 + 崩溃事件照常识别 + 行锚 = 崩溃头行（D3 钉死用例）。

### D11 README 与设置兼容

README ×2 在 change 内就删「续行合并」「单行化」提及——代码已删而 README 还在宣传属文档撒谎；不补「逐行展示」新特性行（README 描述当前版本该有什么，版本差异是发版说明的事）；测试数字 / 徽章按活文档口径与测试文档即时联动。老 `settings.json` 的 `join` 等未知键：序列化器默认忽略，不会加载失败，下次保存自动抹掉，无兼容负担。

## Risks / Trade-offs

- [记录数 / sidecar 体积 / 内存 +11.3%]（已确认接受）→ 验收基线写明；sidecar 的 LRU 上限与降级策略兜底。
- [约 11% 无元数据行在显式启用元数据过滤时静默消失]（已确认接受，实际影响面小于原估）→ 范围写进 spec；不加用户可见提示（成本高于收益）。
- [误删空行 / 横幅「不索引」语义] → 必留清单（D5）+ 2 个新变异锚点 + 专用测试用例。
- [`Reload(join:)` 漏改 → 隐式恒 true 合并] → 属性与形参同批删（D2），编译期即可发现。
- [变异锚点静默失效] → D9：基线 + 修回 + 删码后重核。
- [行号语义漂移（崩溃行锚、标记列、崩溃汇总首末定位）；行号基数 +11.3%] → 崩溃汇总锚点恒为崩溃头行；等价性测试重建期望。
- [覆盖率净效果未知（删的代码大多被测过，分子分母同减）] → D8 闸门：不低于基线，下降必须归因。

## Migration Plan

1. apply 第 1 任务（改码之前）：worktree 就绪后，用专用探针 + 变异脚本取得删前三类基线（耗时 / 内存 / 变异），回填本文件与验收记录。
2. 按 tasks 分 4 段实施，每段结束可编译、`dotnet test` 无新增失败、单独 commit（commit 需当轮授权）。
3. 全量验收（D8 全表 + UI 手工验收项）→ 用户验收。
4. 归档：delta 并入主规范（含手工补 Purpose 一句）、探索笔记同批归档、worktree 同批清除。
5. 回滚策略：无 kill switch，出问题 revert 对应 commit。
