# Proposal: fix-chunked-tail-loss

## Why

本地文件分块渐进加载完成后，仍滞留在 100 ms 节流窗口内未上屏的内容被永久丢弃：加载结束即停掉上屏定时器，没有「最终整批发布」。真实窗体实测：0.5 / 4 MB 文件视图 **100 % 空白**，36.56 MB（636,335 行）只显示 69,841 行（缺失 89 %），状态栏也停在最后一次节流快照——用户连「文档共有多少行」都看不到。这是违反 `chunked-file-load` spec（「加载完成状态一致」「加载完成无内容滞留」）的实现缺陷，不是设计缺口；且现有测试只覆盖了节流缓冲本身，未覆盖生产收尾路径，缺陷因此通过了归档验收。探索结论见 `openspec/notes/CHUNKED-TAIL-LOSS.md`（根因已在真实窗体上复现并经对照实验闭环）。

## What Changes

- 加载完成后补「最终整批发布」：停掉节流定时器前/后，把缓冲内所有未上屏的发布操作无条件取走并按序上屏，保证视图最终行数与文档行数一致（含 ≤ 首块的小文件场景——当前 100 % 空白的档位）。
- 加载完成后刷新一次状态栏统计，消除「总/命中停留在中途快照」的误导（≤4 MB 时状态栏全空）。
- 修复语义对齐 spec 既有承诺（候选甲），不引入加载期全量重过滤（候选乙已否决：与「加载期已增量构建、无需全量重过滤」的既有设计冲突，且大文件多一次全量过滤开销）。
- 新增「生产收尾路径」自动化断言：加载完成后视图行数 == 文档行数（本地路径），样本取首块以内的小文件即可钉住 100 % 空白档位；STA + 消息泵下运行。
- spec delta：将「加载完成时缓冲内暂存内容全部上屏、状态栏反映最终统计」固化为行为需求，防止回归。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `chunked-file-load`: 强化「已发布前缀稳定」中「加载完成无内容滞留」场景——滞留不仅指解析未发布，也包括已进入发布节流缓冲但未上屏的内容；加载完成时 SHALL 全部可见。另新增「加载完成后状态栏统计反映最终值」需求。

## Impact

- **代码**：`frmMain.Load.cs` 的加载收尾分支（`finally` 内补强制消费入口）与状态栏刷新；预计改动集中在单文件、小体量。其余加载路径（代理、ADB 采集、Reload、实时增量）均已有全量上屏兜底，不受影响、不改。
- **spec**：`openspec/specs/chunked-file-load/spec.md` 增补一处场景强化 + 一条新需求（delta 形式）。
- **测试**：新增生产收尾路径断言（真实窗体 + STA 消息泵范式，沿用 `frmMainTests` 既有手法）；现有测试不受影响。
- **非目标（out of scope）**：
  - 不改代理路径、ADB 实时采集、Reload、实时增量同步的上屏机制。
  - 不做 `SIDECAR-CACHE-INDEX` 的 sidecar 接入点改造（经核对，sidecar 尚无任何实现代码；若其未来复用本地分块加载路径，将自动受益于本修复，届时另核）。
  - 不调整节流窗口时长、块长等加载参数。
  - 不改状态栏其他展示逻辑。
