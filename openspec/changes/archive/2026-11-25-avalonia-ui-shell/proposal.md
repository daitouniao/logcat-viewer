# Proposal

## Why

旧的 `logcat-viewer` 里两件事已到维护瓶颈、且不是靠修补能解决的：界面文案以中文原文为键、漏译静默回退，运行时切语言要靠遍历控件树；配色没有主题层，级别色、标记底、过滤框着色都是浅色字面量，昼夜切换必须逐控件手写。现在 core 已经能通过 `logcore.dll` 端到端提供装载与分页数据，具备另起一个 UI 宿主的前提；此时新建工程，才能把这两件事从「手写补丁」改成「框架原生机制」。

## What Changes

- 新增独立 Avalonia UI 工程（暂名 `logcat-next/`），不迁移、不改动既有 `logcat-viewer` 与 `logcat-uicore`，两套并行发布。
- 新 UI 只经既有 C ABI（`logcore.dll`）取数，不引用旧 C# 引擎；互操作层在新工程内重建。
- 建立语义色 token 层：明暗两套主题，切换即时生效，自绘列表随主题重绘。
- 建立稳定键本地化目录：中英双语，运行时切换即时刷新；缺键、缺占位符由测试报红，不再静默回退。
- 建立大列表虚拟渲染：只渲染视口行，分页数据与滚动位置在主题 / 语言切换后保持一致。
- 第一版为**最小验证壳**：只验证「大列表渲染、主题切换、双语切换」三件事，不实现过滤、标记、导出、ADB 等业务功能。

**范围外（out of scope）：**

- 不迁移旧 viewer 的任何界面或业务代码；不改旧工程的本地化、配色与发布链。
- 不实现过滤、标记与标记跳转、导出、ADB 采集、设备工具箱、崩溃聚合。
- 不解析日志格式、不建索引：解析与分页由 `logcore` 承担，本 change 只消费。
- 不做设置持久化的完整方案（第一版可只保留主题与语言两项）。
- 不改 `crates/`，不改 C ABI，不做打包与发版脚本。
- 不做旧 viewer 到新 UI 的切换方案（何时替换、如何回退另立 change）。

## Capabilities

### New Capabilities

- `next/ui-theme`: 明暗主题与语义色契约——主题三态、切换即时生效、可见区域无「半深半浅」、领域色（日志级别、标记、过滤输入提示）在两套主题下可读。
- `next/ui-localization`: 界面语言切换契约——中英双语、运行时切换即时刷新、启动语言来源、缺译不得呈现空白或占位符。命名避开既有 `old/ui-language`（规范分层：同一 capability 名不得跨分类并存）。
- `next/log-view-rendering`: 大列表虚拟渲染契约——只渲染视口、分页数据正确、主题与语言变化后行外观同步刷新、千万行级可用。

### Modified Capabilities

- 无。旧 `old/ui-language` 继续描述旧查看器行为，本 change 不改动其契约。

## Impact

- 代码：新增 `logcat-next/` 下的互操作、UI 壳与测试工程；`crates/`、`logcat-viewer/`、`logcat-uicore/` 零改动。
- 依赖：新增 Avalonia UI 依赖；沿用既有 `.NET 10` 目标框架。
- 构建 / 发布：新工程独立构建，第一版不接入现有双包发布链。
- 规范：新增 `openspec/specs/next/` 分类（已在 `config.yaml` 登记），不再新增 `old/` 内容。
- 文档：`docs/TESTING.md` 的用例口径待新工程测试落地后同步。
