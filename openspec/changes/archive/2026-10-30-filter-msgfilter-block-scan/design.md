# Design

关联探索笔记：`openspec/notes/UTF8-BYTE-SIMD-SEARCH.md`（决策 Q1=A / Q2 已随零拷贝落地 / Q3=A / Q4 非目标清单；探针数据 §7.2）。本文所有性能数字均出自该笔记，不重复论证。

## 总体结构

`MsgFilter` 保持签名不变，内部改为两层：

1. **分派层**：按阈值决定走「逐行匹配」（现状路径，原样保留）或「块扫描」。
2. **块扫描层**：原始 mmap 字节上的分块并行扫描 → 命中点 → 行归属与 message 段边界复核 → 与候选行集合求交 → 按组合/排除语义产出结果。

`FilterTail`（增量过滤）不接入块扫描：增量覆盖行数少，逐行路径已是最优，且增量行不属于「文档前缀之外的区域」，块扫描整文档语义不适配。分派只在全量 `MsgFilter` 内做。

## 关键决策

### D1 分派：文档规模 + 候选占比 + 关键词可用性三条件

- 块扫描判全体行、再与候选求交；候选极少时逐行更便宜。走块扫描需**同时**满足：
  - 行数 ≥ `BLOCK_SCAN_MIN_ROWS`（初值 200 万，探针文件 1582 万行、块开销摊薄后收益显著）；
  - 候选数 > 行数 / 8（候选占比过低时逐行胜出）；
  - 关键词全部为 ASCII 字节，且关键词数 ≤ `BLOCK_SCAN_MAX_KEYS`（初值 8）——多关键词每词一轮的串行轮次成本按词数线性增长，超限时回退逐行以免慢于现状（见 D2）。
- 任一条件不满足直接走逐行：小文件固定开销（并行调度、指针获取、二分复核）不划算，探索笔记 §5 已指认；关键词条件不足时块扫描的轮次成本反超。
- 常量定义为常量并配注释指向探针数据，不做配置项（避免 UI/设置面扩大，超出 Q3=A 边界）。
- **2026-10-29 用户授权（决策 5）**：tasks 4.1 基准标定后，可直接调整本组常量（行数阈值、候选占比、块大小、并行度上限、关键词数上限）并注明依据，**不再回评审**。
- **授权边界（2026-10-29 决策 6=①）**：只有常量在授权内。若实现或基准暴露出需要改**结构**的问题——两轮扫描必须合并、行归属范式变更、分派条件增删、合并层语义调整——一律停下回评审，不在 apply 内自行决定。

### D2 扫描形态：Parallel 分块 + 重叠 ndLen-1 + 行首归属

- 沿用探索笔记 §7.2 探针验证过的目标形态：`Parallel.For` 按固定块（约 16–64 MB，实现时以探针量级为起点）切分 mmap 视图字节区间。
- **并行度上限（2026-10-29 决策 4=②）**：`ParallelOptions.MaxDegreeOfParallelism = min(Environment.ProcessorCount, BLOCK_SCAN_MAX_DOP)`，`BLOCK_SCAN_MAX_DOP` 初值 16。依据：探针所在 72 逻辑核机器上 CS 并行仅 ~3.5×，收益受内存带宽墙限制，线程继续增多无收益且会抢占 UI 线程 / 磁盘 IO。该上限随 D1 常量一并由基准标定。
- 块区间向尾部重叠 `最长关键词字节数 - 1`，防止跨块关键词漏配；多个关键词取最大长度。
- **行归属唯一性**沿用仓库既有范式：命中点映射到「行首落在本块 `[rawStart, rawEnd)`」的记录；重叠区只用于把命中点所在行读完整，不重复产出。命中点 → 行号用 `Offs` 二分（`Moff`/`Lens` 复核命中是否落在 `[offs+moff, offs+lens)` 内，探索笔记 §4.3）。
- 头部命中（时间戳/tag 区）在段边界复核时天然剔除，不产生误报。
- 多关键词（2026-10-29 决策 1=②）：每关键词独立一轮块扫描，命中行号集合在归属层按 and/or 语义合并（and = 各关键词命中集合的交集对应的候选行；or = 并集）。轮次成本按词数线性增长，故由 D1 的 `BLOCK_SCAN_MAX_KEYS` 兜住——超限整体回退逐行，避免「词多时块扫描反而慢于现状」。块内多模式匹配（首字节集合 `IndexOfAny` 预筛 + 逐点验证）列为非目标，不预付复杂度。

### D3 大小写不敏感：复用既有 CI 算法口径 + 非 ASCII 行回退 + 非 ASCII 词整体回退

- CS 路径：原始字节 `IndexOf(needle)` 与现状逐行 `MatchAny` 语义完全一致，无需特殊处理。
- CI 路径：块级扫描复用 `ContainsAsciiInsensitive` 的算法口径——首字节大小写两态 `IndexOfAny` 候选定位 + 逐字节验证（D2 已定并随零拷贝落地）；SIMD 化采用探针 CI-Simd 形态（`Vector256` 两态等值 + `MoveMask` 提取候选），验证仍逐字节。
- **完备性红线（探索笔记 §4.2 实测教训）**：CI 块扫描只对「纯 ASCII 行」的判定有权威性。含 ≥0x80 字节的行必须回退既有 `MatchFolded`（整行 Unicode 折叠）路径——`İ`（U+0130）小写化会产生 ASCII `i`，原始字节扫描找不到这类命中；ß/ẞ 等宽度变化规则同理。实现方式：块扫描同轮顺带记录含 ≥0x80 字节的行（对 ASCII needle 之外，再对 `0x80` 单字节做一轮 `IndexOfAny` 定位），这些行全部交给逐行折叠路径判定，两侧结论合并。判定标准（笔记 §8「行号集合完全一致」）即由此保证。
- **额外一轮扫描的成本已接受（2026-10-29 决策 3=①）**：CI 路径固定多一趟全文档 `≥0x80` 定位（约 +100–170 ms / 1 GB），不合并进 needle 扫描循环（合并会失去 `Span.IndexOfAny` 的现成向量化）。因此基准须单列「CI 含非 ASCII 回退轮」的数字，验收不得直接对 133–151 ms 的探针值。
- **含非 ASCII 字节的过滤词：整体回退（2026-10-29 决策 2=①）**：spec 中任一关键词含 ≥0x80 字节时，本次过滤整体走逐行路径，不做「块扫描 + 逐行补齐」。理由：and 语义下补齐等于对全部候选行再跑一遍逐行，块扫描收益归零却仍付并行调度与复核开销；or 语义下同样需要各关键词结论齐备。现状 `keyAscii` 判定在逐行路径内原样保留。

### D4 空 needle / and / or / exclude 语义在合并层保持

- 空 needle：or 模式整体立即成立（全部候选命中）、and 模式跳过该词——与 `MatchAny` 现状一致，在块扫描结果合并前单独短路，不进扫描。
- exclude：命中集合求反的口径与现状 `ok != exclude` 完全一致，只作用于最终合并结果。
- 无正文记录（message 段空）：CS 下不可能命中；exclude 模式视为未命中保留——沿用现状，无需特判（段边界复核对空区间恒为不命中）。

### D5 指针与生命周期：复用 MessageSession，一次 Acquire 全程

- 块扫描在 `doc.OpenMessageSession()` 会话的指针上进行（`ptr + PointerOffset` 为数据起点、`Capacity` 为有效长度，与既有 `LineIndexProbe`/零拷贝口径一致）；并行块共享同一次 Acquire，只读访问。
- 块扫描期间映射被 `Close`/重映射置换属误用，护栏与现状会话相同（span 只在语句内消费的约束改为「块区间边界在 Acquire 时快照」）。`Append` 触发重映射的竞态由「过滤开始前取 `Capacity` 快照」消解——扫描只读快照范围，行索引列（`Offs` 等）在过滤全程有效（现状同样假设）。

### D6 取消与进度

- 取消：块间检查 `ct`（`Parallel` 用 `ParallelOptions.CancellationToken`），粒度与现状批次一致。
- 进度（2026-10-29 决策 7=①）：块扫描内部按已完成字节占比推进，但**对外上报值仍换算为「已完成行数估计」**，沿用现有键 `匹配 message {0}/{1}`（`LocTable.RuntimeMsg.cs`）；`ApplyFilter` 传入的 Progress 包装与 0.35–1.0 段映射不动，**不新增本地化键**（中英表零改动）。行数估计取「已扫描字节对应的 `Offs` 二分位置」，保证 x/y 单调且 y = 候选行总数。

## 验收口径

- **性能门槛分机器档（2026-10-29 决策 6=③）**：探针数据出自 72 逻辑核机器，不能外推到常见机器，故按核数分档：
  - 多核档（逻辑核 ≥ 16）：1 GB 热缓存 CI 全量 message 过滤 ≥ **5×**（对照现状 945–1270 ms），200 MB 热缓存 ≥ **2×**；
  - 普通档（逻辑核 4–8）：只要求「有可测量下降且不劣化」，不设倍数门槛。
- **本机只跑多核档 + 普通档永不补测（2026-10-29 决策 1=①、3=①）**：基准仅在本机（72 逻辑核）实测，普通档结论标注「未验证」即**终态**，不作为发版阻塞项，README / 发版说明也不承诺 4–8 核收益；**不用限核模拟替代**（`MaxDegreeOfParallelism` 限核改变不了内存带宽与磁盘路径，模拟数字不可信）。不排后续补测计划。
- **高频短词必须进基准（2026-10-29 决策 2=①）**：除 1/3/10 个正常长度关键词外，另设短词组（`1` / `:` / `error` 类），用于暴露「头部区命中点多、复核成本高」这一无数据支撑的风险。短词组若出现劣化，按决策 6=① 回评审，不得自行改结构。**具体词清单由 tasks 4.1 自行选定并记录**（决策 4）。
- 两档共同要求：结果集与逐行路径逐位一致（spec 契约）；冷缓存不劣化。核数与档位在基准记录中写明。
- **大文档等价性验证：不做测试，只做一次手工比对（2026-10-29 三轮决策 2）**：不新增集成测试、不改测试工程与 `docs/TESTING.md` 命令口径；双路径命中集合一致性由 tasks 4.1 基准任务在真实大文档（≥200 MB，复用基准文件）上手工执行一次并记录结果。常规 `dotnet test` 不含超大文档用例。
- **实测结论与门槛处置（2026-10-30 用户拍板「接受现状」）**：等价性达标（200 MB / 1 GB 各 10 组用例命中集合逐位一致，含 12.2 M 行命中集合）；性能门槛**未达成**——1 GB CI 1.49×（门槛 ≥5×）、200 MB CI 1.88×（门槛 ≥2×），CS 场景 1.5–2.9× 稳定正收益，短同义词与多词 `and` 场景与现状持平（0.92–1.01×，不劣化）。主因：非 ASCII 行折叠回退按 D3 红线必付（8 % 中文行时 1 GB 约 1.1 M 行 × ~0.3 µs ≈ 340 ms）、短词逐条路径本就便宜、多词 `and` 逐条路径提前退出。处置：**不改口径、不改结构，如实记录并交付；发版说明与 README 不承诺任何倍数收益**。上面「性能门槛分机器档」一节因此仅作设计期目标留档，不再是验收判据。

## 风险与对策

- **多轮扫描在多关键词下的退化**（D2）：已由 D1 的 `BLOCK_SCAN_MAX_KEYS` 上限兜住（超限回退逐行），基准任务仍覆盖 1/3/10 个关键词用于标定该常量；不预先设计多模式匹配（探索笔记 §4.1：字节域无多子串 SIMD 重载，任何多模式方案都是自建，复杂度不值得预付）。
- **冷缓存**：顺序整文档读对冷缓存友好（随机小读是现状路径的劣势项）；基准任务记录冷/热两组数字对照「冷缓存不劣化」判定标准。
- **非法 UTF-8**：字节扫描可能造出假命中，但段边界复核 + 命中行复核（CI 路径逐字节验证、非 ASCII 行折叠路径）自然消解，与现状「显示型工具可接受」口径一致。
