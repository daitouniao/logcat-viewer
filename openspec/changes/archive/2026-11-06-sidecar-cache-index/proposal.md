# Proposal

## Why

重开一个已解析过的大文件时，全量解析（扫描 + 八列物化 + 崩溃事件）耗时 12–18 s（1 GB 样本实测 14.8 s），期间界面无内容。解析结果本身是确定性的——同一文件重复解析纯属浪费，应把建好的列式索引落盘复用，将重开耗时压到亚秒级（探针实测 459 ms，≈32×）。

## What Changes

- 新增 sidecar 索引缓存：首次静态文件解析完成后，将列式索引（8 段 SoA + 三字典 + 崩溃事件）异步落盘到 exe 同级 `cache/` 子目录；退出不等待写入。
- 新增 sidecar 命中路径：重开同一本地文件时校验缓存身份（源路径派生名 + `size` + `mtime` + 首尾各 64 KB 哈希），命中则直接加载索引装配文档并全量过滤，**绕过**分块渐进加载编排，一次到位。
- 新增失效与容量治理：缓存身份任一项变化即重建；单 sidecar 上限 1 GB，缓存目录总量 LRU 淘汰；单份超上限不落盘。
- 新增静默降级：缓存缺失 / 损坏 / 版本不识别 / 目录不可写 / 文件非静态（增长中、采集、代理 spool）一律静默走原加载路径，不弹提示、不加开关，仅启动日志留痕。
- **等价性不变量**：sidecar 命中路径产出的文档与从零解析完全一致（行数、8 列、三字典、崩溃事件、自然行边界），作为可自动化断言的不变量。

### 非目标（Out of Scope）

- 过滤加速（另立 change）。
- 流式 / 首屏加载——已由 `chunked-file-load` 承接，本 change 不改其行为。
- 改列布局、改解析管线形态、改 UI、删除 join（已另立归档）。
- 缓存命中路径的渐进发布与节流上屏（命中装载亚秒级，用不上）。

## Capabilities

### New Capabilities

- `sidecar-index-cache`: 已解析索引的落盘缓存行为契约——缓存身份与失效判定、命中重开与结果等价性、容量上限与 LRU 淘汰、静态文件边界、静默降级。

### Modified Capabilities

（无——`chunked-file-load` 的既有需求不变，命中路径在其编排之外独立分流。）

## Impact

- **代码**：`Services/LogDocument.cs`（新增 internal 装载入口，复用 private `SetColumns`；仿既有 `BuildChunkedCore` internal static 范式）、`frmMain.cs` `StartIndex` 本地文件分支（编排启动前分流命中判定）、新增 sidecar 读写器（全仓库现无二进制读写器 / 压缩，需从零实现，可参照 mmap / FileStream 落盘 / JSON 持久化既有范式）。
- **数据**：exe 同级新增 `cache/` 目录，与既有 `Log/`、`temp/` 惯例一致；sidecar 不含文本本体（文本仍在源文件 mmap）。
- **性能**：1 GB / 15.8M 行样本重开从 14.8 s 降至约 0.5 s 装载 + 全量过滤；首次解析路径不劣于现状。
- **测试**：新增等价性对比、失效重建、降级、容量淘汰等用例；`dotnet test` 口径报数。
