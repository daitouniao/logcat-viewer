# Design

## Context

动机见 proposal.md（Why）。当前代码事实（2026-11-04 复核，详见探索笔记 `openspec/notes/SIDECAR-CACHE-INDEX.md`）：

- 列布局 = 8 段 SoA（`offs`/`lens`/`moff`/`min`/`pid`/`tid`/`lvl`/`tagId`），flags 列已随 join 删除移除；三字典（Tag/ExcType/Pkg 的 `List<string>` + `Dictionary<string,int>`）与崩溃事件表（6 字段）构成索引的全部派生数据。
- 文本本体在源文件 mmap，索引不含文本——命中路径只跳过扫描与物化，mmap 仍须打开。
- 全仓库无二进制读写器、无压缩用法；既有持久化范式：mmap（`OpenMap`）、`FileStream` 落盘、JSON 设置持久化。
- 本地文件入口 `StartIndex` 分流到分块编排（`RunChunkedLoadAsync`）；代理与 adb 采集是另外两条独立入口。
- 装配收敛先例：`BuildChunkedCore`（internal static）、`MergePart`（internal），测试经 `InternalsVisibleTo` 直测；列填充由 private `SetColumns` 完成。

## Goals / Non-Goals

**Goals:**

- 命中重开装载 ≤ 600 ms（1 GB / 千万行量级，验收只约束装载段，不含其后的全量过滤）。验收以绝对时长为准，不设随机器漂移的比例式验收线。
- 命中结果与全量解析完全等价（spec 不变量）。
- 首次解析路径不劣于现状。

**Non-Goals:**

- 过滤加速（另立 change）；渐进首屏（`chunked-file-load` 已承接，本 change 不改其行为）。
- 缓存命中路径的渐进发布 / 节流 / 加载期过滤增量——命中装载亚秒级，这些机制用不上。
- 跨版本缓存格式迁移：版本不识别即整份丢弃重建，不做向后兼容读取。

## Decisions

### D1. 落盘位置：exe 同级子目录 `cache/`

替代方案：源文件旁（SMB/只读介质不可行）、用户 AppData（同盘异地，失去「与源同生」语义且难做总量治理）。选 exe 同级：与既有 `Log/`、`temp/` 惯例一致；源文件在 SMB 时索引落在本地盘，重开才能保持亚秒。目录不可写 → 静默停用缓存功能。

### D2. 缓存键与身份摘要

文件名 = 源路径哈希 + 可读前缀（**不落本机绝对路径明文**——公开仓库红线，产物与落盘数据均不得暴露用户路径/用户名）。身份摘要 = `size` + `mtime` + 首尾各 64 KB 内容指纹，写入 sidecar 头部；打开时重算比对，任一不匹配即失效。

理由：FAT32/exFAT 的 mtime 精度低（2 s 级），就地改写可能不动 size/mtime，首尾哈希兜底覆盖最常见的追加与头部改写；64 KB 折中哈希成本与覆盖面。替代：全文件哈希（GB 级文件重开时自身就是秒级开销，否决）。

同内容多副本按路径各自独立建条目，不做内容寻址去重——重复占用由目录总量触发线与 LRU 兜底；内容寻址去重复杂度高且改变身份校验语义，否决。

### D3. 落盘格式：8 段 SoA 原始字节 + 头部，不压缩

头部：magic + 格式版本 + 8 段元素宽度 + 行数 + 各段期望长度与总长 + 身份摘要 + 三字典（文本 + 索引）+ 崩溃事件表（6 字段）。数据区：8 段变长段顺序排布，段内定长原始字节。

加载 = 顺序读直接填入现成 8 个数组，零转换。替代方案：压缩（Brotli/Deflate）——省空间但增加装载耗时与依赖面，索引体积已有 1 GB 上限与 LRU 兜底，否决；AoS 快照（逐记录结构体数组）——装载需逐条拆解回 SoA，转换开销违背亚秒目标，否决。体积公式：行数 × 30 B（8 段定宽合计），落盘前据此预判。

### D4. 装配入口：`LogDocument` 新增 internal 装载方法（仿 `BuildChunkedCore` 范式）

列字段与 `SetColumns` 均为类内 private，外部（含 `InternalsVisibleTo` 程序集）无法触达——friend 装配器路线需反射，排除。新增 `internal` 装载入口落在 `LogDocument` 类内，由其调用 `SetColumns` 完成八列填充并恢复三字典与崩溃事件；命中分支只调该入口。这是仓库现成范式（`BuildChunkedCore` L422 / `MergePart` L929），不发明新模式，且装配逻辑与数据同域，天然满足等价性验收。

### D5. 接入点：`StartIndex` 本地文件分支在编排启动前分流，命中绕过分块编排

命中路径：读 sidecar → internal 装载 → `OpenMap()` + `IndexedSize` 对齐 → 按当前条件全量过滤。不进 `RunChunkedLoadAsync`。

理由：命中装载实测 459 ms，渐进首屏 / 100 ms 节流 / 加载期过滤增量全为「边解析边上屏」服务，对命中路径无增益；绕开编排除装载外需显式全量过滤（千万行量级为秒级），验收线仅约束装载段。替代：命中也走编排（把索引当「第 0 块」发布）——需为一次性 459 ms 装载维护节流与增量过滤语义，复杂度无回报，否决。

代理与 adb 采集路径**不接入**命中（属非静态文件边界，见 D7）。

### D6. 原子写与多实例并发：临时文件 + 原子替换，无锁

后台线程先写 `cache/` 内临时文件，成功后原子替换（`File.Move(overwrite)` / `File.Replace`）到正式名。两个实例各写各的临时文件后替换，后写者胜，无需进程间锁——替换是原子的，任何时刻正式名下都是完整文件。头部位记录各段期望长度与总长，装载时长度/版本不符即整份丢弃重建。

### D7. 静态文件边界：构建前后两次取样 + 入口显式排除

只有静态文件落盘：解析开始与结束各取一次 `size`+`mtime`，不一致即放弃；代理 spool 路径与 adb 采集增长文件在入口处显式排除（这两条入口本就不经 `StartIndex` 本地分支，天然隔离，但代码上仍显式标注，防未来重构误接）。

### D8. 异步落盘：索引建完即返回，退出不等待，失败静默

解析完成、界面可用后由后台线程落盘，失败（磁盘满、权限、IO 异常）一律静默吞掉并留启动日志；程序退出不等落盘线程。临时文件 + 原子替换保证任何中断不产生半截正式缓存。

### D9. 容量治理：单份 1 GB 上限 + 目录 4 GB 触发线 LRU，以条目自身文件时间做「最近使用」

单份上限按「行数 × 30 B」预判，超限直接不写。目录总量触发线定为固定值 **4 GB**（简单可测；替代的按剩余磁盘百分比、「装不下才淘汰」两案已否决）。目录超限时按条目文件的最近使用时间从旧到新淘汰，直至容纳新条目；新条目必留。命中装载时刷新条目文件的访问时间（`LastAccessTime`）作为「最近使用」标记——零额外状态文件；访问时间不可靠的场景（noatime 等挂载）以条目修改时间参与排序兜底，仍不新增状态文件。淘汰跳过当前会话正在使用的条目（进程内存持引用计数即可）。

### D10. 降级静默：一切异常走原路径

缓存缺失 / 损坏 / 版本不识别 / 目录不可写 / 装载中途异常 → 捕获后走既有 `RunChunkedLoadAsync` 全量路径，不弹提示、不加开关；现状 `StartIndex` 失败分支是弹错误框，命中路径不得复用该分支，需独立静默分支。降级事件写 `startup.log`。

## Risks / Trade-offs

- [mtime 精度不足漏检就地改写] → 首尾 64 KB 哈希兜底；残余风险是文件中段改写且 size/mtime 不变，接受（对日志文件场景概率极低）。
- [命中后全量过滤秒级，用户感知为「重开变快但没到亚秒」] → 验收线明确只约束装载段；过滤加速属另立 change，proposal 已列为非目标。
- [替换瞬间两实例并发写同一正式名] → 原子替换语义下后写者胜，双方文件各自完整，无损坏窗口；`File.Replace` 在目标不存在时抛异常的边界需在实现时覆盖（先探测后替换）。
- [LRU 依赖 `LastAccessTime`，部分文件系统（挂载选项 noatime）不更新] → 已拍板：访问时间不可靠时以条目修改时间参与排序兜底（D9），不新增状态文件。
- [sidecar 落盘将索引体积镜像到磁盘（最大 1 GB/份）] → LRU 上限治理；不压缩是为亚秒装载支付的明确代价（体积换时间），已在 D3 权衡。

## Migration Plan

纯增量功能，无存量数据迁移。旧版本程序产生的 `cache/` 目录对新版本无影响（版本不识别即重建）；新版本回退旧版本时，旧程序不读 `cache/` 目录，需用户手动删除（或保留无害）。
