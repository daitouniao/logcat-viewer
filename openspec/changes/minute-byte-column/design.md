# Design

## Context

动机见 proposal.md - Why。现状要点（本 design 的直接对象）：

- 列存储为「定长列（内存）+ mmap 文本本体（磁盘）」结构；`_ts` 为 `long[]`，8 B/row，由 `FinalizeTs` 从扫描期的 `within`（年内毫秒，闰年日序编码）+ 行内年份 + 跨年回退检测 + `YearTables` 查表终算。
- `_ts` 的生产消费仅三处：分钟过滤（每行）、frmMain 右键「按此分钟过滤」（单行）、`CrashEvent.Ts`（稀疏，供聚合排序与两处 UI 显示）。`NearestPos` / `TsFromParts` / `HasYear` 无生产调用方（仅测试）。
- Time 列显示本来就走 `HeaderBytes`（mmap 行首原始字节），`TsToText` 仅是方括号 long 格式行（`HeaderBytes` 不识别 `[ ` 前缀）的兜底。
- 约束：后台 Reload / Append 与 UI 渲染并发（列存储沿用「引用整体替换、不原位改」模式）；测试唯一口径为 tstrun 反射 runner；公开 API 可破（应用非库，无仓库外消费方）。

## Goals / Non-Goals

**Goals:**

- 分钟 byte 列替代绝对毫秒列，分钟过滤语义严格等价（`s=60` 一处显式修正，见 D3）。
- 删除年份机制全家：`FinalizeTs`（跨年检测 / 绝对年份推算）、`GuessYear`、`YearTables` 及静态缓存、`_yearLast` / `_withinLast` 跨批缓存；`ScanRange` 停止收集 `within` / `years` 临时列。
- 崩溃侧放弃绝对时间戳：组排序改首次行号、组内末次改行序最后、时间文本改行首原文（见 D4）。
- `-v long` 方括号行 Time 列显示修复（`[ ` 前缀识别，见 D5）。

**Non-Goals:**

- 不实现小时 / 日期过滤（预留路径：未来各加一列 byte，本 change 不碰）。
- 不动列存储整体架构与其他列（`offs` / `pid` / `tid` / `tagId` 等）的表示。
- 不动 fileproxy 能力；不新增依赖；不改 UI 交互（仅上述显示修复）。

## Decisions

### D1：分钟值取自解析器已有字段，经解析结果透传

三条时间解析路径（`mm-dd` 快路、`yyyy-mm-dd` 快路、方括号正则慢路）内部本已算出分钟；解析结果结构加一个分钟字段透出即可，扫描期零新增计算。备选：列存储侧从 `within` 反解 `(within/60000)%60`——丢弃已算出的字段再算一遍，且给删除 `within` 收集制造依赖，否。

### D2：分钟列用 byte，无时间行哨兵 255

分钟 0-59 占一个字节；无有效时间戳的行存 255。分钟集合只含 0-59，哨兵天然不命中，过滤处省去原 `ts < 0` 分支。备选：sbyte 存 -1——需符号处理且集合判定要额外排除负值，哨兵方案与集合成员判定完全同构，取哨兵。

### D3：等价性论证与 `s=60` 显式修正

**等价性**：`ts = within + offs - adj`。`offs` 为两个 1 月 1 日之间的毫秒差，`adj` ∈ {0, 一个 `DAY_MS`}，两者均为 60000 的整数倍（`DAY_MS = 1440 × 60000`）。故 `(ts/60000)%60 ≡ (within/60000)%60`，而 `within/60000 = 日序×1440 + 时×60 + 分钟`，对 60 取模恰为原始分钟字段。跨年检测、闰年补偿、基准年选择对分钟值均无影响——这是「整套年份机制可删」的正确性基石，spec 场景与测试双重钉死。

**`s=60` 例外**：`MsOf` 容忍秒字段 60，`within` 落入下一分钟，现状 `(ts/60000)%60` 给出分钟 0；而 Time 列显示行首原文 `:60`（分钟 59 的秒位）。即既有「看得见、滤不出」割裂。分钟列取原始字段后归属分钟 59，过滤与显示一致。这是有意的行为修正而非回归，spec 以专场景固化。

### D4：崩溃侧放弃绝对时间戳，改行序 + 原文呈现

崩溃事件的绝对年份依赖「从头至此的跨年回退顺序扫描」，无法只给稀疏的崩溃行计算——只要崩溃还要绝对时间，整套机制必须保留（此为评估中的变体 A，已否决）。改后契约：

- `CrashGroup` 排序：次数降序 + 首次行号升序（原为首次时间戳升序；两者仅在时钟回跳文件上有差异）。
- 组内末次：行序最后的事件（原为组内最大时间戳）。
- 时间文本：取该行行首原始时间戳——汇总行到秒、列表摘要取时分秒；行首无时间戳显示 `-`。

备选：文件相对时间（距首行天数 + 日内毫秒）——仍需跨年计数，显示仍需日历映射，只删掉一半机制，否。

### D5：`HeaderBytes` 加 `[ ` 前缀识别

`_ts` 删除后方括号 long 行的显示兜底随之消失。让 `HeaderBytes` 在行首为 `[ ` 时跳过 2 字节再按既有两种日期形态判定（约 5 行），`-v long` 行恢复显示。该识别只服务显示，不过滤分钟（快路解析已覆盖方括号行的时间字段）。

### D6：公开 API 直接删除，不做废弃保留

`Ts` / `BaseYear` / `HasYear` / `TsToText` / `TsFromParts` / `NearestPos` 及 `CrashEvent.Ts` / `CrashGroup.FirstTs` / `LastTs` 一并删除。应用非库、无仓库外消费方；保留废弃入口等于保留年份机制的入口，违背本 change 目的。契约由 spec 新能力 `time-column` 整体确立。

## Risks / Trade-offs

- [乱序文件崩溃末次语义变化（组内最大时间 → 行序最后）] → spec 场景 + 改写后的测试显式钉死新语义；CrashTests 原乱序用例（100→300→200→-1 期望 300）随之调整。
- [`s=60` 行为变化影响既有过滤习惯] → proposal 与 spec 显式记录；方向为修复显示 / 过滤割裂；测试钉死「分钟 59 命中」。
- [`-v long` 行若漏改前缀识别则时间列空白] → tasks 第 4 步先行且独立可验证；spec 有对应场景。
- [删除约 20 条测试致覆盖率 / 口径数字变化] → 按 AGENTS.md §3.4 同批更新 `docs/TESTING.md` 与 `docs/UT-AUDIT.md` 相关段（跨年阈值条目、A/B/C/D 跨年场景分析）。
- [mutation 锚点失效] → `scripts/mutation-test.py` 4 条锚点（NearestPos / GuessYear / TsFromParts-adj / YearTables-adj）随实现改写，并为分钟哨兵与集合判定补变异目标。
- [改动面大（7 文件 + 测试 + 工具）] → tasks 分 7 步、每步可独立验证，任一步可停；回滚为整 change revert，无数据迁移（索引随装载重建）。

## Migration Plan

无数据迁移：文档索引在装载时重建，磁盘上无持久化时间数据。实施顺序见 tasks.md，每步完成后跑受影响测试（tstrun 口径，声明数字）。回滚策略：revert 本 change 的全部改动。

## Open Questions

无。`s=60` 归属与乱序崩溃末次语义已在 proposal / spec 显式定为变更后契约；小时过滤预留路径不构成本 change 的未知项。
